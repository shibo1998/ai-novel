## 10. 追加修复（2026-10-31 00:45）：轮询观感与"调用可无限挂起"

**现象**：卷工作台创建任务后页面每秒刷新、接口不停，界面上看不到模型调用，作者怀疑"一直在空调用"。

**核对结果（非空调用）**：`generation_log` 显示 `prepare_G1` 成功（858 输入 / 7090 输出 token），`prepare_G3` 于 00:33:04 发出后长时间未返回；manifest 停在 `status=preparing, phase=model`。中转站对 `deepseek-v4.1-flash-1017` 的短提示词首字约 14 秒，长提示词单次可达数分钟。轮询是规格10 §3 的既定 1000ms 串行核对，不是重复调用模型。

**三处真问题与修法**：

| 问题 | 修法 |
|---|---|
| `phase="model"` 无中文映射，界面显示"服务端阶段：model"，看着像卡死 | `PHASE_LABELS` 补 `model/chapter/prepared/queued`，并标注 `SLOW_PHASES` |
| 每秒全量替换 `model/job/review` 对象 → 整页每秒重渲染（列表闪、滚动跳） | `refresh()` 内容未变时跳过赋值（`sameJson`），轮询仍在但不重渲染 |
| 无"是否还活着"的反馈 | 进度区常显"本页最后核对 HH:MM:SS"；慢阶段显示"正在等待模型返回，单次可能几分钟，阶段不变不代表卡死" |
| **`httpx` 300s 只是单次读超时**：服务端持续发心跳/思考分片时整次调用可无限挂起，且超时后自动重试 3 次 | `llm.MAX_CALL_SECONDS=600` 总时长上限；`调用超时` 明确不重试（再等一轮还是同一份长提示词） |

回归：`tests/test_llm.py::test_call_timeout_is_not_retried`。前端 lint/typecheck/build 通过。

## 11. 追加修复（2026-10-31 02:35）：半途任务无法清理

**现象**：作者「停止后续生产」后，任务停在 `cancelled / phase=model / 0 章`——没有候选可看、`canResume` 不含 `cancelled` 所以无法恢复、界面上也没有任何删除入口，任务永久占着主面板。用户原话：「不上不下的恶心人」。

| 位置 | 改动 |
|---|---|
| `production.remove()` | 新增：删除 `books/<书>/production/<id>/` 任务目录（候选、检查点、准备缓存）。**不动 `chapters/` 稿件、不动 generation_log**。运行中（`preparing`/`generating` 或在 `_ACTIVE`）拒绝，返回 409 `PRODUCTION_RUNNING` |
| `DELETE /api/books/{book}/production/{job_id}` | 新增路由；重复删除 404 |
| `ProductionProgress` | 新增「删除此任务」（仅 `canRemove` = 非运行中）；`cancelled` 且 0 产出时给出说明文案：不会自动恢复，可删除后重新准备 |
| `useVolumeProduction.removeJob()` | 删除后清空当前任务并刷新；无剩余任务时自动展开「准备本卷」表单 |
| 确认弹窗 | 明示：已生成的 N 章正文与生成日志保留，任务本身删除后不可恢复 |

**回归**：`test_remove_deletes_finished_job_only`、`test_remove_refuses_running_job`、`test_remove_job_api`。
