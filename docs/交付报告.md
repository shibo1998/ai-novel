### 7.1 环境准备

```bash
pip install -r requirements.txt        # 5 个包（pydantic 由 fastapi 传递引入）
cd web && npm install && npm run build && cd ..

python scripts/smoke.py                  # 端到端冒烟（临时目录，安全）
cd web && npm run typecheck && npm run lint:check && npm run build   # 前端三件套
```

### 7.3 改代码前必读

1. `AGENTS.md`（工程约束与红线）；2. 对应规格（动文件格式/表结构/状态机/提示词/管线/UI 前先读 `docs/specs/01~04`）；3. `README.md`「与规格的对应与偏差」（已定案决策，不要"顺手修复"）；4. 本报告 §5（别重复造已修的东西，也别误报遗留）。

### 7.4 三个最容易踩的坑

| 坑 | 说明 |
|----|------|
| 路径解析三模式 | `AINOVEL_HOME` → PyInstaller frozen（exe 所在目录）→ 包父目录。改路径逻辑要同时照顾三种模式 |

## 8. 撰写本报告时发现的「文档与代码不一致」

按严重度排序（已提交给 Lead 处理）：

1. **定稿解锁是死路**：`statemachine.py:51` 有 `finalized --unlock--> pending_finalize`，`pipeline.py:645` 与 `api.py:873` 的文案都让用户"先解锁"，但**没有任何 unlock 路由或 UI 按钮**。用户被提示去一个不存在的地方。建议：补 `POST /chapters/{no}/unlock` + 工作台按钮，或改文案。
2. **meta 表单的"单章字数区间"是摆设**：档案编辑页 meta 表单可改 `meta.chapter_word_range`，但管线/装配器只读 `config.json` 的 `chapter_word_range`（`pipeline.py:143/416/...`、`assembler.py:246`）。用户在那改完不生效，真正的入口在档案编辑页底部「书级配置」面板。建议：meta 表单去掉该项或加"实际以书级配置为准"的提示。
3. README「测试」段仍写 **104 项**（实际 187）；README 目录结构段 `tests/ pytest（135 项）` 也是旧数——Lead 已在改，合并时留意。
4. `scripts/e2e_test.py` / `e2e_stage2.py` 两个真实 LLM 脚本在任何文档里都没有"会花 token、会写真实数据"的警告。
5. 规格02 §1 说书级覆盖"`prompts/` 下同名文件优先"，实际必须分层 `prompts/<层>/<ID>.md` 才生效（照规格字面做会静默退回全局）。
