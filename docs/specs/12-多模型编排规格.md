## 2. 契约与数据格式

### 2.1 `config.json`（书级）— 无字段增删，语义收紧

| 项 | 改前 | 改后 |
|---|---|---|
| `model_stages` 键集合 | 五档 | 不变（`plan/prose/polish/review/longctx`） |
| 值为空串或键缺失 | 空串被原样当模型名发出 → HTTP 400 | 视为**未配置**，向下一层下探（§2.3） |
| 值含非法字符 | 直接发出 → 供应商 400，报错信息难读 | 该层跳过并记 warning，继续下探；最终层保证有值 |

不新增 `prompt_models`、不新增 `model_stages_source`（来源是计算结果，不落盘）。

### 2.2 `settings.json`（全局）— 改前 → 改后

```jsonc
// 改前
{
  "providers": { "openai": { "api_key": "...", "base_url": "https://relay/v1" } },
  "default_model": "gemini-3.8-flash-high",
  "prices": { }
}

// 改后
{
  "providers": { "openai": { "api_key": "...", "base_url": "https://relay/v1" } },
  "fallback_model": "gemini-3.8-flash-high",       // 原 default_model，语义降为最后兜底
  "model_defaults": {                               // 新增：全局五档默认，留空即不用
    "plan": "", "prose": "", "polish": "", "review": "", "longctx": ""
  },
  "prices": { }
}
```

- 兼容读：读到 `default_model` 且无 `fallback_model` → 值映射到 `fallback_model`。
- 首次 `settings.update()` 落盘时写入新键并删除 `default_model`（幂等：再执行一次无变化）。
- `settings.masked()` 对 `providers.*.api_key` 的掩码逻辑不变。

### 2.3 解析规则（本规格核心，必须逐条实现）

输入：`book`、`prompt_id`、`stage`（取自提示词 frontmatter 的 `model_stage`）。

按顺序取**第一个"非空且合法"**的值：

| 层 | 来源 | `source` 取值 |
|---|---|---|
| 1 | `config.json.model_stages[stage]` | `book` |
| 2 | `settings.model_defaults[stage]` | `global_stage` |
| 3 | `settings.fallback_model` | `fallback` |
| 4 | `books.DEFAULT_MODEL_STAGES[stage]` | `default` |
| 5 | 常量 `"deepseek-chat"` | `default` |

- **"非空"** = `str.strip()` 后非空。
- **"合法"** = 匹配 `^[A-Za-z0-9._:\-/]+$`。不合法 → 跳过该层并记 `logger.warning`（含档位、层级、被跳过的原值），**不抛错**。
- 第 5 层是硬兜底，保证 `resolve()` 永不返回空。
- **不存在"全局一刀切覆盖"这一层**。这是与改前唯一的行为差异，也是本规格的目的。

输出：

```python
@dataclass(frozen=True)
class ModelRef:
    model: str          # 实际发给中转站的模型名
    source: str         # book | global_stage | fallback | default
```

**唯一实现约束**：`assembler.render_request()` 与 `pipeline._call()` 必须都调用 `models.resolve()`，
不得再各写一遍表达式。`assembler` 用它算 `request_digest` 与 `meta.model`，`pipeline` 用它记录与调用，
两者对同一输入必须返回相同 `model`（§6 判据 12-03 守这条线）。

### 2.4 SQLite 表结构

`generation_log` 增两列，走既有 `_ensure_column` 迁移模式（同 `cost_millicents` 的先例）：

| 列 | 类型 | 含义 |
|---|---|---|
| `provider` | `TEXT` | 当前恒为 `"openai"`（协议名，非厂商名），为将来多端点留位 |
| `model_source` | `TEXT` | `book` / `global_stage` / `fallback` / `default` |

不新增表；`db.rebuild()` 不处理这两列（generation_log 不参与 rebuild，见 README 偏差 6）；
历史行两列为 `NULL`，读取方不得把 `NULL` 当成"配置错误"。

### 2.5 状态机 / 提示词契约

**无变更。** 不改任何 `prompts/**.md`，不动 `model_stage` 取值集合，不增删提示词 ID，不改温度。

## 3. 接口

| 端点 | 方法 | 入参变化 | 返回值变化 | 错误码 |
|---|---|---|---|---|
| `/api/models` | 新增 GET | 无 | `{ok, models:[{id}], error?}` | 中转站不可达 → **200** + `ok:false` + 可读 `error`（不阻断前端，退回手填） |
| `/api/books` | POST 改 | 新增可选 `model_stages: {plan?,prose?,polish?,review?,longctx?}` | 无 | 非法键或非法值 → 422 |
| `/api/books/{book}/config` | GET 改 | 无 | 新增**只读派生**字段 `model_effective: {stage: {model, source}}` | — |
| `/api/books/{book}/config` | PUT 改 | `model_stages` 值允许空串（= 清除该书级该档配置） | 同上 | 非法键 → 422 |
| `/api/settings/test` | POST 改 | `model` 省略时按 `model_defaults.plan` → `fallback_model` → `deepseek-chat` 取 | 无 | 同现状 |

**派生字段剥离规则（强制）**：`PUT /config` 落盘前必须 `cfg.pop("model_effective", None)`。
理由：前端拿到 GET 结果后会整体回传，`put_config` 用的是 `cfg.update(payload)`，
不剥离就会把派生字段写进 `config.json`，下次 rebuild / 手改文件时变成脏数据。
先例：`outline.write_outline` 剥离 `_body` / `_rhythm`（README 偏差 10）。

## 4. 迁移与兼容（强制）

- **老数据（settings.json）**：有 `default_model` → 读时映射为 `fallback_model`；首次 PUT 写新键、删旧键。重复执行结果一致（**幂等**）。
- **老数据（config.json）**：无需迁移。但**生效行为会变**——原先被 `default_model` 压住的 `plan: deepseek-chat` 开始真正生效。这是本规格唯一预期的行为变更，实施报告必须列出受影响的书与档位，并逐本记录改前/改后实际 `model`。
- **删库 → rebuild**：不受影响。本规格不写任何文件派生状态，`model_effective` 每次现算。
- **降级路径（新数据被旧代码读）**：旧代码只认 `default_model`，读不到就当空 → 回落 `model_stages` → 行为等同本规格第 1 层。即**回滚到旧代码不会崩，只是失去全局档位与兜底语义**，可接受。
- **回滚方式**：代码回退即可，数据不需要回退（新键旧代码忽略）。残留的两列 `provider` / `model_source` 旧代码不读，无害；若必须清库，`ALTER TABLE ... DROP COLUMN` 或直接删 `data/*.db` 后 rebuild（generation_log 历史会丢，属已知代价）。

## 5. 失败模式（强制，fail-closed）

| 可能的静默失效路径 | 对策 |
|---|---|
| 书级档位写了空串/纯空格 → 被当模型名发出 → 400，且报错指向"网络问题" | 空值视为未配置向下下探；层内校验失败记 warning 并跳过 |
| 模型名含中文/全角字符/换行 → 供应商 400，现象像鉴权失败 | 字符集校验（§2.3），跳过该层并 warning 明确写"模型名非法，已跳过该层" |
| 全局 `fallback_model` 填错模型名 → 所有档位一起 400 | 不改既有"4xx 不重试"语义；设置页"测试连接"默认测 `model_defaults.plan`，让用户在保存前发现 |
| 前端把 `model_effective` 原样回传 → 污染 `config.json` | 落盘前剥离（§3） |
| `/api/models` 不可达 → UI 下拉空白 → 用户以为没模型可选 | 返回 `ok:false` + 可读 error，UI 保留手填并提示"中转站未提供模型列表，可手动填写" |
| **两处解析逻辑再次漂移**（本 bug 的根因） | 只允许 `models.resolve()` 一个实现；加测试断言 assembler 与 pipeline 对同一输入返回相同 `model` |
| `generation_log.model` 与实际请求不一致 | `_call` 先 resolve 再记录，记录值直接取自 `ModelRef`，不二次计算 |
| 历史行 `model_source IS NULL` 被当成"配置错误"告警 | 读取方显式把 `NULL` 渲染为"（历史记录）"，不参与一致性校验 |
| 档位配了一个中转站没有的模型 → 只在真跑时炸 | 不改既有行为（这是用户显式配置的结果）；`/api/models` 提供清单后，UI 下拉默认只列真实存在的模型 |
