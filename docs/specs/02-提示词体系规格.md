## 1. 组织与版本

- 每条提示词一个文件：`prompts/<层>/<ID>.md`，frontmatter 含 `id / stage / model_stage / temperature / version / inputs / output`
- 变量统一用 `〖变量名〗` 标注；运行时由装配器/程序填充
- 每次 LLM 调用记录 `prompt_digest`（文件内容 SHA-256）入 generation_log——同一细纲 + 同一 digest = 可复现
- 书级可覆盖：`books/<书名>/prompts/` 下同名文件优先

**model_stage → 模型映射**（默认，config 可改）：

| stage | 用途 | 默认模型 |
|-------|------|---------|
| plan | 档案生成 G1-G6、卷末审计 V6 | DeepSeek |
| prose | 正文 W1-W5 | Gemini |
| polish | 润色 V2/V3 | Gemini |
| review | 审校 V1、修复 V5、记忆卡 V4 | DeepSeek |
| longctx | 跨章长上下文通读（V6 若多章合并） | Gemini |

**温度总表**：G1=0.8，G2=0.6，G3=0.8，G4=0.7，G5=0.6，G6=0.5，W1=0.75，W2-W5=0.7，V1=0.2，V2=0.4，V3=0.3，V4=0.1，V5=0.4，V6=0.2（依据【全集】§7.2）。

## 3. 核心提示词详细卡

### P-W1 章节正文（系统最关键的一条）

**来源**：【豆包】T7 原文全文 + 尾部附加 S1 全文。

**改造点（对原文的 5 处修改）**：
1. 原文【本章位置】至【章末钩子】各段由人工粘贴改为装配变量——模板改写为引用装配器槽位（规格01 §2.3 的 13 槽位产物整体注入），模板里只保留写法要求与禁止项
2. 字数区间从书 config 注入，不再硬编码
3. 章节 ≤3 时自动追加 T7-C 的开篇要求段（M3 之前先手动触发）
4. 保留原文输出要求：直接输出正文、无开场白、无章节标题、段落 2-4 行
5. 尾部完整附加 S1（去AI味硬规则），S1 与 lint 词库同源

**输入**：装配器产物。**输出**：纯正文。
**失败处理**：字数越界 → 自动重跑一次并在指令中强调字数；仍越界 → 转人工。

### P-G6 单章细纲（章合同）

**来源**：【豆包】T6（整卷批量 → 改造为单章按需生成）+ T6-B 骨架表字段全收。

**改造点**：
1. 输入 = 全局大纲中该章一行 + 所属卷目标 + 上一章钩子 + 本章出场角色当前状态（从 characters/ 读）+ 活跃伏笔线程 + 章号/总章数
2. 输出 YAML frontmatter（机器）+ MD 正文（人读），schema：

```yaml
chapter_no: 3
volume: 1
stage: 引入|发展|转折|高潮|收束
emotion_task: 压|小扬|爆
purpose: [推进主线, 埋伏笔]
core_event: "一句话"
scenes:                       # 3-5 个
  - { goal: "", conflict: "", chars: [{ name: "", state: "" }], end_state: "" }
emotion_arc: { from: "", via: "", to: "" }
must_include: [至少一项新信息揭露, 至少一个关键决策]
hook: { content: "", type: 悬念|选择|反转 }
foreshadow_ops:               # op ∈ plant|advance|pay
  - { op: plant, fo_id: "FO-004", note: "" }
word_range: [2200, 2800]
pov: 林寒
confirmed: false
```

3. 程序校验：`foreshadow_ops` 引用的 FO 编号必须已存在于台账（pay 的必须处于 building）；`hook.type` 不得与上一章相同，违反 → 重试
4. prompt 内写入约束：连续两章不得复用相同场景结构与战斗套路（T6 原文要求保留）

### P-V1 章内审校

**来源**：【豆包】T9-B 七项检查 + 审查层 V1 崩盘点清单并入检查项 + 【全集】提示词10 的三维评分框架。

**改造点**：
1. 输出改 JSON：`{ scores: {ai_flavor, plot, pacing, prose, hook}, issues: [{category, severity(blocking|warning), location, quote, description, suggestion}], verdict(pass|fix|fail) }`
2. `location + quote` 强制引用原文举证（T9-B 原文要求"引用原文说明问题"升级为必填字段）
3. **程序+LLM 分工**：状态 diff、伏笔编号核对、术语表比对由程序预生成"疑似冲突清单"注入 prompt，LLM 只做语义判断与遗漏补充——避免 LLM 漏检机械可查项
4. rubric 五维锚点写进 prompt（见规格03 §6）
5. verdict 规则：存在 blocking 或任一维 <70 → fix；两轮 fix 后仍 fix → fail（转人工）

### P-V4 记忆卡抽取

**来源**：【豆包】T9-C 原文。**改造**：输出 JSON 固化：

```json
{
  "chapter_no": 3,
  "char_updates": [{ "name": "林寒", "changes": { "realm": "炼气四层" } }],
  "new_chars": [{ "name": "", "identity": "", "stance": "" }],
  "new_locations": [],
  "foreshadow_ops": [{ "op": "advance", "fo_id": "FO-001" }],
  "new_settings_pending": [],
  "event_summary": "一句话",
  "time_elapsed": "半日"
}
```

**回写规则**：程序将 `char_updates` diff 到 characters/ frontmatter——无冲突自动写入，与现档案矛盾（如境界倒退、死者复现）进人工裁决队列，**禁止静默覆盖**。只记录客观变化（T9-C 原则保留）。

### P-V2 整章润色

**来源**：【豆包】T8-A 原文。**改造**：
1. 禁词引用 `lint/banned_words.txt`（与机械检查同源，改完不可能再命中）
2. 输出 = 润色全文 + 改动清单（命中类别/位置/改法，T8-A 原文要求保留）
3. 程序校验：字数浮动 ≤10%；机械检查重跑必须全绿
4. 保留原文铁律：不改剧情、不改人设、不加新情节

### P-V5 定向修复（唯一新写的提示词）

**输入**：当前正文 + 问题清单（lint 命中 或 V1 issues）。
**约束**：只改问题相关句段，其余逐字保留；每条问题给出一处修改；输出全文。
**程序校验**：对未涉及问题句段的改动率 >10% 视为越权重写 → 丢弃本次输出，版本 +1 走完整重生成。

## 4. 档案生成链的改造要点（M1，简卡）

- **G1 世界观**：T2 原文保留七维+自检；输出节标题强制对齐 STORY_BIBLE 的 H2 schema
- **G2 力量体系**：T3 原文保留；境界总表列名对齐 Bible 固定表格列；五问平衡校验保留为生成后自检节
- **G3 角色卡**：T4 原文保留；输出 H2 节对齐 char-*.md schema；对话试金石 3 句保留
- **G4 关系网**：【全集】提示词5 原文；结果合并写回各角色的"关系网络"节
- **G5 全书大纲**：T5 原文保留；章节行格式固定为 OUTLINE 章节总表列；伏笔总表生成后由程序转写入 PLOT_POINTS.md（编号自动分配 FO-xxx）
- **G6 详卡见上**

所有 G 链统一流程：生成 → UI diff 预览 → 人工改定 → 采纳落盘。AI 生成的档案永远不直接静默覆盖人工内容。
