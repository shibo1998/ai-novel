## 1. 存储总览

**原则**：文件 = 单一真相源（人可读、可 git、可手修）；SQLite = 可随时重建的索引与历史。

```
books/<书名>/
├── meta.md
├── STORY_BIBLE.md
├── OUTLINE.md
├── PLOT_POINTS.md
├── LOCATIONS.md
├── characters/               # 偏离豆包 F1：由单文件改为目录（见 §2.3 说明）
│   ├── char-林寒.md
│   └── ...
├── style/                    # M5 启用：文风特征卡、语料
├── chapters/
│   ├── 001_细纲.md
│   ├── 001_正文.md
│   └── 001_记忆卡.md
└── config.json               # 本书配置
prompts/                      # 全局提示词库（见规格 02）
  system/ generate/ write/ review/ style/
lint/
  banned_words.txt            # S1 禁词 + T8-B 烂词表，每行一个
  sensitive_words.txt         # 敏感词红线
  dialog_suffix.txt           # "说道/问道/淡淡地说"类后缀
```

### 2.2 STORY_BIBLE.md（固定 H2 节，程序按节解析）

| H2 节 | 约定 |
|-------|------|
| `## 基础设定` | 时代/地理/文明等级，≤300字/维 |
| `## 力量体系` | 固定表格，列：大境界\|子境界\|突破条件\|能力边界(不能做什么)\|战力对标\|寿元\|代价与风险\|突破异象 |

## 3. SQLite 表结构

| 表 | 列 |
|----|----|
| books | id, name, path, created_at |
| chapters | id, book_id, no, title, status, current_version, updated_at |
| generation_log | id, book_id, chapter_no, stage, prompt_id, prompt_version, prompt_digest, model, input_tokens, output_tokens, cost_cents, status(ok/error), error, created_at |
| review_records | id, book_id, chapter_no, version, kind(mech/llm/polish/audit), scores_json, issues_json, verdict, created_at |
| snapshots | id, book_id, chapter_no, version, label, content, created_at |

`chapters_fts`：FTS5 虚表（chapter_no, body）。中文分词采用 trigram tokenizer（SQLite 3.34+ 内建），M0 时验证不可用则降级为入库前 bigram 切分。

## 4. 章节状态机

状态存 `chapters.status`，转换只能由下列触发：

```
awaiting_outline ──生成细纲(P-G6)──▶ outline_draft ──人工确认──▶ outline_locked
outline_locked ──开始生成──▶ generating ──完成──▶ mech_check
mech_check ──阻断命中──▶ lint_fix(P-V5) ──▶ mech_check          （自动，1轮）
mech_check ──通过──▶ llm_review
llm_review ──verdict=fix 且轮次<2──▶ targeted_fix(P-V5) ──▶ mech_check
llm_review ──verdict=fail 或轮次耗尽──▶ human_review
human_review ──修改细纲重写──▶ generating（新版本分支）
human_review ──通过/豁免──▶ pending_finalize
pending_finalize ──人工定稿(二次确认)──▶ finalized（写快照）
finalized ──重写──▶ generating（从所选快照开新分支，version+1）
任意状态 ──异常──▶ error ──重试──▶ 原状态
```

- "章内全自动"= generating → mech_check → llm_review → targeted_fix 循环内无人工动作
- 豁免必须填理由，写入 generation_log（合规证据链的一部分）
- 台账冲突队列非空时，禁止开始下一章的细纲生成（强制清空）

## 5. 校验与防损

1. 所有文件写回 = 写临时文件 → 原子替换（防写一半崩溃损坏档案）
2. frontmatter schema 校验失败 → 拒绝写回并报错，不静默降级
3. 每次定稿自动写快照；快照保留全部历史版本
4. SQLite 可从文件全量重建（rebuild 命令），重建后校验 generation_log 之外的表一致
5. 装配器预览必须可见（UI 折叠面板）——排查"为什么生成跑偏"的第一入口
