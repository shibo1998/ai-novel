### 2.3 采纳凭据与就绪状态

`planning.adoptions`是键到记录的映射，键格式为`global`、`volume:<no>`、`unit:<id>`、`chapters:<unit_id>:<from>-<to>`。记录字段：`content_digest`、`parent_digest`（全书层为空字符串）、`accepted_at`（带时区时间，仅作展示）、`source`（manual/ai）。

- 内容指纹为规范化结构JSON的完整SHA-256：UTF-8、键排序、固定分隔符；不依赖YAML排版、mtime或采纳时间。正式章节行内容纳入对应批次指纹。
- 全书层取root logline/ending_direction、global及卷的no/name/direction/estimated_chapters，不取已展开卷细节、单元详情或章节表；卷层取本卷详细字段及每个单元骨架的id/name/chapters，不取单元detail_level、目标/阻力/选择/结果等详细字段；单元层取本单元详情；章纲层取该批次行、单元ID/范围与对应节奏小节。深化单元不得反向改变卷层指纹。实现必须集中定义投影，不由前后端各自拼散列。
- 当前内容等于人工采纳指纹，且父层当前有效指纹等于`parent_digest`，才显示“已采纳/就绪”。直接改文件导致本层指纹变化显示“待采纳”；上游变化导致下层显示“待复核”，不自动重生成。
- 更新正文、记忆卡或角色动态状态不直接把所有规划层变成待复核；这些是**下次生成/预览的输入版本**，不是每层采纳指纹的永久父节点。
- 规划读模型使用`missing/unadopted/ready/stale/invalid`并配中文说明，不能将invalid当missing。`generation_gate={allowed,code,message}`须解释下一步，不用单个绿色勾代替全部条件。
- 章纲采纳同时原子写内容和对应凭据；读回不一致不返回成功。删除DB后凭据与就绪状态仍可重建。

### 2.4 提示词契约

**阶段A**不修改提示词、装配槽、机检或审校，不因浏览器补验触发真模型质量对比。

**阶段B**只修改既有`prompts/generate/G5.md`与`G6.md`，不增删重命名文件，不改ID、model_stage或温度。按实施时最新版本递增，当前参考为G5 v2、G6 v4。

| 提示词 | 新契约 | 兼容 |
|---|---|---|
| G5 | 新增`〖规划作用域〗`与`〖规划上下文〗`；作用域为legacy/global/volume/unit/chapters | legacy保持原MD四部分输出；旧调用由服务端补明确legacy变量，不能让新增占位符残留 |
| G5 global | 输出全书粗纲、阶段边界、各卷方向/估算，不输出全书章节表 | 只供新规划端点调用 |
| G5 volume | 只输出目标卷详细字段与unit_skeletons；chapter_count与骨架范围须经程序及人工预览确认 | 远卷仅给简短方向，不顺带展开 |
| G5 unit | 只细化目标单元的目标/阻力/选择/结果及信息边界 | 不重写其他单元，不生成正文 |
| G5 chapters | 只输出指定单元、指定章号批次的七列章纲；不越范围 | 单批1–10章，默认取该单元接下来最多10章；更长单元连续分批 |
| G6 | 新增`〖所属剧情单元〗`与`〖本章规划边界〗`，保留所有既有变量及章合同schema | legacy提供明确“旧模式无单元，按既有章纲/卷目标执行”，不猜造单元 |

非legacy的G5使用严格JSON对象输出，包络为`{scope,target,data}`：global的data为logline/ending_direction/global/rough_volumes；volume为chapter_count/volume_detail/unit_skeletons；unit为unit_detail；chapters为chapter_rows/rhythm_note。只允许对应作用域字段，先验证再做影子合并与预览，模型不能提交整本OUTLINE代替局部输出。

作用域影子合并规则：global只改全书字段和各卷粗方向投影，保留已展开卷细节/单元/章纲，不把既有expanded卷降为rough；volume只改目标卷详细字段与单元骨架，不改各卷全书方向；unit只改目标单元详情及detail_level，不改ID/名称/范围，改骨架须回卷层预览；chapters只改目标批次行及其节奏说明，不改卷/单元。卷内新单元分配范围必须覆盖整卷；旧书已有历史段允许显示为只读未分配段，不要求自动补历史单元。`rhythm_note`仅更新固定H2节奏总谱下对应`### 章纲批次 <unit_id>:<from>-<to>`小节，保留原手工正文与其他批次小节，不逐次追加重复说明；该小节纳入批次指纹。

模型不确定或输出不完整时回喂校验错误，最多沿用既有解析重试上限；耗尽返回失败，不自动改成legacy或接受部分空壳。语义质量与因果合理性仍交作者判读，不用结构校验声称“剧情一定好”。

书级覆盖优先规则不变：覆盖G5不支持新作用域时，legacy可继续，新作用域明确报`PLANNING_PROMPT_INCOMPATIBLE`并提供检查覆盖模板/恢复全局模板的人工路径；不静默绕过覆盖、不批量重写用户提示词。所有兼容默认值在变量装配层明确提供，不在Python内联prompt文本。

## 3. 接口与页面

### 3.1 新规划接口

省略公共前缀`/api/books/{book}`。所有写入在同书互斥内重新检查；新端点必须提供版本，不沿用旧端点“缺If-Match也允许写”的兼容豁免。

| 端点 | 方法 | 入参 | 返回与错误 |
|---|---|---|---|
| `/planning` | GET | 无；只读 | mode、schema_version、tree、readiness、chapter_numbers、protected_numbers、unassigned_numbers、estimates、next_actions、warnings；强ETag |
| `/planning/enable` | POST | `{mode:"rolling"}`，If-Match | 仅显式初始化规划元数据，保留旧内容，不生成、不自动采纳；返回新读模型/ETag；412/409/422 |
| `/planning/generate` | POST | `{scope,target,requirements}`，If-Match；scope不接受legacy | 纯候选`{scope,target,content,prompt_id,prompt_version,prompt_digest,input_version}`；调用日志必记；结构或门禁失败不写正式规划 |
| `/planning/preview` | POST | `{scope,target,content,input_version,rebase?:bool}`，rebase默认false，If-Match | 纯计算的规范化candidate、同基线diff、影响、preview_version、preview_digest与基线变化警告；不写档、不记凭据、不调用模型 |
| `/planning/adopt` | POST | 同preview入参加`preview_digest`，If-Match必须为所见preview_version | 写后核对，返回实际updated_scope/added_numbers/changed_numbers/readiness/ETag；不能只返回ok=true |

`target`固定结构为`{volume_no:int|null,unit_id:string|null,chapters:[int,int]|null}`：global全null；volume只含卷号；unit含卷号和单元ID；chapters三项齐全且范围属于该单元。路径书名、target与候选scope必须一致，不接受任意文件路径或跨书目标。

规划ETag为**文件原始字节与存在性**的组合指纹，GET/generate/preview/adopt使用同一文件集合规则：OUTLINE、meta/config、Bible、角色集合、PLOT_POINTS、LOCATIONS、TIMELINE，书内正式细纲/正文/记忆卡文件，以及实际生效的G5/G6全局或书级覆盖模板。摘要与历史状态从这些正式文件及其可重建索引获得；不把DB、运行日志、草稿/备份/候选、前端缓存或未使用的派生状态卡纳入版本。新增/删除文件也纳入；按固定源标识与相对文件名排序计算。版本扫描可以遍历文件签名，不代表把全书文本装入提示词。实现返回实际source_files用于排障，预览前后复核快照，不混读两版；不展示设置密钥。

候选生成固定原书、作用域、参数和input_version；生成期间输入发生变化时保留候选但标记“基线已变，需重新核对”。生成失败、返回体丢失或停止等待沿用规格07的结果未知语义，**不新增服务端任务队列、不承诺未收到候选可恢复**。

预览从服务端当前正式数据做影子合并；`preview_digest`覆盖scope/target、最终候选投影、原始input_version、当前preview_version、rebase标志与影响列表。候选被编辑后旧预览不可直接采纳；重新预览才能确认。input_version与当前版本不同且rebase=false时返回409 `PLANNING_INPUT_CHANGED`，保留候选；作者点击“按当前版本重建差异”后才能显式传rebase=true，不由拦截器自动重试或改原始input_version。预览分配的新卷号/单元ID/章号必须放入返回的规范化candidate，后续重预览与采纳复用它们，不在采纳时重新随机分配。服务端采纳时重算同一候选/预览并比较，If-Match版本变化返回412，预览变化返回409，不接受客户端提供的“无影响”结论。

### 3.3 页面与滚动展开

新增hash路由`/book/:name/planning`，支持固定`node`与正整数`returnChapter`查询参数，不接受任意返回URL。

- 书总览、当前书菜单、空书、工作台缺章纲/规划不就绪提示，都提供明确“内容规划”入口；新Web建书成功后进入规划页，**不直接生成正文，也不自动调用G1–G6**。
- 左侧树为全书→卷→单元→章纲批次，右侧当前节点编辑/候选/diff/影响。显示“未建立、待采纳、已采纳、上游变化待复核、读取失败”，并给下一步按钮与具体拒绝原因。
- 定位与设定仍在既有档案页；规划页展示来源摘要和缺档提示，提供同书节点跳转，不再复制一套Bible/角色编辑器。
- rolling书的全书/卷/单元/章纲唯一编辑实现放规划页；档案树中大纲节点改为只读摘要+定位规划页。总览仍只读。legacy保留原档案编辑。多处快捷入口可存在，不能保留第二套可写章纲组件。
- 编辑固定书与scope，沿用脏数据三选、旧响应隔离、If-Match、任务条和错误记录；正文/候选不进localStorage，只有导航与显示偏好可保存。
- 全书显示目标字数、单章字数范围、估算总章数、各卷粗方向与**已采纳章纲实际行数**，不把估算当进度分母。自动估算用`ceil(target_words/单章区间中值)`，作者显式调整值仅存`planning.global.estimated_chapters_override`（正整数或null，null为自动），标注为估算；不能硬编码120。目标或区间无效时显示无法估算，保留编辑入口，不用默认值假装有效。
- 当前卷是作者当前选中的、尚未完成的最前置详细规划卷；不自动越过前卷展开远卷。全书粗纲可列远卷，详细生成只针对当前卷。前卷全部有效规划章定稿且队列清空后，提示人工校准全书方向、展开下一卷；不自动改纲、不自动开新卷。
- 卷纲包含目标/阻力/转折/高潮/预期末态与单元骨架；当前单元再详细规划行动链与释放边界，然后一次最多10章生成章纲。默认不跨单元；作者点名范围只做该范围，不顺带多生成“凑齐整卷”。
- 单元/批次完成以正式行范围和对应就绪状态为准；卷末仍为**作者确认的卷结束章**，不是最近一次批次末章。尚未出章纲的预留范围不误触发卷末审计。
- 上游改动展示实际受影响的下层节点，要求人工复核后才恢复未来G6；不会后台重写下层。已写内容或已锁细纲显示保护标签，可查看，但新规划采纳不得改其行/章号/单元归属。

### 3.4 G6和正文装配

G6继续按章生成，不提供整卷细纲自动确认。rolling的最小规划闭包为：已采纳全书粗纲、本卷目标/边界、当前单元详情、本章七列行、同单元相关伏笔提示；前后单元只给必要短摘要，并明确是规划。

卷/单元生成参考已写摘要、上章真实停点与人物状态，不能只参考尚未发生的后卷计划。取段集中在规划服务，不由每个调用方整读/拼接所有卷和单元。

正文装配复用现有`volume_rhythm`等槽位，在卷信息后补本单元目标/信息边界与本章任务，不增加一套平行正文prompt。现有字数预算、章合同不截断、上章尾、角色历史状态及FTS策略不放宽；装配预览可看真实单元上下文。未来设定/角色建议不得冒充已确认世界或已发生状态。

## 4. 迁移与兼容（强制）

1. **无自动全书迁移**：缺planning的书为legacy；新版部署、GET、rebuild或打开页面都不替书写enabled或采纳凭据。旧API建书调用保持原行为，新Web显式选择rolling。
2. **旧书显式启用**：先展示影响和现有卷/章范围；确认后只加空规划元数据，不改原章纲/正文/细纲/FO/历史。已有有效卷字段作为可读依据，不自动宣告全书/卷已采纳。
3. 启用后，旧书未来未写行可由作者明确映射到单元并以原内容预览采纳；没映射时显示`unassigned_numbers`及操作入口。也可从现有最大范围之后另开新卷。不得自动删除旧未来行、缩短旧卷或重排章号解决重叠。
4. **保护集**：有效已写正文（含未定稿）、记忆卡或已确认细纲对应章号；损坏但存在的正式内容也纳入保护并要求修复。仅有DB row不算保护内容；未确认细纲不允许被规划采纳顺带覆盖，其文件始终不在规划写范围。
5. rolling所有正式规划写入口对修改/删除/编号/归属变化检查保护集；触及保护返回409，列出章号与原因，所有正式文件哈希不变。已采纳的祖先方向可以经人工改定，但仅标未来下层待复核，不自动迁移历史合同。
6. 批次修改只允许当前目标未受保护行；未涉及内容保留。新增号、卷号、单元ID稳定，重复采纳相同预览不重复增加行；内容与有效采纳凭据均无变化时不重复写mtime，首次人工确认仍须写凭据。章纲采纳记录不能相互重叠：修改既有批次的子范围时更新该批次记录，未改行保留；跨多个既有批次分开预览/采纳，不另建重叠记录。
7. 开启动作幂等：重复enable返回当前模式，不清采纳记录。rebuild不得改变enabled、规划内容、就绪或最后编辑时间；SQLite运行历史丢失仍按原约定不可从文件恢复。
8. **旧版读取**：保留七列表及原卷字段便于读取；旧版不理解采纳指纹/粗卷时不保证新规划界面可用。**旧版写入不安全**，禁止把“旧版能读”当作“旧版能继续写”。
9. 回滚前停止新写入、备份受影响的完整OUTLINE；只读旧正文允许，继续写入应使用兼容版本，或经用户明确确认在副本转换为legacy。不能仅回退代码后让旧序列化丢planning/单元；不能自动恢复旧书稿覆盖已采纳修改。
10. 路径解析继续覆盖AINOVEL_HOME、frozen和包父目录；挂载书使用原书目录解析，不写回注册目录之外，不把临时验证书当真实书。

## 5. 失败模式（强制）

| 失败路径 | 必须结果 |
|---|---|
| 粗卷/单元范围被当成已有章纲 | planned只看有效七列行；不产生DB row、不虚增导航与进度 |
| 规划解析/版本无法识别 | invalid中文提示、只读可用旧内容、禁新写；不静默legacy降级 |
| 下层基于旧上游/输入生成 | 候选保留、标旧基线；重新预览并人工确认，不偷换版本 |
| 候选编辑后仍用旧diff采纳 | preview_digest不符拒绝；保留修改，重新预览 |
| 模型越scope、生成其他卷/章或重复号 | 结构校验拒绝整次输出，不能只捡合法部分默默入档 |
| 指纹记录了错误投影或各端不一致 | 集中投影/指纹服务与确定性测试；前端只展示服务端就绪状态 |
| 父级变化自动覆盖已锁合同 | 只标未来规划待复核；正文/细纲哈希与章节状态不变 |
| 旧全量G5/PUT绕过rolling保护 | 服务端拒绝，不能仅隐藏按钮；无版本的新端点也拒绝 |
| 停止等待后重发/切书旧响应 | 保留原目标未知状态；不自动重发、不把旧候选塞进新书 |
| OUTLINE写入/读回失败 | 不返回成功；原子替换防半文件，实际已替换但回执丢失时先读回核验，不盲重试 |
| legacy G5多文件部分写入 | 如实列成功/失败文件，候选保留；重新拉实际基线供人处理，不虚称自动回滚 |
| 50条裁决第N项明确失败 | 逐项保留结果；可继续后续独立项；重试只含仍待处理的failed/skipped |
| 第N项断网/占用/结果未知或主动停止 | 停发后续项；N项先核验，前成功项不重跑，不把HTTP未知当文件未变 |
| 启用旧书却无法映射旧行 | 展示未分配范围；不猜分卷/单元，不编造已采纳状态 |
| 规划建议混入事实与记忆 | scope产物只进OUTLINE；角色/时间线/记忆仍按已写正文和既有人工入口处理 |

### 6.4 真模型与最终用户判读

阶段B改G5/G6及装配上下文，**必须在另行授权后跑1章真模型对比**，不能沿用规格07“纯UI不触发”豁免。隔离副本、同一合法上章起点对比旧/新方案，分别记录规划/细纲/正文、字数、耗时、五维分数、人物/地点/时间衔接、单元目标兑现、是否提前释放后续信息及实际prompt digest。人工确认细纲与定稿由作者完成，不能以自动测试动作代替真实人工关。

结论只能为更好/无变化/更差；更差则修正或撤回相关改动。未获模型授权时保持“质量验证待授权”，不调用模型、不标L2完成。真实书副本与模型验证可共用经授权的隔离副本，但分别记录证据，不能因做了一项默认另一项已授权。

用户最终判读须明确：规划层级/确认是否符合写作习惯、专项正文阅读是否可接受、真模型对比章是否愿意采用，以及接受哪些遗留。agent可整理证据和协助通读，不能代签最终接受。
