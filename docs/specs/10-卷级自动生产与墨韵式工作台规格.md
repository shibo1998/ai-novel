# 规格10 · 卷级自动生产与墨韵式工作台

> 规格11增补首卷准备前“没想法？AI给我3个故事”的同题材候选入口，选用仅填logline/requirements，正式书名/题材/章数不改。只有作者后续点击prepare才建立本规格卷任务；已有卷/章或未结束任务不能改换故事。见 `11-同题材AI故事候选规格.md`，本规格原批准/验收不变。

- 版本v1.0，批准范围内离线工程实施/验收已完成；真实副本、真模型与作者读感仍未授权。批准快照 `.pi/plan/墨韵式卷工作台与自动出稿-20261029-2340.md`；本文细化接口与模块边界，不替换批准快照。
- 基线HEAD `5b8f5d64e95228e6454959104d57b8629998aef1`及批准时工作区。实施报告 `docs/规格10实施验收.md`。
- 目标：启动准备 → 一次整卷细纲人工确认 → 自动逐章生成/检查/有限修复 → 最后统一人工审核/定稿。成功路径不让作者调度内部层级。

## 0. 范围
### 0.1 本批做
A 文件任务、卷级候选/一次人工确认、追加/新卷；B 自动出稿与隔离临时上下文、顺序人工定稿；C 墨韵式卷工作台、前端任务查询/恢复/阅读、隔离浏览器验证。

### 0.2 不做清单（强制）
不自动确认细纲/定稿/豁免/清队列；不改敏感词或V5>10%护栏；不覆盖已写章/锁定细纲/历史编号；不复制墨韵清表或自动落库；不引入新依赖、第二套运行时、Redis/向量库/账号；不自动全文无人值守/发布/成本产品化；不改W1句子规则/模型/温度；不运行run.py、读取真实books/data、调用付费模型、提交/推送/打包。真实质量验证另行授权。

## 1. 红线（强制）
文件为真相、写入atomic+frontmatter；批次UUID与相对受控路径；SQLite仅索引，现有运行历史丢库不可恢复。人工确认由用户一个请求批量完成，不能由worker调用；生成worker零finalize。M-04、V5、队列非空、未生效规则均暂停；不以metrics扣分/自动润色。所有模型调用走pipeline._call并记录请求/token/费用。旧单章不传批次参数时行为不变。

## 2. 契约与格式
### 2.1 权威覆盖
本规格新增卷级联合候选人工采纳，覆盖规格08默认逐层点击；旧高级规划保留。多个细纲一次人工确认仍保留人工属性，章节状态词/迁移表不变。指定UI墨韵式视觉覆盖规格04的不做视觉设计条款；Vue3+EP不变。正式正文frontmatter/DB表不变。

### 2.2 文件任务
`books/<书>/production/<uuid>/manifest.json`、`planning_candidate.json`、`outlines/`、`checkpoints/`、`draft_context.json`、`receipts/`。manifest/schema_version=1，含id/book/request/status/phase/current_chapter/numbers/completed/applied/reason/created_at/updated_at/input_digest/confirmation_digest/dependencies/recovery/action_requests。UUID服务端生成，严格小写标准UUID；路径仅接受程序生成的受控相对档案名，不接受任意客户端路径。候选目录不参与正式章节/摘要/FTS/TXT导出。

任务状态preparing→awaiting_outline_confirmation→generating→awaiting_final_review→applied/partially_applied，另paused/error/interrupted/cancelled/stale/recovery_required。manifest坏/未知版本明确报PRODUCTION_INVALID，不视为零任务。线程状态只作活动标记，重启活动阶段变interrupted，不自动重发模型请求。暂停/cancel在安全检查点阻止下一次调用，不能承诺取消已发送的付费请求。

### 2.3 候选包
候选JSON schema_version=1，含`outline:{fm,rows,rhythm}`、`files:Record<受控相对路径,完整档案文本>`（只允许缺失必要Bible/角色/地点/伏笔等）、`outlines:[{no,fm,body}]`、`notes:string[]`。候选里的confirmed只能false，章号由服务端范围决定；输入档案保持不变直到确认。G5各作用域候选只在内存投影合并，G6使用计划状态/预期承接而非虚构已写原文。验证文件frontmatter、表头、chapter_rows、unit范围、FO操作顺序、角色与境界。非法/超范围/已写/锁定范围拒绝。

确认摘要覆盖输入digest、规范化候选、范围与每章完整细纲。确认提交为一个用户请求：同书锁内重算摘要与输入，恢复标记记录原文件/本章索引，atomic写全部档案、逐章confirm状态迁移、读回核对，最终回执发布；异常原位置可回滚/恢复，出现第三方内容不覆盖，recovery_required。不能自动调用旧逐层adopt端点写假凭据；规划adoptions在这一个真实人工请求里建立。

### 2.4 临时上下文
批次内V4只抽取并校验，不_apply_memory。每项含no/body_fingerprint/outline_fingerprint/memory；只用no<当前章且当前正文指纹仍匹配的本批已检查稿。传入正文装配/疑似冲突/审校，标记批次待审事实而非正式正史，角色/位置/伤势/物品/知情/伏笔变化临时覆盖仅本次请求。未知角色/境界/FO、相互矛盾暂停，不注册正式实体。正式角色/STATE/伏笔/全局摘要/正式记忆/FTS不变。后续只有已审核定稿调用原finalize/writeback。

依赖覆盖meta/config/Bible/OUTLINE/角色/地点/伏笔/文风/实际提示词与规则（不记录密钥）；每完成章保存正文/合同指纹，前章改动标受影响后缀stale且保留文本。不自动改已确认细纲；需人工重新确认受影响部分，或回到原工作台处理。单章路径不受批次运行标记误锁。生成线程持同书锁，读取接口不持长锁，任务暂停请求可以在运行中投递。

## 3. API（精确共享契约）
所有路径以`/api/books/{book}`为前缀；输入extra=forbid。

- GET `/volumes` → `{book,title,etag,volumes:[{no,name,goal,chapter_range:[a,b]|[],planned_count,draft_count,finalized_count,chapters:[{no,title,status,word_count}]}],jobs:Job[],warnings:string[]}`。ETag响应头与body.etag为书依赖digest。不自动创建任何任务。
- POST `/production`，If-Match必填，`{mode:'prepare'|'append'|'new_volume',volume_no?:number,count:1..50=10,logline:string='',requirements:string='',client_request_id:UUID}` →202 Job。prepare只目标未写范围，append从当前卷尾后追加，new_volume从全局预留最大章号后。与后卷范围冲突409，不挪后卷。
- GET `/production/{id}` → Job，响应ETag为manifest摘要；Job含`id,book,status,phase,numbers,current_chapter,completed:number[],applied:number[],reason,request,created_at,updated_at,etag,preview_digest?,interrupted?:boolean`。
- GET `/production/{id}/review` → `{job:Job,candidate:Bundle|null,preview_digest:string,files:[{path,before,after}],chapters:[{no,title,body,fingerprint,outline_fingerprint,status,check:object|null,review:object|null}],warnings:string[]}`。
- PUT `/production/{id}/candidate`，If-Match=job.etag，`{candidate:Bundle}` → review；只存任务候选，严格服务器重验范围/文件路径/保护集；重算摘要，旧确认失效。
- POST `/production/{id}/confirm`，If-Match=job.etag，`{preview_digest,client_request_id}` →202 Job；只在awaiting_outline_confirmation，以当前输入digest验证；confirmation操作相同ID/摘要返回回执不重复生成。
- POST `/production/{id}/pause|cancel`，`{}`，If-Match=job.etag → Job，投递安全检查点请求；生成中etag变化可刷新后重试，不自动重复模型调用。
- POST `/production/{id}/resume`，If-Match，`{client_request_id}` →202 Job；只resume已暂停/中断/error且依赖仍匹配，完成章不重复。
- POST `/production/{id}/finalize`，If-Match，`{chapter_nos:number[],fingerprints:Record<章号,string>,client_request_id,confirmed:true}` → `{job:Job,results:[{no,applied:boolean,result?:object,error?:string}],stopped:boolean}`；只接受已通读连续段，原检查/指纹/合同重查，真实用户动作顺序finalize，冲突/写回错误停止。无force/auto_finalize。

错误detail={code,message}：422参数、404不存在、412输入/任务版本、409忙/保护/冲突/stale、428缺If-Match、503未知/损坏不可继续。202不表示成功完成。坏任务在卷列表warnings显示，不吞成无任务。

## 4. 模块实施契约
production.py负责文件任务/依赖digest/线程/幂等/确认恢复与API公共服务；volumeproduction.py负责prepare/validate/单章调度；draftcontext.py负责临时事实。

独立模块接缝：
- `volumeproduction.prepare(book, request, *, client=None, progress=...) -> Bundle`（progress(phase,current_no)保存安全检查点；暂停时抛专用暂停异常）。
- `volumeproduction.validate_bundle(book,bundle,numbers) -> dict[str,str]`返回完整将发布的档案文件，包括OUTLINE和细纲；纯校验/渲染、不写正式档案，确认时由production统一发布。
- `volumeproduction.generate_chapter(book,no,job_dir,*,client=None) -> checkpoint`串行复用单章，成功pending_finalize后保存draftcontext；checkpoint至少正文/合同fingerprint/status/check/review。
- `pipeline.prepare_outline(book,no,*,projection,previous_contracts,client=None) -> {no,fm,body}`：projection含outline/Bible/characters/plot_rows；不写正式文件、不改state；单章generate_outline仍原入口。
- `draftcontext.load_for_chapter(book,job_dir,no)`严格校验源指纹，`collect(book,job_dir,no,client)`仅抽取并保存批次文件；内部批次作用域提供pipeline/assembler所需数据，默认不传不变。

## 5. 失败模式（强制）
准备中断保留已完成候选片段，完整包未就绪不能确认。确认写档中断有恢复标记和原文/目标指纹，不能接口200半写；第三方改动recovery_required。模型空/截断/解析坏/红线/护栏/未知临时事实/规则未生效→暂停/错误；后续章调用数为0。页面离开只停止等待，不取消后台；任务可刷新恢复。完成章指纹改动后缀stale，不能继续或定稿旧结果。定稿回执失败不重复完成章/调用V4；原finalize结果writeback error或冲突时停止并留回执。原文件与DB联合原子性不虚假承诺，明确可恢复提交。

## 6. 验收判据（强制）
按批准快照阶段0/A/B/C执行。
- A测试：prepare不自动采纳；一次人工confirm；stale/保护/partial包拒绝；幂等与busy；append不改旧章/号；重启不自动再计费；确认写回故障恢复与第三方保护。
- B测试：3章一次confirm后无中间点击到pending_finalize且finalize次数0；第2/3章只收真实前文临时上下文；正式档案/记忆/FTS指纹不变；M04/越权/队列/未生效/截断暂停后续不调用；resume不重跑完成章；前文改动后缀stale；人工finalize指纹/回执/冲突停止；旧单章兼容。
- C：前端test:offline实际状态/晚到/刷新/一次确认/输入保护；lint:check/typecheck/build。临时mock实例3章真实全链路、刷新/暂停恢复、红线/未知/外部改稿/确认中断/追加冲突、1280×800无溢出/阅读行号/危险动作区分。
- 基线与每阶段pytest FAILED集合无新增且全绿、smoke，提示词23文件/版本/变量回归；最终一次有界复核与具体修复复测。相关diff/doc引用检查。
测试全部home+mockllm、不得真实网络。真模型/真实副本缺失只报工程结果，不声称质量改善。
