# 规格 03 · 管线与约束

> 上游：开发计划.md M2/M3。本文档定义单章闭环每个环节的功能、约束、模型、异常处理。

> 规格06覆盖项：请求装配与日志、M-12仅建议、V1允许无问题、手动V2候选预览及人工采纳恢复见 `06-生成文风与安全去AI味规格.md` §2、§5—§9。采纳后回机检，敏感词人工处理、V5护栏、定稿与记忆闭环不变。

## 1. 管线总览

```
细纲生成(P-G6) → 人工确认关 → 上下文装配 → 正文生成(P-W1)
  → 机械检查(V1-mech) → [阻断→P-V5→重查] → LLM审校(P-V1)
  → [fix→P-V5→重查重审, ≤2轮] → 人工定稿关 → 快照 → 记忆卡回写(P-V4)
  → (卷末) 跨章审计(P-V6)
```

## 2. 各环节规格

### 2.1 细纲生成与确认关
- 输入：大纲该章行、卷目标、上章钩子、出场角色状态、活跃伏笔、章号
- 程序校验：FO 编号合法、钩子类型与上章不同（规格02 P-G6）
- **人工关口**：UI 表单化展示 frontmatter，可编辑；确认后 frontmatter `confirmed: true`，进入锁定——锁定后正文生成阶段不接受细纲变更，改细纲 = 回到 outline_draft

### 2.2 上下文装配器
- 槽位与预算：开发计划 §2.3 十三槽位
- FTS5 检索 query 构造：本章细纲核心事件关键词 + 出场角色名 + 场景地名，取 top 8 片段（每片 ≤150 字）
- **超预算截断顺序**（从先砍到后砍）：前文检索片段 → 最近章摘要 → Bible 条目；力量体系行、出场角色卡、细纲合同永不截断
- token 估算：中文字符数 × 0.75（工程粗估，误差可接受；装配结果与估算值记入 log）
- 产出装配预览数据结构（UI 折叠面板可查，排查跑偏的第一入口）

### 2.3 正文生成（P-W1）
- Gemini 流式输出；超时 300s；finish_reason 检测截断
- 输出落 `chapters/001_正文.md`（status: draft, version 不变）
- 字数越界自动重跑一次（见规格02）

### 2.4 机械检查（零 token，规则表）

| ID | 级别 | 逻辑 | 词表/来源 |
|----|------|------|----------|
| M-01 | 阻断 | 字数 ∉ [2200, 2800]（config 可调） | config |
| M-02 | 阻断 | 禁词命中，输出行号+词 | banned_words.txt（S1+T8-B） |
| M-03 | 阻断 | 对话后缀：`(淡淡|平静|缓缓|冷冷|温柔)(地)?(说道|问道|答道|开口)` | dialog_suffix.txt |
| M-04 | 阻断 | 敏感词红线命中 | sensitive_words.txt |
| M-05 | 提醒 | 单句逗号 >2 | 标点规则 |
| M-06 | 提醒 | 每千字感叹号 >2 或省略号 >3 | 标点规则 |
| M-07 | 提醒 | 连续 4+ 句长度差 <20%（爆发度塌陷） | 句长算法 |
| M-08 | 提醒 | 段落 >120 字（>4 手机行） | 排版规则 |
| M-09 | 提醒 | 连续 3 段以相同词开头 | 模板检测 |
| M-10 | 提醒 | 末 200 字命中总结式收尾词（"他知道/从这天起/一切才刚刚开始/未来"） | 启发式 |
| M-11 | 提醒 | 非对话段"我"占比 >8%（主视角漂移启发式，允许误报） | 启发式 |

阻断未过 → 自动 P-V5 修复 1 轮 → 重查；仍有阻断 → human_review。提醒级只记录不拦截。

### 2.5 LLM 审校闭环（P-V1）
- 注入：正文 + 程序预生成的疑似冲突清单（角色状态 diff、伏笔状态核对、术语表比对）+ 细纲合同 + 台账摘要
- verdict=fix → P-V5 定向修复 → 重跑 2.4+2.5，最多 2 轮（config）
- verdict=fail 或轮次耗尽 → **人工关口**：改细纲重写 / 手改正文 / 豁免（必填理由入 log）
- 审校 JSON 必须包含五个 0–100 有限数字分数与完整举证字段；缺失/非法输出回喂重试，耗尽进入 error，不接受缺分的 pass。
- 正文手改/定向修复/润色后，审校态与待定稿态统一回退机检；审校与定稿都必须核对当前正文指纹。人工豁免绑定本版正文，后续改文即失效，检查未生效不可豁免。

### 2.6 人工定稿关
- 展示：五维分数、问题清单、与上版本 diff
- 定稿 = 二次确认 → 写快照 + `status: final` → 触发记忆卡回写

### 2.7 记忆卡回写（P-V4）
- JSON diff 到档案：无冲突自动写，冲突进裁决队列（见规格01 §4）
- 同时更新：全局摘要（最近章摘要环形缓冲，保留最近 2 章 + 累计摘要）、chapters_fts 索引
- 记忆卡先抽取并完整校验候选，再替换派生事实；应用异常恢复旧档案、摘要、状态索引与 FTS，模型调用历史与费用日志仍保留。回写失败不撤销定稿，缺卡入口可重试。
- 状态卡按规格05 C-05 先生成提议，由人工对比后确认；已确认状态卡不得被下一次 V4 静默覆盖。

### 2.8 卷末审计（P-V6，M3）
- 触发：某卷最后一章定稿后
- 输入：本卷全部正文 + PLOT_POINTS 全表 + 主要角色弧光 + Bible
- 输出：伏笔回收率（程序算，LLM 解读）、人物弧线连贯性、设定统一性、下一卷铺垫清单

## 3. 异常处理总表

| 异常 | 处理 |
|------|------|
| API 超时/限流 | 指数退避重试 ×3，全程记 generation_log；仍败 → error 状态，UI 可一键重试 |
| JSON 解析失败 | 错误信息回喂重试 ×2；仍败 → error |
| 字数越界 | 自动重跑 1 次强调字数；仍越界 → 转人工 |
| 阻断级 lint | 自动 P-V5 一轮；仍阻断 → human_review |
| 台账冲突 | 进裁决队列；非空则禁止开下一章细纲 |
| 敏感词 | 阻断 + 人工处理，**禁止自动改写**（红线必须人审） |
| 返回空/截断 | 按 finish_reason 判定，重试 |
| 应用崩溃 | 状态机落库，重开从当前位置续跑；未完成的 generating 草稿保留 |

## 4. 成本核算

- generation_log 逐笔记 input/output tokens 与成本（模型单价写进 config）
- 书总览页显示：本章成本、本卷累计、全书累计；单章 >1 元标黄（验收线）
- 修复循环的重试调用同样计入

## 5. 断点恢复语义

- 状态机状态 + 当前版本号持久化于 SQLite；文件为准、状态可重建
- 崩溃恢复规则：generating 中断 → 保留半成品草稿为 draft.vN，重开提示"继续生成或重来"；review 中断 → 重跑审校
- 同章重写永远开新 version，不覆盖旧 draft——旧版本可从版本列表回看
- 同一进程内，同书写操作互斥；正文编辑可带 `expected_revision`，修订号不匹配返回 409，拒绝覆盖。跨进程共同写同一本书不在支持范围。

## 6. rubric 五维评分锚点（写入 P-V1 prompt）

| 维度 | ≥90 | 70-89 | <70（触发 fix） |
|------|-----|-------|----------------|
| AI味 | 禁词零命中、句长有落差、无模板段 | 个别提醒级命中 | 阻断级命中或通读机器感明显 |
| 剧情一致性 | 无冲突、伏笔操作正确 | 个别 warning | 台账硬冲突、设定越界、OOC |
| 节奏爽点 | 前30%入题、钩子明确、密度达标 | 密度略欠 | 流水账、无钩子、与细纲偏离 |
| 文笔画面 | 五感≥2种、对话有辨识度、有潜台词 | 描写偏概括 | 千人一声、无画面、说教 |
| 开篇钩子 | 300字内入题接上章钩子 | 入题稍慢 | 开篇拖沓/重复上章信息 |
