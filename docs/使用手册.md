# AI 网文创作工作台 · 使用手册

> 文档日期：2026-10-26 ｜ 读者：第一次打开这个工具的人
> 目标：**不问人跑完第一卷**。本手册描述的是界面上的真实行为（以代码为准），不是规格设想。
> 遇到问题先看第 4 节排查表；动手改代码前看 `docs/交付报告.md` 第 7 节。

---

## 1. 这个工具是什么 / 不是什么

**是什么**：一个跑在你自己电脑上的网文创作工作台。它用 23 条分工明确的提示词（简称 P，如 P-G6 写细纲、P-W1 写正文、P-V1 审校）驱动你自选的 OpenAI 兼容 API（官方或中转站均可），把"定设定 → 出大纲 → 逐章写稿 → 机检 → 审校 → 定稿 → 沉淀档案"这条链路自动化；每一章的上下文由 13 槽位装配器按预算拼装，每次调用的 prompt 摘要、token、成本全部入账可查。

**不是什么**（边界，先想清楚再用）：

| 边界 | 说明 |
|------|------|
| 本地单机，零云部署 | 一个 Python 进程 + 浏览器。数据全在 `books/<书名>/`（Markdown 档案）和 `data/`（SQLite 索引），不联网也能跑（除了调 LLM 那次） |
| AI 辅助，**人工主导** | 两个人工确认关（细纲确认、章节定稿）不许绕过；敏感词命中禁止自动改写；V5 修复越权会被丢弃——这些是产品红线，不是可优化项 |
| 不是一键成书机 | 它把你从"每章点 5-7 次按钮"减到"关键处点几次"，并把质量门（机检+五维审校）变成程序强制；写什么、好不好，仍然你说了算 |
| 文件是真相，DB 是索引 | `books/` 下的 Markdown 是单一真相源，`data/` 的 SQLite 随时可删可重建（运行历史除外） |

## 2. 五分钟跑通第一条闭环

从零到第 1 章定稿的完整点击路径。前置：已 `pip install -r requirements.txt`、已 `cd web && npm install && npm run build`。

### 第 0 步 · 启动与配 key

1. 终端运行 `python run.py`，约 1 秒后浏览器自动打开 `http://127.0.0.1:8765`。
2. 顶栏进 **设置** → 「API 连接」面板填三格：
   - **API key**：你的 key（官方 API 或 one-api/new-api 类中转站均可）；
   - **base_url**：填到 `/v1` 为止，如 `https://your-relay.com/v1`，**不要带** `/chat/completions`；
   - **默认模型**：可留空。留空 = 用各书 `config.json` 的五档模型；填了 = 所有档位都用它（中转站推荐用法）。
3. 点 **保存连接** → 点 **测试连接**，看到绿色 OK + 模型回复即通。
   > ⚠️ key 输入框**留空 = 保持原 key 不变**（框里显示的是掩码占位串，不是真实 key）。只改 base_url 时不用重填 key。

### 第 1 步 · 建书（书架页）

填 **书名（必填）→ 题材（都市/玄幻/言情/悬疑）→ 目标字数 → 笔名（可空）→ 平台（默认"番茄"）**，点 **创建**。创建后自动进入该书的总览页。

### 第 2 步 · 备档案（书总览 → 档案编辑）

新书的 `OUTLINE.md` 章节总表是**空表**，而细纲生成要求总表里已有该章行——所以第一件事是先让大纲有内容。两条路任选：

- **快路（推荐）**：档案编辑页顶部点 **G5 全书大纲** → 按弹窗依次回答「目标总章数」（默认 120）、「一句话故事」→ 生成完在 **diff 预览**里核对新旧差异 → 可手改 → **采纳落盘**。采纳是合并式的：新章节行进表，已有伏笔台账的编号与状态保留。
- **稳路**：档案编辑页左侧树选 **OUTLINE.md 大纲 → 章节总表**，直接在表格里加第 1 章一行（章/卷/本章目标/冲突来源/爽点/钩子类型/重要度）。

顺手可做（不阻断主线）：meta 里填对标书与故事核；点 **G1 世界观** / **G2 力量体系** 生成后看 diff 采纳；**G3 角色卡** / **G4 关系网** 同理。

### 第 3 步 · 第 1 章闭环（章节工作台）

书总览「章节列表」上方填章号 1 → **进入工作台**。然后按界面里的 ①②③④⑤ 顺序：

1. **① 细纲**：点 **生成细纲（P-G6）** → 等它生成（约十几秒）→ 检查下方表单与场景清单，可用 stage/情绪任务/钩子类型下拉微调 → 点 **确认细纲（锁定）**（有二次确认弹窗）。
2. **② 正文生成**：点 **开始生成（流式）**，正文逐字流出；前 3 章会自动走 W3 黄金三章专项（顶栏有标记）。等"生成完成"提示。
3. **③ 机械检查**：点 **跑机械检查（含自动修复1轮）**——零 token。阻断级问题会自动用 P-V5 修一轮再查；仍阻断转人工。想省事可跳过本步直接点 **一键跑完本章（机检→审校→再机检）**（上限 3 轮，遇人工关自停）。
4. **④ LLM 审校**：点 **跑审校**，看五维分数条（AI味/剧情一致性/节奏爽点/文笔画面/开篇钩子）与问题列表。verdict=fix 会自动进入定向修复循环（最多 2 轮，书级配置可调）。
5. **⑤ 人工关口 / 定稿**：通读一遍（这是规格里的"本人通读门"，没有自动化替代）→ 需要小改可 **定向修复（P-V5）** 或 **整章润色（P-V2+V3）** 或 **编辑正文** 手改；问题可接受就 **豁免（必填理由）**；确认无误点 **定稿（二次确认→快照+回写）**——两次确认后写快照、置 status=final、触发记忆卡回写（档案自动沉淀）。

**到此第 1 章定稿完成。** 导出页可随时把定稿章节合并成 txt/md 或整书打包 zip。

## 3. 分页面操作说明

### 3.1 书架

| 元素 | 行为 |
|------|------|
| 新建书表单 | 书名必填；题材四选一；目标字数步进 10 万；笔名可空；平台默认"番茄" |
| 创建 | 成功后自动打开该书总览 |
| 书卡片 | 显示 题材 · 目标字数（万字）· 平台 · 状态 |
| 打开 / 删除 | 打开进总览；**删除有两重确认弹窗**，文案明示"将删除 books/书名/ 整个目录，不可恢复" |

### 3.2 书总览

顶部：书名、**待裁决 N 条**角标（或"裁决队列空"）、**档案编辑** 入口按钮、全书成本与调用次数。内容分两列共七块面板：

| 分区 | 能做什么 |
|------|---------|
| 档案导航 · AI 生成 | **G1 世界观 / G2 力量体系 / G3 角色卡 / G4 关系网 / G5 全书大纲** 五个按钮。点击后按提示补变量 → 生成 → **采纳**（流程：生成 → diff 预览 → 人工改定 → 采纳落盘，AI 永不静默覆盖人工内容） |
| 世界观圣经 | 按固定 H2 节（基础设定/力量体系/势力格局/历史脉络/隐藏规则/术语表/日常细节）分节编辑，**保存圣经** 整本落盘；力量体系列名写错会被拒绝并提示应为哪 8 列 |
| 文风系统（M5） | 贴语料（≥500 字，建议 3000-10000）→ **保存语料** → **分析生成特征卡（F1）** → 改定 → **保存特征卡** → 拨开关**启用文风注入**（下次生成生效；会注入装配器 system 段 + 给 W1 喂真实范文片段 + 让 V1 按目标文风评分） |
| 伏笔台账 | Markdown 表格文本域 + **保存台账**；状态只允许 planted→building→paid 单向，非法迁移被后端拒绝 |
| 角色档案 | 角色按钮列表 + 新角色建档（名字 + 五种定位） |
| 章节列表 | 章/状态徽标/版本/修复轮数/成本（>1 元标黄）/工作台入口；上方有"进入工作台"章号框与**卷末审计（V6）**（填截止章号，完成后 toast 显示伏笔回收率与报告路径，报告文件在 `books/<书名>/audits/卷N_审计.md`） |
| 大纲（章节总表） | 只读表格预览；折叠项里可编辑 Markdown 章行表 + **保存大纲** |

### 3.3 档案编辑（左树右编辑器）

从书总览顶部 **档案编辑** 按钮进入。左侧树选档案，右侧出编辑器；结构化字段一律表单，长文本用 Markdown。

**左树节点与右侧编辑器：**

| 节点 | 编辑器 |
|------|--------|
| meta.md 书籍信息 | 结构化表单：title/author/genre/tags/目标字数/平台/对标书/status 下拉/合规声明/正文。**保存 meta.md** |
| STORY_BIBLE.md（按 7 节展开） | **力量体系** = 8 列可增删行表格（大境界/子境界/突破条件/能力边界/战力对标/寿元/代价与风险/突破异象）；其余节 = Markdown 文本域。按节保存 |
| 角色（N） | 动态状态表单（境界/位置/情绪/存活开关/伤势/物品/已知信息/更新章）+ 其余 H2 节折叠 Markdown（关系网络节由 G4 采纳自动合并写回，也可手改）。**保存角色** |
| 地点（N） | 5 列表格（名称/特征/方位距离/首现章/关联剧情）。**保存地点档案** |
| 伏笔台账（N） | 7 列表格（编号 FO-001/内容/埋设章/推进章/预计回收章/状态下拉/备注）。**保存伏笔台账** |
| OUTLINE.md 大纲 | 三个子节点：**章节总表**（7 列）、**卷规划**（卷号/卷名/起止章如 1-12/核心冲突/本卷目标/卷末高潮/卷末钩子）、**爽点节奏总谱**（独占文本域，不会被其他保存重置） |
| 文风（M5） | 同书总览的文风面板 |

**AI 生成 → diff → 采纳**：页头也有 G1-G5 按钮。生成后弹窗顶部是 **DiffViewer**（旧档案 vs 新结果逐行对比：新增绿底、删除红线，默认只显示变更段落 ±3 行，可切"显示全部行"），下方是可手改的生成结果文本域，最后 **采纳落盘**。采纳语义：bible 只更新出现的节；characters 新建缺失角色、关系行合并进各角色关系节；outline 章节行合并、伏笔台账按内容匹配保留原编号状态。

**书级配置（config.json）面板**（档案编辑页底部，管实际生效的参数）：

| 配置 | 说明 |
|------|------|
| model_stages 五档 | plan/prose/polish/review/longctx 各配模型名；设置页"默认模型"非空时全覆盖它 |
| 单章字数区间 | **实际生效的就是这里**（M-01 机检按它判越界；meta.md 里的同名字段没有代码读取，改了不生效） |
| 审校修复最大轮次 | 默认 2 |
| 逐场景生成 scene_mode | 开启后按细纲场景逐个生成再缝合（每场景独立注意力+字数配额） |
| 禁词白名单 lint_whitelist | 每行一词；目标文风招牌词与通用禁词冲突时豁免 M-02（不豁免敏感词） |

### 3.4 章节工作台（核心页）

顶栏：章号上下章导航、状态徽标、当前版本、本章累计成本、黄金三章标记；**error 状态时出现「重试（恢复到 X）」按钮**（X = 后端记录的出错前状态）。

**① 细纲（章合同）**

- 按钮：**生成细纲（P-G6）** / **确认细纲（锁定）** / **编辑细纲原文**（YAML+场景清单原文模式，带格式校验）。
- 表单：核心事件、pov 只读展示；stage（引入/发展/转折/高潮/收束）、情绪任务（压/小扬/爆）、钩子类型（悬念/选择/反转）三个下拉，未确认前可直接改；**伏笔操作只读展示**（JSON，要改只能进"编辑细纲原文"）；场景清单以等宽预览展示；确认锁状态明示。
- 锁定语义：确认后 `confirmed: true`，正文阶段不接受细纲变更（接口直接拒绝，提示走"改细纲重写"）。

**② 正文生成**

- **开始生成（流式）**：SSE 逐字流出、自动滚底；切章/离开自动取消本页读取（后端继续生成并正常收尾）。
- 场景专项下拉：**自动（卷首三章 W3 / 其余 W1）/ W2 对话专场 / W4 突破场景 / W5 高潮场景**。三者都是"整章替换提示词"语义（不是槽位插入），且都带 `〖字数区间〗` 硬约束，超了会被 M-01 拦。
- **编辑正文**：人工手改正文（弹窗 textarea，显示当前字数）。保存后 version 不变、status 保持 draft、字数由后端重算；`pending_finalize` 状态手改后会被打回 `mech_check` 重跑机检（防止绕过质量门）；**finalized 状态按钮禁用**。
- 正文区按行渲染并带行号——这是给下面的"点击跳转"用的。

**装配预览（排查跑偏第一入口）**

点 **生成装配预览**：展开 13 槽位折叠面板，每槽显示标题 + token 估算 + 是否已截断 + 内容；顶部显示总估算/预算与落盘路径（`data/assembly_previews/<书>/NNN_vN.json`，每次生成前也会自动落一份）。**生成结果跑偏时，先来这里看哪槽被截断/哪槽内容不对**，比反复重生成省 token。截断顺序（预算紧张时从先砍到后）：前文检索 → 前情摘要 → Bible 条目；力量体系行/出场角色卡/细纲合同永不截断。

**③ 机械检查（零 token）**

- 按钮：**跑机械检查（含自动修复1轮）**；**一键跑完本章（机检→审校→再机检）**（自动编排，上限 3 轮，遇人工关/error 停并提示，带进度日志）。
- 报告：结论徽标 + 命中列表（规则 ID / 级别 block|warn / 行号 / 命中词 / 说明）。**点任意命中项，正文区滚动到对应行并高亮 2 秒。**
- 规则表：M-01 字数越界（block）/ M-02 禁词（block，白名单可豁免）/ M-03 对话后缀禁式（block）/ M-04 敏感词（block，**禁止自动改写**，直接转人工）/ M-05~M-11 提醒级（逗号/感叹号省略号密度/平句/长段/段首重复/总结式收尾/第一人称占比）。阈值在设置页可调。

**④ LLM 审校（P-V1 五维）**

- 按钮：**跑审校**。报告：verdict 徽标 + 五维进度条 + 问题列表（类别/severity/原文引用/位置/描述/建议），blocking 红边；location 里抽得到行号的问题也可点击跳转。
- **程序守门**：任一维 <70 或存在 blocking → 强制 fix（模型自报 pass 也没用，这是红线）；全维 ≥90 且零问题会触发一次防橡皮章复审。fix 循环最多 2 轮（书级配置可调），耗尽转 human_review。

**⑤ 人工关口 / 定稿**

| 按钮 | 行为 |
|------|------|
| 定向修复（P-V5） | 用最近一轮机检/审校问题清单做定向修复；**未涉及句段改动率 >10% 的输出会被整体丢弃**（越权护栏），转人工走完整重生成 |
| 整章润色（P-V2+V3） | 去 AI 味两段式（润色 + 自检复核）；不改剧情人设，字数浮动 >10% 或机检阻断会自动丢弃 |
| 豁免（必填理由） | 理由写入 generation_log 作为合规证据；空理由提交不了 |
| 改细纲重写 | 回到 outline_draft 改细纲（正文保留，改完需重新确认+生成）；**仅 human_review 状态可达** |
| 定稿（二次确认→快照+回写） | 两次确认弹窗；写快照、status=final、触发记忆卡回写（角色状态/伏笔/新地点/摘要/FTS 索引自动沉淀）；卷末章定稿后自动触发 V6 审计 |
| 从版本重写 | 选快照版本开新分支（human_review/finalized 可用；不传版本则沿用当前正文，**绝不写空**） |
| 查看该版本正文 | 只读回看任意快照（不触发重写） |

### 3.5 裁决队列

顶栏"裁决队列"带未处理数角标（15 秒轮询）。列表显示每条冲突的 kind/章号/书/角色/详情与"档案现值 → AI 新值"。三个动作：

| 动作 | 含义 |
|------|------|
| 采纳AI | 以 AI 新值更新档案 |
| 保留档案 | 维持人工档案，丢弃 AI 值 |
| 手改采纳 | 输入框填值（JSON 或纯字符串均可）后提交 |

**为什么非空时不能开新章**：队列里的冲突（境界倒退/死者复现/未知角色/非法伏笔操作/待补录设定）意味着档案与生成结果已分叉，此时再开下一章只会把错误传播下去。这是硬拦截（后端第一行守卫），处理完队列才能继续。

### 3.6 设置

| 面板 | 内容 |
|------|------|
| API 连接 | key（留空=保持原 key）/ base_url（到 /v1 止）/ 默认模型；**保存连接** + **测试连接**（显示 OK/失败 + 模型 + 回复或错误） |
| 单价（分/百万 token） | JSON 文本域。**成本显示 0 的根因通常在这里**：模型名不在表里就按 0 计（首次调用会在控制台记告警日志）。默认表只含 deepseek-chat/reasoner 与 gemini-2.5-pro/flash |
| 机械检查阈值（M-05~M-11） | 9 项数字表单（单句逗号/感叹号密度/省略号密度/平句窗口/平句阈值/单段字数/段首重复/结尾窗口/第一人称占比），保存后下一轮机检生效；另显示装配预算 token |
| lint 词库 | 三套下拉切换（禁词表 M-02 / 敏感词红线 M-04 / 对话后缀禁式 M-03），**载入** → 改 → **保存**；每行一个词，# 注释 |
| 系统维护 | **从文件重建 SQLite 索引**（rebuild，删库重建场景用；运行历史不重建）；FTS 模式显示（trigram 不可用时自动 bigram） |

### 3.7 导出

选书后三个按钮：**导出定稿合并 txt** / **导出定稿合并 md**（`## 第N章` 二级标题）/ **全书打包 zip**（整个 `books/书名/` 目录）。txt/md 只含 `status=final` 的定稿章节；中文书名与内容实测无乱码（POST blob 下载）。

## 4. 常见问题排查

| 症状 | 原因 | 怎么办 |
|------|------|--------|
| 生成报 401 / 全部调用失败 | key 无效或 base_url 不对 | 设置页 → **测试连接**。确认 base_url 到 `/v1` 为止、不带 `/chat/completions`；key 输入框留空=保持原 key，确认没被清空 |
| 生成中途断网/超时，状态变 error | LLM 异常已落 error（不再卡死） | 顶栏点 **重试（恢复到 X）**：恢复到出错前状态，正文与快照不动。流式生成期间每约 400 字会把半成品落盘到 `books/<书名>/chapters/00N_正文.draft.md`，崩了也能从那里捞回已生成部分 |
| 提示"裁决队列非空（N 条待处理），禁止开新章细纲" | 有冲突未裁决 | 顶栏进裁决队列，逐条 采纳AI/保留档案/手改采纳，清到 0 |
| 提示"OUTLINE.md 章节总表缺第 N 章行，先补全书大纲" | 新书总表是空表 | 档案编辑页用 **G5 全书大纲** 生成并采纳，或在 章节总表 里手动加该章行 |
| 成本显示 0.00 元 | 该模型名不在单价表 | 设置页「单价」补上（JSON：`{"模型名": {"input_per_mtok_cents": x, "output_per_mtok_cents": y}}`）；注意 >1 元标黄也依赖它 |
| 生成跑偏/内容不对 | 上下文装配问题 | 工作台 **生成装配预览**：看 13 槽哪槽被截断、哪槽内容意外；重点查 前文检索（FTS 召回）/前情摘要/角色卡。落盘的预览 JSON 在 `data/assembly_previews/<书>/` |
| V5 越权护栏触发（修复被丢弃，转人工） | 定向修复改动超过了问题涉及范围（未涉及句段改动率 >10%） | 这是有意设计，防止 AI 借修复之名重写全文。改用 **编辑正文** 手改，或 **改细纲重写** 走完整重生成 |
| 定稿后想改正文 | 正文/快照/导出一致性保护 | 当前版本**没有解锁按钮**（已知遗留）：用 **从版本重写** 开新版本分支返工（旧快照保留）；「编辑正文」在 finalized 下被禁用 |
| 豁免提交不了 | 理由为空 | 豁免理由必填（会入 generation_log） |
| 润色被丢弃 | 字数浮动 >10% 或机检阻断 | 有意设计（润色不许改剧情人设）；看丢弃原因提示，改用定向修复或手改 |
| 改 meta 里的"单章字数区间"不生效 | 实际生效的是 `config.json` 的那份 | 去档案编辑页底部 **书级配置** 面板改（已知不一致，见交付报告 §8） |
| exe 打不开界面 | 打包产物是旧的（缺 web/dist） | 用 `python run.py` 运行；或重新打包（见 README 打包段：`pyinstaller ainovel.spec` 后把 `prompts/ lint/ web/dist` 拷到 `dist/ai-novel/` 下） |

## 5. 红线与人工确认点（不是可优化项）

来自 `AGENTS.md` 架构核心第 3 条与规格03，全部由程序强制：

1. **细纲确认关**：确认即锁定（`confirmed: true`），正文阶段不接受细纲变更；改细纲只能走"改细纲重写"回退。
2. **章节定稿关**：二次确认 → 快照 + status:final；定稿后正文/快照/导出三方一致，`/fix` 无法再静默改写已定稿章。
3. **M-04 敏感词命中 = 阻断 + 禁止自动改写**：不走 V5 自动修复，直接转人工，必须人审。
4. **V5 越权护栏**：未涉及问题句段改动率 >10% 的输出整体丢弃，转人工完整重生成；不许放宽。
5. **裁决队列非空禁止开下一章细纲**：硬拦截，先处理冲突再继续。
6. **所有 LLM 调用记 generation_log**（prompt_digest / tokens / cost），豁免必填理由入 log——这是"每次生成可从 log 复现"的根基，也是合规证据链。
