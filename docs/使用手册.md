# AI 网文创作工作台 · 使用手册

> 更新日期：2026-10-30 ｜ 读者：第一次打开这个工具的人
> 目标：按作者三步完成第一卷待审稿；一次整卷细纲确认与最后人工定稿不可省略。本手册描述界面真实行为，不把离线验收当文学质量保证。
> 遇到问题先看第 4 节排查表；动手改代码前看 `docs/交付报告.md` 第 7 节。

---

## 1. 这个工具是什么 / 不是什么

**是什么**：一个跑在你自己电脑上的网文创作工作台。它用 23 条分工明确的提示词（简称 P，如 P-G6 写细纲、P-W1 写正文、P-V1 审校）驱动你自选的 OpenAI 兼容 API（官方或中转站均可），把"定设定 → 出大纲 → 逐章写稿 → 机检 → 审校 → 定稿 → 沉淀档案"这条链路自动化；每一章的上下文由 13 槽位装配器按预算拼装，每次调用的 prompt 摘要、token、成本全部入账可查。

顶栏当前书提供“卷工作台 / 书总览 / 单章精修 / 档案编辑 / 状态卡”和最近书。默认继续生产进入卷工作台，任务来自服务端文件；单章精修保留最近有效章。浏览器不保存正文、词库或候选草稿。

**不是什么**（边界，先想清楚再用）：

| 边界 | 说明 |
|------|------|
| 本地单机，零云部署 | 一个 Python 进程 + 浏览器。数据全在 `books/<书名>/`（Markdown 档案）和 `data/`（SQLite 索引），不联网也能跑（除了调 LLM 那次） |
| AI 辅助，**人工主导** | 两个人工确认关（细纲确认、章节定稿）不许绕过；敏感词命中禁止自动改写；V5 修复越权会被丢弃——这些是产品红线，不是可优化项 |
| 不是一键成书机 | 它把你从"每章点 5-7 次按钮"减到"关键处点几次"，并把质量门（机检+五维审校）变成程序强制；写什么、好不好，仍然你说了算 |
| 文件是真相，DB 是索引 | `books/` 下的 Markdown 是单一真相源，`data/` 的 SQLite 随时可删可重建（运行历史除外） |

## 2. 作者三步跑通第一卷（推荐）

前置：已安装依赖并构建前端。启动和连接配置是一次性的；每卷模型耗时取决于章数、模型和修复次数，不承诺五分钟完成。

### 第 0 步 · 启动与配 key

1. 终端运行 `python run.py`，约 1 秒后浏览器自动打开 `http://127.0.0.1:8765`。
2. 顶栏进 **设置** → 「API 连接」面板填三格：
   - **API key**：你的 key（官方 API 或 one-api/new-api 类中转站均可）；
   - **base_url**：填到 `/v1` 为止，如 `https://your-relay.com/v1`，**不要带** `/chat/completions`；
   - **兜底模型**：可留空。它是**最后兜底**，只在书级档位与全局档位都没配时才用；**不会**再覆盖各书的五档配置（规格12 改掉了旧 `default_model` 的"一刀切覆盖"语义）；
   - **全局 plan/prose/polish/review/longctx 档**：可选，给所有书一个统一默认，书级配置仍然优先。
3. 点 **保存连接** → 点 **测试连接**，看到绿色 OK + 模型回复即通。
   > ⚠️ key 输入框**留空 = 保持原 key 不变**（框里显示的是掩码占位串，不是真实 key）。只改 base_url 时不用重填 key。

### 建书（书架页）

填写书名、题材、目标字数等并创建，进入**卷工作台**。创建本身不调用模型；旧档案与高级规划不会因打开页面被自动采纳。

### 第一步 · 填故事，准备本卷

填写“一句话故事”“本卷要求”“期望章数”（默认10，1—50整数），点**准备本卷**。后台串行准备卷纲、内部单元、必要资产与本批全部细纲候选，你不用逐层调度。准备阶段只写任务目录，不写正式 Bible、角色卡或正文。

**还没想好故事？** 新书首卷未准备时，直接点“没想法？AI 给我 3 个故事方案”（规格11）。题材沿用建书配置，不用再选；“创意偏好”可不填，也可填“轻松、小人物、不要系统流”等要求。点击会调用选题模型，候选不是市场推荐或热门保证。

三张卡可比较暂定名、故事简介、主角、核心冲突、卖点及首卷目标/钩子。“选用这个故事”只填入下方一句话故事与本卷要求，保留正式书名、题材和期望章数；已有手填内容先预览替换，取消不改。选完仍可修改，再手动点“准备本卷”。不满意可显式“换一批”，失败保留旧卡和输入，不自动重试。

停止等待不等于取消模型计费；网络未知时可能收不到候选，再调用须明确确认可能重复费用。故事候选不存浏览器本地，刷新不承诺恢复、不自动重发。已有卷/章或未结束任务不能用此入口改换整本故事，请继续原任务。

### 第二步 · 一次确认整卷细纲

通读各章细纲和“将发布的档案差异”。需要调整时编辑候选并保存；保存会重新校验、更新摘要，旧核对勾选失效。核对范围与字数目标后勾选确认，再点**确认本卷全部细纲并开始生成**，在弹窗确认一次。本次人工动作联合采纳预览档案、锁定细纲并启动自动出稿，不是假装上游已采纳。

系统逐章生成、机检、审校与有限修复。后续章使用真实前文和本批临时事实，临时记忆不写正式角色/状态/伏笔/FTS。成功章停在**待定稿**；遇敏感词、越权修复、裁决队列、未生效检查或未知事实会暂停，不越过人工红线。

### 第三步 · 通读稿件，人工定稿

在阅读区选择章节，可切换首行缩进和原始行号；这些只改变显示，不改正文。展开机检/审校结果，必要时去既有工作台编辑或核对。每章当前版本通读后点**我已通读本章当前版本**，选择已读连续章段，再点**人工定稿所选章（二次确认）**。服务端绑定完整正文指纹重新核对，顺序定稿并写回正式记忆；任何冲突或写回失败即停止，以逐章回执为准，不补选未读章。

**生成完成 ≠ 定稿完成。** 改稿会使旧通读标记/检查与受影响后缀失效，必须重新处理，不可沿用旧结果。

### 追加、新卷与恢复

- **本卷追加 N 章**只扩展该卷未来范围，保留旧稿和编号；与后卷冲突时拒绝，不自动挪后卷。
- **新增下一卷**是独立动作，从全局已预留章号之后开始，不扩展当前卷。一本书有未结束任务时先核对、审核或明确停止后续生产。
- **刷新 / 找回任务**只查询服务端，不重发模型。页面离开不取消后台；暂停/停止在安全检查点生效，已发请求可能继续完成并计费。
- 网络结果未知先刷新核对回执，再显式恢复；不承诺从未知结果零费用恢复。确认写档故障先用**核对并恢复提交（不调用模型）**，第三方改动不能被覆盖。损坏/未知版本任务显示警告，不当作空任务。

旧的逐层准备/采纳在**高级入口 → 旧分层规划**；逐章细纲、生成、审校、润色候选与定稿在**单章精修/既有工作台**，不删除这些入口。

## 3. 分页面操作说明

### 3.1 书架

| 元素 | 行为 |
|------|------|
| 新建书表单 | 书名必填；题材四选一；目标字数最低 1 万、步进 1 万，默认 100 万；笔名可空；平台默认"番茄" |
| 创建 | 成功后自动打开该书卷工作台，不调用模型 |
| 书卡片 | 显示题材、定稿进度、最后编辑时间，默认进入卷生产；未知统计不当0 |
| 打开 / 移出书架 / 删除 | 默认打开卷工作台；外挂只解除挂载不动文件，内置删除仍两重确认并明示目录 |

### 3.2 书总览

顶部：书名、**待裁决 N 条**角标（或"裁决队列空"）、**档案编辑** 入口按钮、整体进度、全书成本与调用次数。总览只保留档案摘要和导航；圣经、台账、大纲、角色的手工编辑统一在档案页完成。

| 分区 | 能做什么 |
|------|---------|
| 档案导航 · AI 生成 | **G1 世界观 / G2 力量体系 / G3 角色卡 / G4 关系网 / G5 全书大纲** 与档案页共用参数、候选、差异和采纳流程；生成只产生候选，采纳前显示实际影响范围并校验档案版本 |
| 档案摘要 | 显示 Bible、伏笔、角色与大纲的前几行/条目数，点击定位到档案页对应节点；总览不再提供第二套保存入口 |
| 文风系统（M5） | 贴语料（≥500 字，建议 3000-10000）→ **保存语料** → **分析生成特征卡（F1）** → 改定 → **保存特征卡** → 拨开关**启用文风注入** |
| 章节列表 | 使用可搜索章节选择器，按规划与已有文件的章号并集导航；稀疏章号跳过缺号，未规划章提供补大纲入口；状态显示中文 |
| 整体进度 | 与书架共用统计：定稿章数/规划章数、定稿字数/目标字数；未知统计不画误导百分比 |
| 卷末审计（V6） | 填截止章号，完成后显示伏笔回收率与报告路径，报告文件在 `books/<书名>/audits/卷N_审计.md` |

### 3.3 档案编辑（左树右编辑器）

从书总览顶部 **档案编辑** 按钮进入。左侧树选档案，右侧出编辑器；结构化字段一律表单，长文本用 Markdown。

**左树节点与右侧编辑器：**

| 节点 | 编辑器 |
|------|--------|
| meta.md 书籍信息 | 结构化表单：title/author/genre/tags/目标字数/平台/对标书/status 下拉/合规声明/正文。**保存 meta.md** |
| STORY_BIBLE.md（按 7 节展开） | **力量体系** = 8 列可增删行表格（大境界/子境界/突破条件/能力边界/战力对标/寿元/代价与风险/突破异象）；其余节 = Markdown 文本域。按节保存 |
| 角色（N） | 动态状态表单（境界/位置/情绪/存活开关/伤势/物品/已知信息/更新章）+ 其余 H2 节折叠 Markdown（关系网络节由 G4 采纳自动合并写回，也可手改）。**保存角色** |
| 地点（N） | 5 列表格（名称/特征/方位距离/首现章/关联剧情）。**保存地点档案** |
| 伏笔台账（N） | 7 列表格（编号 FO-001/内容/埋设章/推进章/预计回收章/状态下拉/备注）。**保存伏笔台账** |
| OUTLINE.md 大纲 | 三个子节点：**章节总表**（7 列）、**卷规划**（卷号/卷名/起止章如 1-12/核心冲突/本卷目标/卷末高潮/卷末钩子）、**爽点节奏总谱**（独占文本域，不会被其他保存重置） |
| 文风（M5） | 同书总览的文风面板 |

**AI 生成 → diff → 采纳**：页头 G1-G5 与总览快捷入口共用同一流程。取消参数不会调用模型；生成后只得到候选。采纳前展示真实差异和影响范围：Bible 列出更新节，角色列出新角色/保留角色/关系写回，G5 列出章节总表、卷规划、节奏总谱和伏笔台账，并说明已写章正文不会随大纲重写。档案版本变化会拒绝旧候选覆盖，保留候选供重新核对。

**保存与离开保护**：普通档案和细纲按打开时的文件版本保存；先确认变更范围，无变化不发写请求。版本冲突会保留本地修改，可复制、查看当前文件或重新载入后合并。切换书/节点、重新载入或关闭编辑器时，未保存修改提供“保存后继续 / 放弃修改 / 取消”。从工作台“去补大纲”进入时会自动定位章节总表，保存成功后可返回原章；失败不跳转。

**书级配置（config.json）面板**（档案编辑页底部，管实际生效的参数）：

| 配置 | 说明 |
|------|------|
| 模型五档 | 规划 / 正文 / 润色 / 审校 / 长文通读，每档先选**接口**再选该接口的**模型**（拉不到清单可手填）；不同档位可以走不同中转站，配置文件里记作 `接口名@模型名`；每档下方显示**生效模型与来源**（书级 / 全局档位 / 兜底 / 代码默认）。留空 = 未配置，向下一层下探（规格12）。界面上只显示中文档位名，配置文件里仍是 plan/prose/polish/review/longctx |
| 单章字数区间 | **实际生效的就是这里**（M-01 机检按它判越界；meta.md 里的同名字段没有代码读取，改了不生效） |
| 审校修复最大轮次 | 默认 2 |
| 逐场景生成 scene_mode | 开启后按细纲场景逐个生成再缝合（每场景独立注意力+字数配额） |
| 禁词白名单 lint_whitelist | 每行一词；目标文风招牌词与通用禁词冲突时豁免 M-02（不豁免敏感词） |

### 3.4 章节工作台（高级精修页）

顶栏：**← 书总览**、可搜索章节选择器、按实际章号集合跳转的上一章/下一章、中文状态徽标、当前版本、本章累计成本、黄金三章标记；**出错待恢复时出现「重试」按钮**。未规划、已有内容但大纲缺行、大纲读取失败是三种独立状态，分别提供补大纲、修复或返回入口。

**① 细纲（章合同）**

- 按钮：**生成细纲（P-G6）** / **确认细纲（锁定）** / **编辑细纲原文**（YAML+场景清单原文模式，带格式校验）。
- 表单：核心事件、pov 只读展示；stage（引入/发展/转折/高潮/收束）、情绪任务（压/小扬/爆）、钩子类型（悬念/选择/反转）三个下拉，未确认前可直接改；**伏笔操作只读展示**（JSON，要改只能进"编辑细纲原文"）；场景清单以等宽预览展示；确认锁状态明示。
- 锁定语义：确认后 `confirmed: true`，正文阶段不接受细纲变更（接口直接拒绝，提示走"改细纲重写"）。

**② 正文生成**

- **开始生成（流式）**：SSE 使用文本缓冲显示；默认跟随最新，上滚后暂停并显示“回到最新”。切章/离开只停止本页等待，后台可能继续写文件和产生费用，可从任务条回原目标确认结果；没有完成帧的断开不会显示成功。
- 场景专项下拉：**自动（卷首三章 W3 / 其余 W1）/ W2 对话专场 / W4 突破场景 / W5 高潮场景**。三者都是"整章替换提示词"语义，且都带 `〖字数区间〗` 硬约束。
- **编辑正文**：人工手改正文，带未保存修改与修订号保护；`待定稿` 状态手改后打回 `机械检查中`，`已定稿` 状态禁止普通编辑。
- 正文按小说段落显示，默认宋体/衬线、首行缩进，行号默认隐藏；缩进和行号偏好可记忆。检查命中仍按原始行号定位，显示切换不改落盘文字。

**装配预览（排查跑偏第一入口）**

点 **生成装配预览**：展开 13 槽位折叠面板，每槽显示标题 + token 估算 + 是否已截断 + 内容；顶部显示总估算/预算与落盘路径（`data/assembly_previews/<书>/NNN_vN.json`，每次生成前也会自动落一份）。**生成结果跑偏时，先来这里看哪槽被截断/哪槽内容不对**，比反复重生成省 token。截断顺序（预算紧张时从先砍到后）：前文检索 → 前情摘要 → Bible 条目；力量体系行/出场角色卡/细纲合同永不截断。

**③ 检查结果**

- 按钮：**跑机械检查（含自动修复1轮）**；**一键跑完本章**（自动编排，上限 3 轮，遇人工关/出错停并提示）。
- 报告统一分“阻断项 / 提醒项 / 参考项”；M-12 与 D 系列仅作文风参考，默认收起且不阻断、不触发自动改稿。未生效与过期检查单独醒目提示，不能算作“无问题”。
- 规则、阶段和有效级别显示中文，保留原编号供排障；点击有效命中按原始行号滚动到对应段并高亮，无法唯一定位时明确提示。
- **透明文风计量（规格09）**：在原检查区查看段落平均长度、段数、中位数/P90和不超过10字的短段占比；空行分段，段内换行不拆段，长度统一按去空白可见字符计算。显式比喻线索按全文（含对白）每千可见字符计数，最长词条优先、重叠只计一次，排除图像/头像类；不等于语义比喻数，暗喻可能漏计，普通比较也可能命中。旧结果未提供统计时显示“未提供”，空文密度无法计算，词表不可用显示原因，不当作0或质量合格。两项只供回读，不扣分、不阻断、不触发改稿，也不进入模型输入。

**④ LLM 审校（P-V1 五维）**

- 按钮：**跑审校**。报告：verdict 徽标 + 五维进度条 + 问题列表（类别/severity/原文引用/位置/描述/建议），blocking 红边；location 里抽得到行号的问题也可点击跳转。
- **程序守门**：任一维 <70 或存在 blocking → 强制 fix（模型自报 pass 也没用，这是红线）；全维 ≥90 且零问题会触发一次防橡皮章复审。fix 循环最多 2 轮（书级配置可调），耗尽转 human_review。

**⑤ 人工关口 / 定稿**

| 按钮 | 行为 |
|------|------|
| 定向修复（P-V5） | 用最近一轮机检/审校问题清单做定向修复；**未涉及句段改动率 >10% 的输出会被整体丢弃**（越权护栏），转人工走完整重生成 |
| 整章润色（P-V2+V3） | 去 AI 味两段式（润色 + 自检复核）；不改剧情人设，字数浮动 >10% 或机检阻断会自动丢弃 |
| 豁免（必填理由） | 理由写入 generation_log 作为合规证据；空理由提交不了 |
| 改细纲重写 | 回到 outline_draft 改细纲（正文保留，改完需重新确认+生成）；**仅 human_review 状态可达** |
| 定稿（二次确认→快照+回写） | 两次确认弹窗；写快照、status=final、触发记忆卡回写（角色状态/伏笔/新地点/摘要/FTS 索引自动沉淀）；卷末章定稿后自动触发 V6 审计 |
| 从版本重写 | 选快照版本开新分支（human_review/finalized 可用；不传版本则沿用当前正文，**绝不写空**） |
| 查看该版本正文 | 只读回看任意快照（不触发重写） |

### 3.5 裁决队列

顶栏"裁决队列"带未处理数角标（15 秒轮询）。列表只显示待处理项，支持按书、中文冲突类型筛选和分组计数，详情默认收起。每条显示原值、候选值、目标文件/字段和动作后果。

| 动作 | 含义 |
|------|------|
| 采纳 AI | 仅对候选完整且能真实写回的条目开放；写入并核对成功后才关闭待处理项 |
| 保留档案 / 人工确认 | 明确不采用候选；仅说明或未知类型只能单条人工确认，不虚构自动修复 |
| 手改采纳 | 按类型使用结构化表单：术语、时间线、缺档角色和角色状态；布尔/列表保持真实类型，不再手填 JSON |

批量操作只允许同书、当前筛选可见且支持该动作的条目，沿用单条接口顺序执行。二次确认说明可能部分成功；明确失败可继续独立项，网络中断、书占用或结果未知会停止后续项。结果分为已成功、明确失败、结果待确认、未执行，重试不重复已成功写回。

**为什么非空时不能开新章**：队列意味着档案与生成结果已分叉，此时再开下一章会传播错误。这是后端硬拦截，处理完队列才能继续。

### 3.6 设置

| 面板 | 内容 |
|------|------|
| API 连接 | key（留空=保持原 key）/ base_url（到 /v1 止）/ 兜底模型 / 全局五档模型；**保存连接** + **测试连接**（显示 OK/失败 + 模型 + 回复或错误） |
| 单价（分/百万 token） | JSON 文本域。**成本显示 0 的根因通常在这里**：模型名不在表里就按 0 计（首次调用会在控制台记告警日志）。默认表只含 deepseek-chat/reasoner 与 gemini-2.5-pro/flash |
| 机械检查阈值（M-05~M-11） | 9 项数字表单（单句逗号/感叹号密度/省略号密度/平句窗口/平句阈值/单段字数/段首重复/结尾窗口/第一人称占比），保存后下一轮机检生效；另显示装配预算 token |
| lint 词库 | 三套下拉切换后自动载入；切换/重新载入带未保存保护，保存固定当前已加载词库与版本。缺文件、加载失败和版本冲突均有独立提示，旧草稿可复制 |
| 系统维护 | **从文件重建 SQLite 索引** 前确认实际范围：不改书稿，保留现有运行历史，但不能恢复已丢失历史；成功显示书数、章节数、全文索引结果、停用书名和请求耗时；已知写任务中禁用 |

### 3.7 导出

选书后三个按钮：**导出定稿合并 txt** / **导出定稿合并 md**（`## 第N章` 二级标题）/ **全书打包 zip**（整个 `books/书名/` 目录）。txt/md 只含 `status=final` 的定稿章节；中文书名与内容实测无乱码（POST blob 下载）。

### 3.8 任务条与错误恢复

长调用在任务条显示书/章、操作名、耗时与当前已知结果，不显示虚构百分比。**停止等待**只中止本页等待，不保证服务端停止，后台可能继续写文件并产生费用；任务进入“结果待确认”，应回原目标点“确认结果”，不要直接重发。纯返回体的 AI 档案候选断开后可能无法取回，界面会明确说明。

错误通知不自动消失，可复制、手动关闭，并进入本次会话错误记录（最多 20 条，刷新清空）。版本冲突保留修改；书占用应等待并确认；大纲缺行/损坏可直达档案修复；写操作断网或超时先按结果未知处理，不自动重试。后台轮询同因错误聚合计数，不持续堆叠通知。

## 4. 常见问题排查

| 症状 | 原因 | 怎么办 |
|------|------|--------|
| 生成报 401 / 全部调用失败 | key 无效或 base_url 不对 | 设置页 → **测试连接**。确认 base_url 到 `/v1` 为止、不带 `/chat/completions`；key 输入框留空=保持原 key，确认没被清空 |
| 生成中途断网/超时，状态变 error | LLM 异常已落 error（不再卡死） | 顶栏点 **重试（恢复到 X）**：恢复到出错前状态，正文与快照不动。流式生成期间每约 400 字会把半成品落盘到 `books/<书名>/chapters/00N_正文.draft.md`，崩了也能从那里捞回已生成部分 |
| 提示"裁决队列非空（N 条待处理），禁止开新章细纲" | 有冲突未裁决 | 顶栏进裁决队列，逐条 采纳AI/保留档案/手改采纳，清到 0 |
| 提示"OUTLINE.md 章节总表缺第 N 章行，先补全书大纲" | 新书总表是空表 | 档案编辑页用 **G5 全书大纲** 生成并采纳，或在 章节总表 里手动加该章行 |
| 成本显示 0.00 元 | 该模型名不在单价表 | 设置页「单价」补上（JSON：`{"模型名": {"input_per_mtok_cents": x, "output_per_mtok_cents": y}}`）；注意 >1 元标黄也依赖它 |
| 生成跑偏/内容不对 | 上下文装配问题 | 工作台 **生成装配预览**：看 13 槽哪槽被截断、哪槽内容意外；重点查 前文检索（FTS 召回）/前情摘要/角色卡。落盘的预览 JSON 在 `data/assembly_previews/<书>/` |
| V5 越权护栏触发（修复被丢弃，转人工） | 定向修复改动超过了问题涉及范围（未涉及句段改动率 >10%） | 这是有意设计，防止 AI 借修复之名重写全文。改用 **编辑正文** 手改，或 **改细纲重写** 走完整重生成 |
| 定稿后想改正文 | 正文/快照/导出一致性保护 | 当前版本**没有解锁按钮**（已知遗留）：用 **从版本重写** 开新版本分支返工（旧快照保留）；「编辑正文」在 finalized 下被禁用 |
| 豁免提交不了 | 理由为空 | 豁免理由必填（会入 generation_log） |
| 润色被丢弃 | 字数浮动 >10% 或机检阻断 | 有意设计（润色不许改剧情人设）；看丢弃原因提示，改用定向修复或手改 |
| 改 meta 里的"单章字数区间"不生效 | 实际生效的是 `config.json` 的那份 | 去档案编辑页底部 **书级配置** 面板改（已知不一致，见交付报告 §8） |
| exe 打不开界面 | 打包产物是旧的（缺 web/dist） | 用 `python run.py` 运行；或重新打包（见 README 打包段：`pyinstaller ainovel.spec` 后把 `prompts/ lint/ web/dist` 拷到 `dist/ai-novel/` 下） |

## 5. 红线与人工确认点（不是可优化项）

来自 `AGENTS.md` 架构核心第 3 条与规格03，全部由程序强制：

1. **细纲确认关**：确认即锁定（`confirmed: true`），正文阶段不接受细纲变更；改细纲只能走"改细纲重写"回退。
2. **章节定稿关**：二次确认 → 快照 + status:final；定稿后正文/快照/导出三方一致，`/fix` 无法再静默改写已定稿章。
3. **M-04 敏感词命中 = 阻断 + 禁止自动改写**：不走 V5 自动修复，直接转人工，必须人审。
4. **V5 越权护栏**：未涉及问题句段改动率 >10% 的输出整体丢弃，转人工完整重生成；不许放宽。
5. **裁决队列非空禁止开下一章细纲**：硬拦截，先处理冲突再继续。
6. **所有 LLM 调用记 generation_log**（prompt_digest / tokens / cost），豁免必填理由入 log——这是"每次生成可从 log 复现"的根基，也是合规证据链。

## 文风候选的人工选用（规格09）

仓库 `style/候选范例/README.md`列出六组、每组两个完整片段和特征卡草案；`sources.json`记录语料段落范围与指纹。它们是待作者认可的本地候选，运行时不会自动扫描全局目录。

1. 同一本书先选择一种方向，不把不同作者或题材混注入。只参考表达与场景推进，不搬原文人物、剧情或专有设定。
2. 在书级文风资料页粘贴所选TXT并保存为语料。保存会使基于旧语料的范例索引过期；若已有人工作品资料，先保留备份和比较，不自动覆盖。
3. 按候选README里的两组范围选完整片段并保存范例。例如restrained选择语料段1–6和7–11，而不是任意选两个孤立自然段。每个范围含general标签，可补适用场景标签。
4. 通读该组“观察/适用/例外”草案，按本书需要编辑后人工保存正式特征卡，再独立打开文风开关。没有正式卡或关闭开关不会注入；生成F1草案也不等于保存/启用。
5. 在实际装配预览检查system/user、有效文风开关、所选范例ID/指纹/全文与预算。每次最多两个完整片段，总计1200可见字符；超预算舍弃完整范例，不能截半句。

计量词表在 `lint/simile_cues.txt`、`lint/simile_exclusions.txt`，一行一个字面词条（1—64个无空白可见字符），空行和`#`注释忽略。词表坏/缺失只让线索统计不可用，不改变旧检查分数与门禁。不要用这些统计给W1增加写作配额。

本批验证的是离线工程链路；真实书正式应用和同章真模型对比仍另行授权。对比须冻结细纲、正式卡、开关、模型与采样参数，只改变范例块，最后由作者决定是否采用。
