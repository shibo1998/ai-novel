# 生成文风诊断与改进方案

调研日期：2026-10-27。基线代码：`253c62e`。

## 结论

现有正文的主要问题，是反复使用同一种叙事节拍：短句切镜头、身体反应加压、解释刚发生的事、再用更大的危机收尾。常见套话已经很少，继续扩充禁词表难以解决这类读感问题。

项目已经有范文、文风卡和去味润色，但生成链条没有一致消费这些信息；部分提示词反而把“人味”规定成固定配额，润色要求又互相牵制。建议先精简和统一这些约束，做有原文依据的局部编辑，再考虑采样和模型选型。

这是一份诊断与待验证方案。本轮没有修改提示词、代码、真实书稿、书级配置或运行数据库，没有真实模型调用。下文区分已核实的行为、读感判断与需要实验验证的因果推断。

## 1. 样本与方法

- 样本为本地 `books/流程测试书/chapters/001_正文.md` 至 `013_正文.md`，共13章；正文定稿时间为2026-10-25至2026-10-27，属于本次调研前已生成的内容。
- 重点阅读第1、12、13章正文与第13章细纲，读取本书 meta、文风卡及文风开关；其余章节的词频、段落和章尾来自全量只读统计。
- 追踪正文、文风、润色与复核的提示装配链，核对已有规格和有意偏差。使用 story-deslop 的只读规则扫描辅助定位，再回到上下文判断。
- 联网核对出版记录、作者论文摘要与官方提示文档。研究只提供方法依据，不替代本书实验。
- 所有统计脚本、规则结果、原始来源文本和正文校验值放在会话 scratch，未加入仓库或运行数据。

## 2. 正文里实际出现的问题

### 2.1 一个动作拆成连续提示语

第12章183—191行：

> 脚下的花岗岩地面开始颤抖。
>
> 不。
>
> 不是颤抖。
>
> 是咆哮。

偶尔这样写可以压强；在持续高压、频繁短段的章节里反复使用，就像逐格提醒读者“这里很震撼”。同章153—161行又用“痛”、详细痛感、“经脉要爆了”多次强化同一状态。

改进方向是只保留有必要的一次强调，将其余信息放回动作和后果。短句仍可留在真正的转折处。

### 2.2 已经呈现的结果，又由旁白替读者总结

第1章132—134行，三名打手已经倒下后，又连续说明“这不是一个普通的外卖骑手”“这是懂得运转灵气的修士”“绝对的降维打击”。156—166行再次用势力名、背景解释、否定判断、概括结论递进。

第13章96行“太昊把整个山头封死了”，116行又概括“地面全封死了”；148—166行连续解释盲区、生路、代价，再用两行判断句强调同一选择。

必要设定和因果应保留；重复结论不必换一种说法再讲。编辑时先问“读者在前文是否已经知道”，而不是简单搜索某个词。

### 2.3 整章持续满格，人物承压方式越来越像

第12、13章频繁使用皮肉、指骨、黑血、焦臭、经脉、死死、狠狠等强度表达。检修、观察、移动与搏命都使用相近的语言强度，轻重差别变小。

但身体代价是本书明确设定：meta第55—64行规定底层账本感、手段越阶、玄铁令反冲。正确改法是让伤势影响握工具、移动和决策，避免同一伤势反复升级描写。不能为了“干净”删掉代价和后续约束。

本书也有值得保留的细节：修稳压管、利用检修结构、算跑单损失、用装备寻找机会。这些具体问题和人物选择，比强行添加吐槽、粗口或微表情更能形成个人声音。

### 2.4 重复感已经进入细纲

第13章细纲20—43行已经密集规定“唯一通道”“正面硬闯必死”“闭锁倒计时”“跳车死、留下死”，58—74行又以详细叙述复述这些要求。正文很难完全摆脱这种节奏。

全量章尾抽样还看到：第7、8章都用滴水黑伞的出现收尾；第11—13章连续围绕爆破、坍塌、封路、逃生继续加压。悬念本身有功能，问题是相邻章节是否重复承担相同的悬念功能。

未来细纲应检查最近几章的任务变化、信息兑现与呼吸空间；已经人工确认的细纲不能由润色器自行改动。不能把新增日常戏、删掉危机或改写选择混进“去味”。

## 3. 生成链条中的具体成因

下列行为已从代码或配置核实；它们各自贡献多少模板感，尚未进行受控生成实验。

| 位置 | 已核实的行为 | 风险与建议 |
|---|---|---|
| 本书 `style/特征卡.md:63`、`:68`、`:74`、`:75` | 要求8—15字短句、高频生理恐慌、微段落、场景必须异常收尾 | 容易将参考片段的局部特征扩大成整本配方；改成有条件的倾向与例外 |
| `prompts/write/W1.md:41`、`:61` | 人味五件套每章至少各一次；每场截图；每300字固定节拍 | 容易打卡式塞入毛边、吐槽、打断；去掉文体配额，保留具体剧情约束 |
| `prompts/write/W1.md:17`、`:23`、`:26` | 装配上下文展开两次，章合同也重复出现 | 输入冗余且重复强调清单；上下文与合同各保留清晰的一份 |
| `ainovel/pipeline.py:375`、`:606` | 范文随机截取约600字符；默认前三章走W3，而W3不消费范文占位符 | 本书已启用文风，但前三章只有特征摘要；改用稳定、完整、适用的示例 |
| `prompts/system/S1.md:14` 与 `prompts/write/W3.md:30` | 一处允许情绪直给，一处禁止情绪名词、要求生理反应 | 可能把内心一再替换成身体动作；统一为“有上下文支撑的直写可用” |
| `prompts/system/S1.md:23`、`ainovel/assembler.py:327` | 提示层把词库写成全禁，实际检查区分L1/L2和白名单 | 写作目标与检查口径不一致；区分不可违反的规则和需要语境判断的建议 |
| `prompts/review/V2.md:24`、`:58`、`:60` | 一边要求删/合，一边要求段落数原样、字数接近原稿 | 难以修复碎段与重复解释，容易退成同义替换；先消除提示内冲突 |
| `prompts/review/V2.md:31`、`:34`、`:41` | 把冷静分析示范成没想就冲，固定替换成瞳仁、眼睫等反应 | 可能改变人物决策，或制造另一套动作模板；改为保留决策原因的语境例子 |
| `ainovel/pipeline.py:1533` | V3仅接收新稿、模型自报改动清单、禁词，没有原稿 | 无法充分核对“剧情不变”；同时传原稿、候选和必要合同信息 |
| `prompts/review/V1.md:53` | 要求至少找3条问题，找不满等同放水 | 可能诱导凑问题；允许零问题，要求每项问题提供原句和实质影响 |
| `ainovel/pipeline.py:60`、`ainovel/prompts.py:46` | system为空；包含元数据的模板全文进入user | 需要明确角色、指令、素材、示例边界；这是装配一致性问题，不能单独视为AI味根因 |

本书实际 `style_enabled=true`，语料为5,232字符，特征卡存在。因此不能把问题归结为“没开启文风”。

V2整章润色需要在工作台主动触发，正常生成不是自动经过V2。即便触发，当前通过条件主要是字数、完整机检、部分字面保真以及V3明确通过；这些不等于“比原文更好读”。

现有±10%字数、句末数量、四元字串和敏感词人工关有保护作用。第一步应解决提示矛盾、补全复核证据，不能为了大改读感直接放宽安全边界。更大规模重写应作为需要人工审阅的独立候选流程设计。

## 4. 外部调研能提供什么

### 4.1 写得顺与作品有个性，需要分别验收

Doshi与Hauser的短篇创作辅助实验发现：提供AI创意可以提高个体作品评价，同时让不同作品更加相似。[R1]

对本项目的启发是：规则通过、措辞顺滑、审校分数高，不能代替人物声音、叙述态度与章节差异的检查。这是方法迁移，不是对中文长篇或当前模型的直接因果证明。

### 4.2 用具体、相关、多样的示例引导写法

Anthropic官方提示文档建议明确表达期望行为，使用贴近用途且足够多样的示例，并区分指令、素材和示例。[R2]

可借鉴为：少写“每章必须有人味”，多给出经作者确认的对话、动作、判断、过渡片段，说明该片段为何有效。示例库可以多样，每次只选当前场景适用的一小部分；不能把同一个惊悚片段的特征扩成全书强制写法。对项目实际使用的兼容模型仍需实测。

### 4.3 模型自评需要人工校准

关于模型自我偏好的研究显示，部分受测模型会更偏好自己的输出；实验也考察了自我识别与这种偏好的联系。[R3]

这支持采用匿名、交换顺序的新旧文本对照，允许人工判定原文更好或两者持平。不能据此断言本项目已经发生同样偏差，也不能认为更换一个审稿模型就自然消除了偏差。

## 5. 建议实施顺序

### 第一阶段：先调整提示与文风资料

1. 使用已有书级覆盖机制做小范围试验；保留既有提示词文件名与ID，正式修改时递增version，记录每次输入版本。
2. 去掉“五件套各一次”“固定字数插转折”“每场截图”等文体配额；保留细纲事件、人物选择、视角、信息边界与本章真实字数区间。
3. 将文风卡整理为“观察—适用条件—例外”。短句用于转折和急迫动作，完整句用于检修、观察和判断；生理反应只在产生新后果时出现。
4. F1提取时允许“样本不足，不能确定”，不必每维凑三条；由人工确认跨场景仍适用的特征。
5. 删去V2的固定同义替换和“段落数不变”；在现有保真范围内允许合段、拆段，不让润色器改变理性/冲动等人物决策。
6. 统一S1、W3、V1对情绪直写、词库级别、功能性标点的口径。

可用于试验的简短文风说明，不应直接覆盖当前作者配置：

> 以林寒能感知的线索推进场景，写清他要做什么、哪里受阻、因此怎样选择。已经交代的伤势，后文只写新增影响；有依据的心理判断可以直说。追逐和交手处可以压短，检修和观察用能连起来读的完整句。重要转折保留停顿，普通动作不逐行加重。保持已确认事件、代价和悬念，不额外制造更大的危机。

### 第二阶段：修整现有装配和复核链

- W1上下文去重，模板运行元数据与正文指令分离，明确system/user职责；预算核算覆盖真正发送的全部内容。
- 从人工确认的完整片段中稳定选例，记录所用片段指纹。W3及其他专项都能收到适用的真实范文；不要只有常规章有、前三章没有。
- 先建立少量不同用途的示例，按当前场景选择1—2段；不一次塞入大量原文，也不复制示例中的人物、设定和情节。
- V3同时接收原稿、候选与必要章合同；检查人物决策、事实、数字、动作结果、信息揭露、伏笔和关系是否改变，并引用双方原句。
- 问题清单允许为空；只为有证据的问题提出定点编辑。保留原稿、展示差异，候选变差时允许直接不采纳。
- W6长度处理沿用文风与事实边界，核查截断结果，避免补字、压缩阶段又把口气磨平。

预期成本：去重可减少输入；补范例和V3原文对照会增加部分输入。V3补原稿本身不需要新增一次模型调用。是否增加局部编辑轮次，应由实际改进效果决定。

### 第三阶段：用小规模对照决定参数与后续方案

先选战斗、对白、检修/判断、过渡等不同用途的冻结片段，比较基线与精简版提示。保持事件、上下文、模型和采样设置相同，每组保留重复生成样本，避免只挑最好的一次。

小片段通过后，再用完整章节验证连贯性和章尾。最后才在当前采样温度附近做单变量比较；本轮没有证据表明单纯升温、换更贵模型或增加自动润色轮数能够解决问题。

目前不建议直接启动微调、引入新的运行时依赖、对整本旧稿自动重写，或将V2接成无条件必经步骤。这些都应建立在前两阶段的对照证据上。

## 6. 两个短片段的改法示意

以下是针对现有句子的编辑示意，没有写回书稿，也没有新增剧情。它们只说明编辑方向，不代表整章已完成去味。

### 6.1 合并同一动作的重复强调

原文：第12章183—191行。

> 脚下的花岗岩地面开始颤抖。不。不是颤抖。是咆哮。被九号灵井强行镇压了数十年的古灵脉地煞，在这一刻找到了缺口。

示意：

> 脚下的花岗岩地面开始颤抖。九号灵井压了数十年的古灵脉地煞，在地底咆哮着找到了缺口。

保留地面变化、力量来源和突破封锁，把否定、改口、再加重合回连续叙述。高潮仍然可以保留别处的一处停顿。

### 6.2 让代价贴着选择，不反复喊绝境

原文：第13章162—166行。

> 那是唯一的生路。也是把活人烤熟的地方。钻进夹层，肉身要硬顶着未稀释的地煞冲刷。感气境初入的经脉根本扛不住这种烈度，稍有不慎，皮肉都会被活活烫烂。

示意：

> 车底的夹层能进山，可里面积着没稀释的地煞。他只有感气境初入，钻进去，经脉未必撑得住，皮肉还可能被烫烂。别的路已经封死了。

保留进入夹层的目的、反冲与灼伤代价；最后一句承接本章96、116行已经确认的封路事实。示意没有改变他的选择，也没有用随机吐槽来填补删掉的形容。

## 7. 验收办法

### 内容与读感分开验收

| 维度 | 核对方式 |
|---|---|
| 剧情保真 | 事件、因果、人物决策、数字、信息揭露、伏笔逐项对照；不能靠字串覆盖代替 |
| 人物声音 | 隐去姓名后，是否仍能从措辞、关注点、回避方式看出人物差异 |
| 叙述节奏 | 急迫、判断、过渡的句段是否有差别；短句是否集中在真正需要停顿处 |
| 信息效率 | 同一事实是否反复用动作、心理、旁白总结三遍 |
| 叙述态度 | 是否来自人物处境与本书视角，而不是模板吐槽、微动作和粗口 |
| 连续章节变化 | 相邻章是否重复使用同一破局方式、同一悬念功能与同一高压曲线 |

人工匿名对照应允许“原文更好”“改稿更好”“持平”；模型可辅助找问题，但不能替作者决定全部审美偏好。试验先约定采用标准与不可接受的退化，不以词频下降或检测分数上涨作为唯一上线条件。

### 实施后的工程回归

下列是计划中的检查，本轮未实施这些改动，也未重新运行完整测试：

- W1上下文不会重复；运行元数据不会成为正文指令。
- 生成、专项写作、长度处理、润色、审校都遵守文风开关与一致的有效规则。
- 范文完整、选择可复现，预览能够解释实际发送了哪些内容。
- V3确实拿到新旧稿和必要事实；无法确认语义保真时保留原文。
- 敏感词人工处理、人工确认、修订冲突、机检有效性和失败回滚保持原约束。
- 代码实施后执行pytest与smoke；如涉及前端，再执行lint:check、typecheck、build。
