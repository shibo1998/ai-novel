## 3. 前端与有界复核

最终 `npm run test:offline` **66 passed、0 failed/cancelled/skipped/todo**；`npm run lint:check`、`npm run typecheck`、`npm run build`均通过。未手改`web/dist`，由Vite构建并同步到隔离实例。

一次只读有界复核发现四项具体问题，已修复并回归：

1. 新端点只调用一次_call，但兼容客户端会内部重试：新增本入口`retry=False`，不改普通调用默认值。
2. SSE默认stop会把提前EOF当完整：严格模式要求实际finish_reason及`[DONE]`，无结束帧拒绝。
3. Markdown解析跳过分隔行会漏掉第一条章行：context显式校验表头、分隔行语法与列数，坏表503且零模型调用。
4. 组件卸载残留局部blocking：卸载清局部状态，全局running/unknown继续由任务表派生，结束后解除，晚到确认不填表。

实际浏览器又发现`withTask`创建原始对象后在完成时直接改原始对象，响应式任务表不一定收到变更，造成请求成功但prepare仍阻断。新增真实withTask/VolumeView回归先复现`true !== false`，只把任务对象创建改为`reactive<TaskRecord>`后66项全过；在实际顶层浏览器原路径复验，显式确认重试只增1条日志、返回3卡并立即解除prepare阻断。没有发起第二轮广泛审查。

现存非阻塞警告：Starlette TestClient/httpx弃用、archiveAI.ts静态/动态混合导入构建提示，未扩范围整改。
