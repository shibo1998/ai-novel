## 1.1 追加（同日 23:55）：选题报错的根因与修复

**用户报障**：点"AI 给我 3 个故事方案"报 `选题请求未完成；模型可能仍有费用，未自动重试，请核对后再决定`。

**根因（两个，叠加）**：

1. **配置指向中转站不存在的模型**。`generation_log` 显示失败两次都用 `deepseek-chat`（`model_source=book`），而成功两次是改优先级之前的 `gemini-3.8-flash-high`。查中转站 `/v1/models` 共 24 个模型，**没有 `deepseek-chat`，也没有 `gemini-2.5-pro`**；实测 `deepseek-chat` 返回 `HTTP 503 model_not_found`，同参数换 `deepseek-v4.1-flash-1017` 返回 200。两本书的 10 个档位**全部**指向不存在的模型——改前一直被 `default_model` 覆盖，所以从未暴露；规格12 让书级配置真正生效后，问题才浮出来。
2. **代码把可诊断信息吞了**（真 bug）。`storyideas.py` 的 `except Exception` 把任何异常压成同一句通用话，`pipeline._call` 又把日志写成 `type(error).__name__`（只有 `LLMError`）。结果"模型不存在"和"网络超时"在界面和日志里长得一模一样，用户无从判断。

**修复**：

| 改动 | 内容 |
|---|---|
| `llm.error_brief()` | 新增：只提取 HTTP 状态码 + 白名单错误码（`model_not_found` 等），不透传响应体原文（响应体可能回显凭据），非 HTTP 异常退回类型名 |
| `pipeline._call` | 日志 error 改为 `请求未完成：HTTP 503 / model_not_found`，不再是光秃秃的 `LLMError` |
| `storyideas._model_failure_message()` | 报错点名模型：`中转站没有模型「deepseek-chat」（HTTP 503 / model_not_found）。请到设置页或档案页换成中转站支持的模型；本次未自动重试，可能仍产生费用` |
| `ModelSelect.vue` | 当前值不在中转站清单里时显示红字提示「注意：中转站清单里没有这个模型，调用会失败」，不阻断（清单可能不全） |

**数据修复（经用户确认）**：两本书五档改为 `plan`/`review` = `deepseek-v4.1-flash-1017`，`prose`/`polish`/`longctx` = `gemini-3.8-flash-high`；原文件已备份为 `config.json.bak`。两个模型均通过 `require_complete=True` 的严格流式校验（`finish=stop, complete=True`）。

**遗留**：`deepseek-v4.1-flash-1017` 未在单价表里，成本会按 0 计并记告警日志，需在设置页补单价。新增回归用例 `test_error_brief_keeps_diagnostics_without_leaking_body`、`test_story_ideas_failure_names_the_model`。

**有没有做规格之外的事？** 只有一处：`/api/settings/test` 的默认模型从"`default_model` 或 deepseek-chat"改成走 `models.resolve(None, "plan")`。属 §3 接口表的既定改动，不是新增范围。多端点、提示词级覆盖、自动故障转移、模型能力探测**均未做**。
