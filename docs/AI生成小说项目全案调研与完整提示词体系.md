# AI生成小说项目全案调研与完整提示词体系

> 调研日期：2026\-10\-24 ｜ 适用对象：零基础网文创作新手（前端开发背景）｜ 目标平台：番茄小说 ｜ 题材方向：都市 / 仙侠 / 系统流
> 证据分级：【共识】= 多来源交叉印证或平台官方/工程文档；【单方】= 个人实测或单一来源，需自行复现；【官方】= 番茄官方教程/平台公告
> 核心结论先行：**AI 写小说不是"一句话生成一本书"，而是「规划 → 写作 → 审查 → 记忆回写」的人机协同流水线**。大纲与设定 AI 擅长，正文 AI 最弱、最容易出 AI 味，一致性必须靠外部档案系统兜底，不能靠模型记忆。

### 1\.2 完整功能模块清单（按创作链路排序，★=长篇必备）

**A\. 选题与创意**

1. ★ 选题灵感雷达：结合平台榜单/热搜标签做题材重组与热度判断

2. ★ 一句话简介 / 书名生成：把核心冲突、金手指、卖点压缩成简介与候选书名

3. ☆ 对标拆解（拆书）引擎：提炼爆款结构、爽点节奏、人设公式（学习不复制）

**B\. 设定与世界观**
4\. ★ 世界观设定编辑器：时代/社会阶层/规则/地理/历史年表，结构化存储
5\. ★ 力量/等级体系编辑器：境界、异能等级、系统面板规则，数值边界锁死
6\. ★ 角色卡管理库：外貌/性格/前史/口头禅/关系网/成长弧线/当前状态
7\. ★ Lorebook 设定词条库：按关键词或语义自动激活注入
8\. ☆ 素材/名词库：功法名、地名、道具名库与命名规则

**C\. 规划阶段**
9\. ★ 全局大纲生成：三幕式/分卷结构、主线支线、转折点、高潮分布
10\. ★ 分卷大纲：每卷核心目标、中高潮与卷终高潮位置
11\. ★ 章节细纲（Beat Sheet）：每章核心事件/出场人物/情绪目标/伏笔/章末钩子
12\. ☆ 爽点节奏总谱：1–2 章小打脸、3–5 章中打脸、8–12 章大高潮、15–20 章卷终决战

**D\. 写作阶段**
13\. ★ 骨架（Beat Draft）生成：先出"谁\+在哪\+做什么\+说什么"的粗糙骨架再扩写
14\. ★ 章节正文生成：按细纲\+设定 Bible 生成 2200–2800 字正文
15\. ★ 对话生成与角色语言指纹：区分各角色说话风格，避免全员同腔
16\. ★ 章节续写/分支选择：多条走向供挑选，支持平行剧情与回滚
17\. ☆ 风格模仿/文风迁移：学习上传片段节奏用词，越写越接近个人风格

**E\. 记忆与一致性（长篇成败关键）**
18\. ★ 上下文/记忆管理：章节滑动摘要 \+ 全局大纲 \+ 相关设定召回（RAG 或台账式）
19\. ★ 事实/伏笔/人物/地点四本台账：结构化沉淀已确立设定
20\. ★ 设定一致性校验器：穿帮检测（外貌/能力/关系/时间线/地点）
21\. ☆ 前情摘要自动压缩：每章生成后由轻量模型压缩为摘要入库
22\. ☆ 周期性一致性审校 Agent：每 10–15 章通读审计

**F\. 质量与合规**
23\. ★ 去 AI 味润色引擎：生成时内置约束 \+ 事后确定性后处理
24\. ★ AI 味量化体检：句长方差/排比密度/连接词密度等指标打分
25\. ★ 人工审阅工作流：草稿/待重写/已审/定稿状态机，保留多版修改痕迹
26\. ★ 合规与敏感词过滤：红线预扫、侵权雷同度提示
27\. ☆ 平台规则适配检查：开篇结构、单章字数、AI 标注要求

**G\. 交付与运营**
28\. ★ 多格式导出：TXT/Markdown/Word/PDF，手机阅读排版
29\. ☆ 封面/插图生成
30\. ★ 多模型接入层：Claude/DeepSeek/Kimi/GLM/本地 Ollama 可切换
31\. ☆ 数据复盘看板：收藏率、追读率、完读率映射回大纲迭代
32\. ☆ 断点续写：跨章节中断后按固定顺序恢复上下文

## 第二部分 · 创作流水线设计（从选题到发布）

### 2\.1 十阶段流水线（5 套以上公开方案交叉验证的共识主干）

|阶段|目标|输入|输出|
|---|---|---|---|
|P0 立项与合规|定产出模式、题材、合规边界|作者偏好、目标平台、预算|项目 meta\.md（书名占位/标签/字数计划/合规声明）|
|P1 选题与市场验证|选"有需求未饱和"的题材组合|平台榜单、热门标签、擅长领域|题材定位卡（题材/核心梗/爽感/金手指/对标作品）|
|P2 故事核/简介/书名|固化可卖座的故事核|题材定位卡 \+ 脑洞关键词|一句话故事核、200 字简介、候选书名|
|P3 世界观 \+ 设定 Bible|锁死所有硬设定，形成单一真相源|故事核、题材套路|STORY\_BIBLE/CHARACTERS/LOCATIONS/PLOT\_POINTS 档案|
|P4 全局大纲 \+ 分卷规划|固化故事骨架与节奏曲线|设定 Bible、字数计划|全局大纲 \+ 分卷规划表 \+ 爽点节奏总谱|
|P5 章节细纲（Beat）|拆成场景级指令|卷规划、Bible、上章钩子|单章细纲卡片（场景/冲突/钩子/伏笔/字数）|
|P6 章节正文|产出本章正文（骨架→草稿→成稿）|大纲\+近 3 章摘要\+相关设定\+细纲|草稿或成稿 \+ 本章摘要 \+ 新设定回写|
|P7 一致性审查|抓穿帮、漏洞、重复|正文 \+ Bible \+ 台账|审查记录 \+ 问题清单|
|P8 润色与去 AI 味|统一文风、压低 AI 检测率|审查通过的章节|定稿 \+ AI 味体检指数|
|P9 合规质检与导出|过红线、按平台格式交付|定稿章节集|投稿包 \+ 合规自查记录|
|P10 连载运营与复盘|用数据反哺大纲|平台后台数据|下一卷规划修订|

### 2\.2 一次性长文生成 vs 多轮对话式分步创作

|维度|一键长文生成|分步人机协作（推荐长篇）|
|---|---|---|
|机制|一次指令输出大纲到正文|每阶段人审，逐步推进|
|优点|快、门槛低，适合短篇/样章|人保留创作主导权、设定可控、合规风险低|
|缺点|几十万字后人物/设定遗忘、AI 味重、无法举证人类主导|耗时、需要搭台账/记忆工程|
|适用|1–2 万字短篇、灵感初稿|番茄连载长篇、追求低 AI 检测率与合规安全|

**长篇不失根的五个通用解法**：① 设定文档持续注入；② RAG/向量记忆库召回相关设定；③ 前情滑动摘要窗口；④ 顺序写作不跳章；⑤ 每 10–15 章长上下文一致性审计。

### 2\.3 番茄平台生态与 AI 合规要点

**题材热度（番茄官方 2026\-03 风向）**：男频高热分类——都市种田、都市日常、都市脑洞、传统玄幻、都市官场、战神赘婿、历史架空；高热核心梗——穿越、小人物逆袭、重生打脸、高光人设、系统、赘婿、扮猪吃虎、身份反差。【官方】

**黄金三章（官方课程）**：第 1 章抛核心冲突（如穿越即被追杀）；第 2 章展现金手指（危机中觉醒系统）；第 3 章明确短期目标。单章约 2000–2800 字，剧情紧凑、章末留钩子，杜绝大段环境描写。【官方】

**AI 政策（官方公告）**：番茄禁止"AI 粗制滥造、格式混乱、空洞水文、机械扩写注水、剧情逻辑混乱"；2026\-02 专项整治打击滥用 AI 批量创作（拒签→限流→下架→封禁）；2026\-08 报道 7 月从签约源头拒绝 AI 低质书约 16 万本。行业侧：2025\-05 阅文、番茄、晋江、七猫等 16 家发布《网络文学行业反洗稿自律公约》；起点 2026 年清理 AI 痕迹过重作品；晋江仅允许"校对级\+极简粗纲"式 AI 辅助。【官方/共识】

**合规关键**：人类实质性主导 = 保留完整大纲、多版修改稿、创作日志作为证据链。国家《人工智能生成合成内容标识办法》要求生成内容添加标识。【共识】

## 第三部分 · 完整提示词体系（核心交付物）

> 组织方式：四层结构——**系统层**（AI 角色定位 \+ 全局规则 \+ 去 AI 味禁令）→ **档案层**（Bible/角色卡/体系表/伏笔台账文件结构）→ **任务层**（按流水线阶段的 12 组提示词模板）→ **审查层**（自检清单）。所有 `[占位符]` 字段名保持统一，方便后续做成配置文件。
> 模型档位建议：规划/体系设计用推理档（DeepSeek\-R1 类/Claude Opus 类）；创意发散用创意档（Claude 类）；批量正文用性价比档（DeepSeek V3/Gemini Flash 类）；精华章节与润色用文笔档（Claude Sonnet 类）；一致性审查与记忆抽取用轻量快档（Flash/Haiku 类）。

### 系统层 S0 · AI 写作系统角色定位（每次对话先挂）

```
你是一名资深网文创作协作系统，服务对象是[作者名]，目标平台是番茄小说。
你的工作原则：
1. 你是"策划 + 写手 + 编辑"三位一体的专业助手，但不是决策者——所有关键剧情、
   人物命运、爽点设计由作者拍板，你提供方案与建议。
2. 分阶段工作：作者说"选题"你只做选题，说"大纲"你只做大纲，绝不越级展开正文。
3. 每次回答都要有结构：先结论、再展开、后自检。
4. 你了解番茄男频读者心理：第一章留人、第三章定生死、章末必留钩子、爽点密集、
   单章 2200-2800 字、拒绝大段设定灌输。
5. 你了解"AI 味"的危害：行文要像真人作者，规避模板句式与机械感。
6. 涉及设定冲突、前后矛盾时，你必须主动指出而不是将错就错。
```

### 系统层 S1 · 全局写作规则（每章生成时挂载）

```
【文风与去 AI 味硬规则（每章必须遵守）】
1. Show Don't Tell：禁止"他非常愤怒/她感到温暖/气氛十分诡异"等抽象情绪标签，
   一律替换为具体感官描写或身体动作。
2. 节奏爆发度：句长必须有落差——偶尔一句 5 字以内的短句，偶尔一句 30 字以上长句；
   禁止连续 4 句以上长短接近。
3. 禁用词表（本段全禁）：微微、缓缓、忽而、陡然、骤然、淡淡、半晌、良久、不由得、
   下意识、不知为何、眼底闪过一丝、眸色沉沉、眼神复杂、唇角勾起、莞尔一笑、
   心脏猛地一缩、心跳漏了一拍、五味杂陈、骨节分明、身子一僵、呼吸一滞、
   标志着、里程碑、未来可期、综上所述。
4. 禁止"不是 X 而是 Y""不仅仅是……更是……"的排比式升华；禁止段末顿悟总结、
   禁止章末"畅想美好未来"。
5. 对话禁止"XX 地说"后缀；每人语气、句长必须符合角色卡声音特征。
6. 标点：单句逗号 ≤2；少用感叹号与省略号；段落 3–5 行。
7. 每章至少注入 1 处具体细节（人名/数字/地点/物件/味道），不要全靠概括推进。
8. 视角：主视角固定为[主角]，同章不切换他人内心；多人发言者 ≤3 人。
```

### 系统层 S2 · 题材风格适配段（按题材选一挂载）

```
【玄幻/修仙】节奏明快不拖沓；打斗用短句切换镜头（单句 ≤15 字）；突破描写要有仪式感
（身体变化+天地异象，不只是喊"突破了"）；保持古风但不用文言文；对话可有江湖气，不能有学生气。

【都市/爽文】短句多，对话推进快；打脸节奏：铺垫憋屈 → 积累期待 → 爆发反打 → 旁观者反应烘托；
侧面烘托主角，让配角替读者震惊（迪化效果）。

【悬疑/推理】克制冷静，不渲染不煽情；关键信息藏在看似无关的细节里；场景带不安感；
对话有潜台词（说 A 想 B）；真相揭露前 10% 突然加速。

【末世/废土】粗粝直接不煽情；环境写"曾有人生活过却已废弃"的细节；人物动机务实。
```

### 档案层 F1 · 设定档案结构（单一真相源，Markdown/JSON/SQLite 均可）

```
项目根/
├── meta.md                    # 书名占位、标签、字数计划、产出模式、合规声明
├── STORY_BIBLE.md             # 世界观规则、体系表、术语表（每章生成前必读相关条目）
├── CHARACTERS.md              # 角色状态表：姓名/境界/目标/信念/秘密/关系/当前位置/生死
├── LOCATIONS.md               # 已出现地点：特征/方位/距离
├── PLOT_POINTS.md             # 伏笔台账：编号/内容/埋设章/推进章/回收章/状态(planted→building→paid)
├── OUTLINE.md                 # 全书大纲 + 分卷规划 + 爽点节奏总谱
├── chapters/
│   ├── 001_细纲.md            # 单章细纲卡片
```

### 任务层 T3 · 力量体系设计（P3，仙侠/玄幻重点）

```
你是一名资深玄幻/仙侠修炼体系设计师。请基于以下设定，构建一套逻辑严密、可连载百万字、
后期不崩坏的境界体系。

【输入参数】
- 修炼理念：[如：以星辰之力为源，观想星图淬炼神魂与肉身；或道家无为 / 武道刚猛 / 魔道吞噬]
- 体系特色：[注重心境修炼 / 肉身成圣 / 法则感悟 / 灵根资质决定上限 / 数据化面板]
- 题材模式：[凡人流（写实残酷，慢节奏重积累）/ 古典仙侠（辞藻华丽）/ 无敌爽文（快节奏越级反杀）]
- 主要境界数量：[5–9 个大境界，可自行建议]
- 参考气质作品：[可选，如凡人修仙传 / 遮天 / 斗破苍穹，只借结构不抄设定]

【输出要求】
一、境界总表（用 Markdown 表格，每个大境界一行，子境界在表内标注）：
| 大境界 | 子境界 | 能量形态/术语 | 突破条件与资源门槛 | 核心能力与能力边界（明确写"不能做什么"）|
| 战力对标（可越几级、克制/被克制关系）| 寿元变化 | 突破代价/风险 | 突破异象（可写进正文的画面）| 社会地位/宗门认可 |

二、突破逻辑链：
1. 从凡人到最高境界，每一阶需要什么类型的积累（心境/资源/悟性/生死劫）？
2. 哪些瓶颈是所有修士共同的？哪些需要特殊机缘？
3. 主角的金手指在体系内处于什么位置：它解决了体系里的哪个痛点？它的限制/代价/反噬是什么？
   （必须写清：它不能无限获取什么，冷却/条件/风险分别是什么）

三、资源品级体系：
- 功法品级：[如 凡品→灵品→宝品→仙品→神品]，对应可修炼到的最高境界；
- 丹药/法器/灵植/妖兽分级规则；命名规则示例：[品级]+[前缀]+[后缀]（如 玄冰玉露丸）；
- 兼容性限制：功法等级与境界的匹配、可同时持有外物数量上限、强行突破/强行炼化的后果。

四、平衡校验（必须逐条回答，不许回避）：
1. 境界之间的实力鸿沟是否足够大，避免"同境碾压失去悬念"？
2. 主角越级反杀需要满足哪些客观条件（环境/外物/情报/对手状态）？哪些情况属于不合理开挂？
3. 体系后期如何扩展（灵界/上界/新法则），保证不提前透支上限？
4. 列出 3 个最容易导致战力崩坏的隐患，并给出预防规则。

五、配套素材示例各 1 个：
- 一件对应第 [N] 境界的防御类法器：名称/品级/材料/神通/副作用；
- 一部中阶功法：名称/品级/修炼难度/入门效果/瓶颈。

输出后请自检：术语是否前后统一（真元/法力/灵力不混用）？有没有作者自己解释不清的规则？
```

**设计要点**：① 一套不崩坏的体系必须定义全部字段——境界名\+子境界、能量术语、突破条件、能力边界、战力对标、寿元、代价、异象、社会地位、配套资源品级；② 突破必须有因果链（丹药/顿悟/生死磨砺），禁止无理由跳级，逆天功法必须配限制；③ 平衡性来自"兼容性限制"而非堆等级——功法品级决定承载上限、外物数量有上限、高级功法有修炼门槛；④ 突破节奏贴合作品气质：凡人流=每层打磨到极限、生死战突破；无敌流=快节奏越级反杀；⑤ 风险—收益对称，气运/奇遇要有代价；⑥ 严禁"筑基肉身扛核弹"式失衡。【共识】

**设计要点**：① 先一句话锁骨架再展开（主角为了 X 必须做 Y 但障碍是 Z），写不出一句话说明核心没想清楚；② 不要让 AI 一次性出全本大纲——分轮渐进（构思→人物/冲突→卷章结构→定稿），每轮人工确认；③ 爽点节奏在大纲层预埋，钩子类型轮换；④ 大纲留版本，每卷结束另存一版标注改了什么。【共识】
