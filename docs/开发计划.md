## 0. 共识记录（已确认决策）

**产品定位**
- 自用质量工具，真实产出能发番茄的书；开源为副产品
- 与现有工具的差异点 = 输出质量，不是功能数量；UI 只求功能够用
- 北极星指标：**追读欲望**；一票否决项：**一眼AI**
- 所有质量问题（AI味/剧情崩/不好看/文笔差/开篇拉胯）都是"追读欲望"的分解项

**技术形态**
- Tauri 2 + Vue 3 + TypeScript，Windows 桌面单机，零云部署
- Markdown/JSON 文件 = 单一真相源；SQLite = 检索索引 + 生成历史 + 审查记录
- 章节定稿即快照，重写/回滚基于快照；git 手动可用，不作为底层

**模型与成本**
- DeepSeek（规划/审查/抽取）+ Gemini（正文/润色/长上下文通读），两个适配器
- 按阶段配置模型，无自动路由；单章全环节成本目标 ≤ 1 元

**流程与人机边界**
- 阶段确认制：章内全自动（生成→检查→审校→回写一气呵成），细纲确认与定稿必须人工点头
- 全过程自动留痕（创作日志 = "人类实质主导"合规证据链）

**验收（v1 完成的定义）**
- 第一卷 ≥10 章 × 2500 字，"细纲→定稿"循环完整跑通不断档，机械检查全绿，台账与正文零硬冲突
- 质量门 = 对标书基准 + 本人通读愿意发；留 3 个固定试写案例做后续版本回归基准

**第一本书**
- 都市题材，求新颖；选题用 T1 提示词对话在工具外完成，工具入口从"设定已确认"开始

## 1. 架构原则

1. **提示词即资产**：所有 prompt 存为独立文件（应用内 prompts/ 目录，可按书覆盖），带版本号；每次生成记录 prompt digest，保证可复现、可回归
2. **阶段确认制**：章节状态机驱动，每个关口有明确的人工确认动作
3. **零 token 优先**：能用代码检查的（禁词、字数、段落、标点）绝不调模型
4. **文件是真相，数据库是索引**：档案损坏可从文件直接修复；SQLite 可随时重建
5. **Scope 纪律**：新功能想法一律先进 backlog，不进当前里程碑

## 2. 数据与存储设计

### 2.1 书籍目录（单一真相源，豆包文档 F1 结构）

```
books/<书名>/
├── meta.md                    # 书名/标签/字数计划/对标书/合规声明
├── STORY_BIBLE.md             # 世界观规则、力量体系表、术语表
├── CHARACTERS.md              # 角色卡（含动态状态段）
├── LOCATIONS.md               # 已出现地点
├── PLOT_POINTS.md             # 伏笔台账：编号/内容/埋设章/推进章/回收章/状态
├── OUTLINE.md                 # 全书大纲 + 分卷规划 + 爽点节奏总谱
├── style/                     # （M5）文风特征卡、作家语料
├── chapters/
│   ├── 001_细纲.md
│   ├── 001_正文.md
│   └── 001_记忆卡.md
└── config.json                # 本书配置：题材模板、阶段模型、字数区间
```

### 2.2 SQLite（应用级，可重建）

| 表 | 用途 |
|----|------|
| generation_log | 每次调用：书/章/阶段/模型/prompt_digest/token数/成本/时间/状态 |
| review_records | 每章每版审查结果：rubric 五维分 + 问题清单 + 结论 |
| snapshots | 章节定稿快照（内容 + 版本号 + 标签），重写/回滚的依据 |
| chapters_fts | FTS5 全文索引（前文检索）。注意：FTS5 默认分词不支持中文，**用 trigram tokenizer 或入库前 bigram 切分**（工程已知解法，M0 落地时定） |

### 2.3 上下文装配器规格（系统的心脏，M2 实现）

单章正文生成的输入装配顺序与预算（总量约 12-16K tokens）：

| # | 槽位 | 内容 | 预算 |
|---|------|------|------|
| 1 | 系统角色 | S0 定位 | 固定 |
| 2 | 全局硬规则 | S1 去 AI 味禁令 | 固定 |
| 3 | 题材适配 | S2 都市段 | 固定 |
| 4 | Bible 相关条目 | 按本章标签检索 | ≤800 字 |
| 5 | 力量体系对应行 | 本章涉及境界 | ≤200 字 |
| 6 | 出场角色状态卡 | 每人一份 | ≤150 字 × ≤4 人 |
| 7 | 卷节奏位置 + 本章情绪任务 | | ≤100 字 |
| 8 | 活跃伏笔线程 | 本章需推进/回收的条目 | ≤300 字 |
| 9 | 前情 | 全局摘要 + 最近 2 章摘要 | ≤1100 字 |
| 10 | 前文检索片段 | FTS5 召回 | ≤800 字 |
| 11 | 上一章末尾原文 | 衔接锚点 | ≤300 字 |
| 12 | 本章细纲（合同） | 全文注入 | 全量 |
| 13 | 输出要求 | 字数/视角/格式/禁则 | 固定 |

档案未覆盖的新设定，生成时标注"待补录"，禁止擅自改规则（T9-A 原则）。

## 3. 里程碑计划（按依赖排序，不排日历；每个里程碑完成后人工验收再进下一个）

### M0 · 脚手架与基础设施
**任务**
- Tauri 2 + Vue 3 + TS + Vite 项目初始化，Windows 构建跑通
- 数据层：Tauri fs 读写 + 书籍目录结构生成 + SQLite 初始化建表（含 FTS5 中文方案）
- LLM 适配层：Provider 接口 + DeepSeek（OpenAI 兼容）+ Gemini（原生协议）两实现；按阶段模型配置（config.json）；流式输出；支持自定义 base URL
- 设置页：API key 配置、连通性测试

**验收**
- `pnpm tauri build` 产出可运行 exe
- 两个 key 各发一条测试消息成功返回
- 建表完成，生成历史能写入

### M1 · 档案层（单一真相源）
**任务**
- 多书项目管理（创建/删除/切换）
- 六类档案编辑器：meta / Bible（含力量体系表）/ 角色 / 地点 / 伏笔台账 / 大纲
- 档案 schema 校验，非法结构被拦
- AI 辅助填充：T2 世界观、T3 力量体系、T4 角色卡、T5 全书大纲四条生成链（生成→人工改定→落盘）

**验收**
- 手动建书、填档案，文件树与 UI 双向一致，重启不丢
- 四条 AI 生成链各跑通一次并人工改定入库

### M2 · 单章闭环（核心管线，系统的心脏）
**任务**
- 章节 state machine：待细纲 → 细纲待确认 → 生成中 → 机械检查 → 审校中 → 待定稿 → 定稿
- 细纲生成（T6/T6-B，DeepSeek）+ 人工确认关
- **上下文装配器**（按 2.3 规格实现，FTS5 召回前文）
- 正文生成（T7 + S1 硬规则，Gemini，流式）
- **零 token 机械检查**（见 6.3 清单）：命中定位 + 分级（阻断/提醒）
- LLM 审校（T9-B 三维一致性 + rubric 打分；问题清单 → 定向修复，最多 2 轮，人工可跳过）
- 记忆卡抽取（T9-C，最便宜档）→ 台账自动回写，冲突项标红待人工裁决
- 定稿快照 + generation_log 记录（prompt digest / token / 成本）
- 断点恢复：关闭重开后从状态机当前位置继续

**验收**
- 测试书完整跑通一章全闭环，无断档；重开应用能续跑
- 机械检查五类（禁词/字数/段落/敏感词/对话后缀）均有命中定位输出
- 每次生成可从 log 复现（digest 对得上）

### M3 · 质量层强化
**任务**
- rubric 固化：追读欲望五维（AI味/剧情一致性/节奏爽点/文笔画面/开篇钩子）每章打分，分数列表可见
- 去AI味第二、三层：T8-A 整章润色槽位（产出改动清单）+ T8-C 自检清单
- 卷末跨章审计（T9-D）：伏笔回收率、人物弧线连贯、设定统一、下一卷铺垫清单
- 黄金三章专项（T7-C）在前 3 章自动注入
- 对话专场（T7-B）、突破场景（T7-D）、高潮场景专项槽位

**验收**
- 每章产出带五维分数的审查报告
- 卷末审计能列出伏笔回收率与冲突清单
- 润色槽位一键跑通且不改剧情

### M4 · 验收跑书（v1 完成线）
**任务**
- 第一本书立项：都市题材选题（工具外用 T1 对话）、定对标书、定书名/简介/金手指
- 用工具跑完第一卷 ≥10 章 × 2500 字
- 留 3 个固定回归案例（同细纲输入，版本升级后重跑对比）

**验收（= 共识第 16 条）**
- 闭环不断档、机械检查全绿、台账零硬冲突
- 对标书基准对比 + 本人通读"愿意发"
- 单章成本 ≤1 元（超出要给出分析）

### M5 · 文风指纹（后期增强，已确认延后）
**任务**
- 作家语料导入（txt）→ LLM 文风分析（T10-A 五维拆解）→ 特征卡落盘
- 特征卡注入装配器（新增槽位 4.5），防止 5 章后风格漂移（T10-B）
- 用 M4 的回归案例对比注入前后质量差异

**验收**
- 导入 3-5 段语料产出特征卡；注入后连续 5 章风格自检无漂移
- 注入前后回归案例对比有可感知提升

### v2 ·（跑完第一卷后）
- **拆文引擎**：书籍导入（txt 分章）→ 多轮分析（结构/爽点节奏/人设公式/文风）→ 拆文报告 → 反哺大纲模板与题材库
- 向量 RAG 升级、数据看板、发布辅助（此前发番茄均为手动复制粘贴）

## 5. 质量体系

### 5.1 追读欲望 rubric（每章审校输出，五维各 0-100）
AI味（一眼AI检测）/ 剧情一致性（含台账冲突）/ 节奏爽点（钩子与密度）/ 文笔画面（五感与对话辨识度）/ 开篇钩子。任一维低于阈值 → 阻断，需修复或人工豁免。

### 5.2 去AI味三层防线
1. 生成时：S1 硬规则挂进正文 prompt（源头预防）
2. 生成后：零 token lint 确定性扫描（词表/句式/标点）
3. 定稿前：T8-A 整章润色 + 本人通读（主观门）

### 5.3 零 token 机械检查清单（M2 实现）
- 字数区间 2200-2800（可配）→ 阻断
- 禁词表命中（S1 词表 + T8-B 烂词表）→ 阻断
- 对话后缀"XX 地说"类 → 阻断
- 敏感词红线词表 → 阻断
- 单句逗号 ≤2、感叹号/省略号频率 → 提醒
- 连续 4 句句长接近（爆发度检测）→ 提醒
- 段落 2-4 行（手机友好）→ 提醒
- 章末总结式收尾启发式检测 → 提醒

## 6. 风险与开放项

**风险**
- Gemini 国内直连不稳：适配器必须支持自定义 base URL / 代理；M0 就验证连通性
- LLM 结构化输出不稳定：细纲/记忆卡等用 JSON 输出 + schema 校验 + 失败重试
- FTS5 中文分词：trigram 或 bigram 方案 M0 定型
- "一眼AI"无法被 lint 根除：靠三层防线 + 人工门，验收以本人通读为准，不承诺检测率
- Scope 膨胀：一切新想法进 backlog

**开放项（不阻塞开发，立项时填）**
- 对标书是哪本（质量基准的锚）
- 文风模仿的作家语料（M5 前提供 txt 即可）
- Gemini 可用代理环境确认（M0 第一天验证）

## 7. 下一步
