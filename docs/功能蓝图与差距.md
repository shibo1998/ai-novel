# 功能蓝图与差距分析

> 目标：把本项目做成**一个完整成熟的 AI 长篇/短篇小说生产系统**，覆盖从选题到发布的全链路；
> 同时把 `D:\1-work` 下已有各项目的成熟能力收敛进来，不再多轨漂移。
>
> 三条硬标准（用户 2026-10-26 定）：**流程正确、成稿质量好、前后一致（长期记忆）**。
> 成本计算**不做**（自用工具，不是产品），已实现的毫分记账保留但不再投入。

## 四、吸收原则（避免多轨漂移）

1. **不搬代码，搬规则与协议**：参考项目多为 JS/TS，本项目是 Python + Vue，只吸收「词表、检查判据、数据结构、事务协议」，不引入第二套运行时。
2. **规则文件单一来源**：词表放 `lint/`，检测判据放 `ainovel/deslop.py` 常量，避免像 oh-story 那样 5 份副本靠脚本同步。
3. **每个新检查器必须带「未生效」通道**，并配一条 pytest 断言它能报出"没跑"。
4. **新能力默认进 P0 的验收线**：`pytest` + 真实书回归一遍（MEMORY.md 里的老教训）。
