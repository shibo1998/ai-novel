## 0. 结论摘要

| 维度 | 结论 |
|------|------|
| 页面数量 | ✅ 7 个页面对应 6 个 view 文件，但 **「档案编辑」是独立页面缺失**（规格04 §1 明确列为独立页，功能分散进 OverviewView） |

| 章节工作台 §2 八项 | ⚠️ 顶格 **✅ 4 项、⚠️ 4 项、❌ 0 项**；但含 **2 个子项完全缺失**（伏笔操作行内编辑、机检点击跳转正文） |

## 1. §1 页面清单 × 功能点矩阵

规格04 §1 的七个页面：书架 / 书总览 / **档案编辑** / 章节工作台 / 裁决队列 / 设置 / 导出。

路由表见 `web/src/router/index.ts:6-14`，只有 6 条路由：

```
/shelf  /book/:name  /book/:name/chapter/:no  /conflicts  /settings  /export
```

**「档案编辑」没有独立路由**（`web/src/router/index.ts:6-14` 共 6 条，无 `/book/:name/archive` 之类）。规格要求的"左树右编辑器 + 结构化字段表单 + AI 生成→diff→采纳"三要素被拆散：

- Bible / 伏笔台账 / 大纲 / 角色 的编辑能力落在 `OverviewView.vue`（书总览页）；
- 但样**全部是文本框 + Markdown 表格原文**，没有"左树右编辑器"，也没有"结构化字段用表单"。

### 6.1 【致命】设置页保存会把真实 API key 覆写成掩码串

链路：`settings.py:121-130` 的 `masked()` 把 key 替换成字符串 `已配置（留空保持不变…）` → `SettingsView.vue:50` 判断 `key.includes('…')` 成立 → 走"保留原 key"分支，但取的是 **`cur.providers.openai.api_key`，即掩码串本身** → `putSettings` 原样提交 → `settings.py:112-118` 深合并落盘。

再测一次 `masked()` 确认**无法自愈也无法察觉**：

## 7. 用户会直接卡住的断点（按实际操作路径走一遍）

完整路径：**建书 → 填档案 → 生成细纲 → 确认 → 生成正文 → 看检查 → 定稿 → 导出**

### 断点 1（⛔ 第一天就撞上）：建书后无法生成第 1 章细纲

- 建书后 `OUTLINE.md` 的章节总表是空表（`books.py:81-86` 只写表头）。
- 进工作台点「生成细纲（P-G6）」→ 后端 `pipeline.py:96-98` 直接抛 `OUTLINE.md 章节总表缺第 1 章行，先补全书大纲` → 实测 `400 OUTLINE.md 章节总表缺第 1 章行，先补全书大纲`。
- 唯一出路是**手工编辑 OUTLINE.md 补章节行**。UI 上：
  - 「G5 全书大纲」按钮 → 必然 404（§6.5）；
  - 「大纲」面板的编辑入口藏在折叠项里（`OverviewView.vue:465-469`），且保存会写坏文件 + 丢节奏总谱（§6.4a）。
- 更糟的是：`assemble()` 要求细纲已存在（`assembler.py:137`），所以「装配预览」在无细纲时也 400（实测 `preview -> 400 文件不存在: ...001_细纲.md`）。
- **净效果：新用户建完书，第一件事就做不下去。**

### 断点 2：填档案时「地点」和「meta」根本没入口

- 规格要求六类档案可编辑，UI 实际只有四类（Bible/角色/伏笔/大纲），且都是纯文本降级。
- `LOCATIONS.md`（规格01 §2.6）在 UI 上零入口 —— 后果不只是"少个页面"：装配器的 FTS 关键词抽取会读地点名（`assembler.py:107-110`），地点档案为空 → **前文检索召回质量下降**，用户会觉得"生成跑偏"，但原因藏在他根本看不到的文件里。
- meta.md 不可编辑 → 书名/笔名/平台/对标书/合规备注在 UI 上永远是建书默认值。

### 断点 3：机械检查报了问题，但点不进去

- 机检命中显示"行 37 · 命中词"，但那是**死文本**（`WorkbenchView.vue:546-557` 无 click）。
- 生成区正文是 `<pre>`（`:506`）纯展示，无行号、无锚点。**正文在 UI 上完全没有编辑入口**：全文件唯一的 `textarea` 是细纲原文（`:643`），无正文编辑器；后端 60 条路由里也**没有任何正文写回端点**（无 `PUT /chapters/{no}/prose`），所以修字只能靠 P-V5 让 AI 改（`:614`）。
- 用户看到"第 37 行有禁词"，既点不进去，也不能手工改那一行，只能自己肉眼在 2500 字里数行号，或再花一次 LLM 调用让模型猜他指的是哪句。

### 断点 4：审校不通过（human_review）时无路可走

`human_review` 状态下规格给了三个选项（规格01 §4）：改细纲重写 / 通过或豁免 / 完整重生成。UI 上：
- 「改细纲重写」✅（`:617`，后端 `pipeline.py:853-854`）；
- 「豁免」✅（`:616`）；
- **「完整重生成」❌** —— 即 `POST /rewrite`，但见 §6.2：无快照时点它会**清空正文**。而 `human_review` 恰恰是还没有快照的状态。用户点"重写"→ 2000 字正文变 0。

### 断点 5：error 状态没有任何恢复入口

- 后端有 `POST /chapters/{no}/retry`（`api.py:686-692`），配套 `statemachine.py:86-88` 的 `error + retry → prev_status`。
- 前端零调用（孤儿接口）。用户在 `error` 状态的工作台只能点「刷新」（`:426`），状态纹丝不动。
- 这类 error 不是理论情况：细纲 3 次校验失败（`pipeline.py:173-174`）、V1 JSON 3 次失败（`pipeline.py:719-720`）、记忆卡回写失败（`pipeline.py:926`）都会 `mark_error`。

### 断点 6：定稿后想回看旧版本，没有只读回看

- 「版本列表」是个下拉（`:622-629`），选中后唯一的动作是「从版本重写」（`:621`）——**会开新分支并立刻进入 generating**，不是"看看"。
- 后端也没有快照正文的 GET 路由（`pipeline.py:886-892` 的 `get_snapshot` 未被任何 `api.py` 路由暴露，实测确认 `api.py` 全文无 "snapshot" 匹配）。
- 规格04 §2 要求"版本列表**可回看**任意快照"——回看能力不存在，只有重写能力（且有 §6.2 的清空风险）。

### 断点 7：导出缺 md

规格04 §1 要求 txt/**md** 合并导出；前后端都没有 md（实测 404）。txt 与 zip 可用。

### （非断点，澄清）偏差 9 的两个点是已定案决策，不算缺陷

- **Vue3+TS+element-plus 技术栈**：README 偏差 9 已定案，`package.json`、`vite.config.ts` 与规格04 §0 完全一致 → ✅。
- **导出 POST blob 下载**：`api/index.ts:191-207` 用 `http.post(url, null, {responseType:'blob'})` + `Content-Disposition` 解析，实测中文文件名与内容均正确 → ✅ 这是修 bug，**不是缺陷**。
