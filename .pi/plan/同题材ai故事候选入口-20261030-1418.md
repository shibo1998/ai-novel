# 规格11 · 建书题材内的 AI 故事候选

## 1. 已确认需求与范围

**L2 跨模块增补**，承接用户实测反馈：第一步不能要求作者先想好故事；建书已经选好题材，应让 AI 在该题材内提供几个不同故事，由作者选择用不用。

本批只补**新书、首卷准备前**的灵感入口：默认每批 **3 个不同故事**，支持空想法生成、可选创意偏好、显式换一批、选用后修改。既有“手填故事 → 准备本卷”路径保留。

不增加跨题材开关，不再次询问题材，不覆盖已发布卷或已写章节。规格10既有批准快照和验收结论不改，本批另建规格11与实施报告。

## 2. 用户可见行为

在卷工作台第一步放置“**没想法？AI 给我 3 个故事方案**”区域，展示“当前题材：都市/玄幻/言情/悬疑”，题材只读，来自书的服务端配置。

- 不需要先填写“一句话故事”。可选填写偏好，例如“偏轻松、主角是小人物、不想写系统流”。
- 点击一次仅发起一次选题模型调用，显示真实等待状态与停止等待入口，不显示假进度或保证耗时。
- 成功后展示 3 张故事卡：暂定故事名、一句话故事、简介、主角与核心冲突、卖点、首卷目标和卷末钩子。各方案应是不同主角/冲突/展开机制，不是同一故事换名字。无榜单数据时不宣称热门、市场已验证或保证能爆。
- “**选用这个故事**”只填入“一句话故事”和“本卷要求”。保留正式书名、已选题材和期望章数；可继续手改。
- 表单已有内容时先展示替换影响并确认，取消不改变输入；确认等待期间输入或候选变化则重新核对，不覆盖晚到的修改。
- “**换一批**”显式再调用模型，带上上一批有限摘要避免重复。新请求失败时保留已有候选和手填内容，不自动重试。
- 选用后仍需作者点击“准备本卷”，然后继续原来的一次整卷细纲人工确认和最后人工定稿。选用候选不是新增强制确认关，也不自动触发后续生产。
- 切书、切页和卸载隔离请求结果；晚到响应不得填入另一书。候选不存 localStorage，刷新后不承诺恢复未落盘候选，不自动重新调用模型。

## 3. 后端与提示词接缝

### 文件

- 新增 `ainovel/storyideas.py`：创意上下文读取、适用范围与版本检查、一次模型调用、结果解析校验。
- 新增 `ainovel/storyideasapi.py`：独立严格输入/输出模型与路由。
- 修改 `ainovel/api.py`：仅在静态挂载前注册新路由，沿用稳定中文错误结构。
- 修改 `prompts/generate/T1.md`：**v2 → v3**，仍使用原 T1 ID、plan 档与 temperature=0.8，不新增或重命名提示词文件。
- 小范围修改 `ainovel/prompts.py`：仅为新版 T1 的新增可选变量补兼容默认值；其它提示词的严格缺变量校验不变。
- 修改 `ainovel/mockllm.py`：补同题材三个不同故事的结构化离线路由及异常测试替身。

### API

新增 `/api/books/{book}/story-ideas` 下两个端点：

1. `GET /context`：返回书名、已选 `genre_template`/中文题材、适用范围与原因、当前上下文 ETag。只读，不调用模型、不创建卷任务。
2. `POST /generate`：必填 `If-Match`；输入只接受可选 `preferences` 和有界的 `previous_loglines`，**不接受客户端自选题材或任意提示词ID**。返回 `schema_version=1`、原书/题材/上下文版本、3个故事候选和实际调用 `request_id`。

题材以书配置为准；缺失、损坏或无法识别时明确不可用，不偷偷默认都市。正式卷或章节已发布、或已有未结束卷任务时拒绝改换整本故事，不覆盖用户当前任务。

复用 `operations.writing(book)` 防同书重复模型请求和并发写入；读取接口不持模型长锁。同书忙时明确409，不串行悄悄排队追加计费。

调用统一走 `pipeline._call(book, None, ..., 'T1', ...)`，保留真实system/user请求、prompt digest、token及generation_log。只生成返回体候选：不写 meta/config/Bible/OUTLINE/角色/章节/正式记忆/FTS，不建立 production manifest，不触发确认、定稿或豁免。

T1增加“结构化故事候选”模式，新增可选的输出模式、作者偏好和既有候选摘要变量；**默认仍输出旧选题六问报告**，旧 `/ai/generate` 使用T1时不因新增变量报错。旧书级T1覆盖若不支持新结构接口，明确提示需要升级，不能静默绕过覆盖或修改真实书级提示词。

结果要求：恰好3项、字段/类型/长度合法、题材回显匹配、规范化一句话故事不重复。空输出、截断、非法JSON、缺字段、数量不符和重复故事均作为不可用返回，不用占位卡冒充成功，不自动修复重试。提示词承担同题材与差异化语义要求，最终故事好坏仍由作者判断。

错误维持 `{code,message}`：422参数、404书不存在、428缺If-Match、412上下文已变、409不适用/书忙、503配置或提示词接口不可用、502模型或结果不可用。失败不暴露凭据或供应商敏感回显。

## 4. 前端改动

- 新增 `web/src/api/storyIdeas.ts` 及类型：精确端点、If-Match、长调用timeout=0、AbortSignal及统一错误上下文。
- 新增 `web/src/composables/useStoryIdeas.ts`：原书/请求序号绑定、候选与等待状态、显式换批、选用前上下文重查与输入保护；复用已有任务/错误设施，不建立第二套全局任务系统。
- 新增 `web/src/components/StoryIdeaPicker.vue`：同题材只读提示、可选偏好、3张候选卡、选用/换批/停止等待。
- 新增 `web/src/utils/storyIdeas.ts`：返回体校验、候选到第一步表单的确定性映射。
- 修改 `web/src/views/VolumeView.vue`：只接入首卷准备表单。脑洞等待期间不允许同时发起本卷准备；已有任务继续按规格10运行。
- 样式小范围追加到现有卷工作台样式，沿用暖墨/朱砂风格，不全站重排。

网络未知或停止等待时说明“模型可能仍在执行并产生费用，候选可能无法取回”；只有作者明确接受再次调用后才能重试，后端书锁仍防重复。不会把停止浏览器等待宣称为取消模型。

## 5. 不做清单与兼容

不做扫榜、联网市场分析、跨题材推荐、自动改书名/题材、完整建书向导、续卷改换故事、候选历史库、自动开书/生成/采纳/定稿、成本产品化或新依赖。本批只解决第一步没有故事想法的缺口，其它能力另行提出。

无正式文件格式、SQLite表、章节状态词或迁移变化；候选是当前页面返回体。回退新入口即可，不能为回退删除书稿、候选目录或数据库。W1/G5/G6及M-04、V5>10%、裁决队列、文风metrics门禁不改。

阶段A实现后端/T1并定向回归，阶段B实现前端并验证，最后全量与文档收口。测试使用 `home` fixture及MockLLM，可离线运行，不读写真实books/data。

新增 `tests/test_spec11_storyideas.py`、`tests/test_spec11_storyideas_api.py`，扩展必要提示词回归；新增 `web/scripts/test-spec11-ui.mjs`并加入 `test:offline`。

可判定验收：

1. 四种建书题材分别无需手填故事即可返回3项不同logline；实际请求题材来自该书配置，客户端不能覆盖。
2. 空偏好、手填偏好和换批均可用；一轮只调用T1一次，实际generation_log存在；非法结果零可采用卡。
3. 生成、浏览、选用、取消均不改变正式书档案hash/章状态/FTS；选用只改变两项本地表单，不调用 production、confirm、finalize。
4. 选用前有手填内容时取消保留；确认期间输入改动、上下文变化或跨书晚到响应不覆盖。
5. 双击只发一个请求；同书并发请求被拒绝；错误/未知不自动重发，停止等待和显式付费重试语义正确。
6. 已有卷/章节或未结束任务的书不得被这条新入口改换故事；旧手填准备与规格10卷生产回归保持。
7. T1旧报告默认变量兼容，新结构模式完整；旧书级覆盖提示明确，其它提示词严格渲染与文件ID集合不变。
8. 全量pytest无新增FAILED/ERROR且全绿、smoke通过；前端test:offline、lint:check、typecheck、build通过。
9. 隔离Mock浏览器实际操作：无故事→生成3卡→取消替换→选用→表单可编辑→作者手动准备；另验换批失败、停止等待、切书晚到和1280×800卡片布局。保存请求/文件指纹证据，不把Mock当真实故事质量证明。
