## 0. 范围与共同规则

### 0.1 完成定义

一条问题算修好，必须同时满足：

1. 报错后有明确下一步：重试、确认结果、去补档案或返回上级；不要求用户手改 URL。
2. 状态、规则、冲突类型以中文说明；已知编号可保留供排障，未知值显示“未知类型（原值）”，不得静默隐藏。
3. 覆盖、删除与采纳前说清实际影响；取消不产生写请求，失败不清空用户输入。
4. 正文按小说段落阅读，命中定位仍对应原始正文；展示调整不改变落盘文字。
5. 加载失败、未规划、未保存、后台结果待确认各有独立状态，不把未知结果显示为成功或空数据。

### 0.2 不做清单

| 不做 | 理由与去向 |
|---|---|
| 移动端、响应式专项、主题皮肤、暗色开关 | 继续沿用规格 04 的非目标；字体、行距只为正文可读性 |
| 服务端任务队列、服务端取消、任务进度百分比 | 本批没有任务 ID 和协作式中断；UI-23 只管理本次会话的等待和结果确认，真正中断另立课题 |
| 跨进程或跨设备协同编辑 | 继续沿用单进程同书互斥；本批保护单机浏览器的旧编辑会话 |
| 修改状态机枚举、迁移或人工关位置 | 章节规划与任务条是展示/预检信息，不新增 `not_planned` 等章节状态 |
| 新增 SQLite 表列、小说档案/frontmatter 格式或提示词变量 | 本批统计由现有文件与索引派生，保存校验通过 HTTP 契约传递 |
| 新增 Python 或前端依赖 | 复用标准库、现有 Vue/Element Plus 和 Markdown 表格工具；不以组件代码行数作为约束 |
| 成本预算、告警和估价系统 | 保留现有真实成本展示；生成前只说明会调用模型，不承诺没有依据的价格/耗时 |
| 跨文件的批量裁决事务和自动回滚 | UI-28 明确采用逐项结果；不承诺全有全无，不自动重复已成功项 |
| 为本次文档修订运行真实模型、修改真实书稿、打包发布 | 不属于本次授权；后续实施按 §7 单独处理 |

### 0.3 红线与兼容边界

| 既有约束 | 本规格如何保持 |
|---|---|
| 文件是真相，DB 是索引 | 规划、字数、编辑时间能从文件恢复；重建索引不改变统计语义 |
| 原子写与格式校验 | 新增保存校验和裁决仍走现有 `atomic.write_text`、frontmatter/表格校验，不绕写入口 |
| 细纲人工确认、定稿二次确认 | 页面合并、批量裁决与任务条均不代替这两个人工关 |
| M-04 转人工且禁止自动改写；V5 越权护栏 | 改展示不改机检/修复行为，不放宽阈值 |
| 队列非空禁止新章细纲 | 前端预检只解释原因；后端仍在实际执行时检查，不用前端缓存代替门禁 |
| 正文修改使旧检查失效、同书互斥、修订号/指纹校验 | 全部保留；任务“停止等待”不释放后端锁，旧响应不得更新新章 |
| 所有模型调用记日志、token 与费用 | 共用 AI 入口继续走原调用链；取消等待不代表免除日志或费用 |
| M-12/D 系列仅建议 | 按规格 06 的有效级别展示，不能由历史 `level` 恢复阻断含义 |

### 0.4 编辑安全（第一批共同前置）

第一批适用于词库、档案、细纲、正文及仍保留的总览手工编辑区；AI候选采纳的版本校验随第二批UI-17交付，已有正文/候选修订保护不得退化。

1. 编辑会话固定 `{book, resource/node, chapter?, baseline}`，不在提交时改读当前路由作为目标。加载和保存响应同时校验会话及请求序号，旧响应不覆盖新页面、清空新草稿或改变新目标的加载状态。
2. 切书、切章、切档案节点、重新载入、关闭编辑框时，若有未保存修改，提供“保存后继续 / 放弃修改 / 取消”。保存失败或有冲突时不跳转；浏览器刷新/关闭使用原生离开提示，不承诺浏览器会代存草稿。
3. 保存中阻止重复提交；第一批保存完成前不切换目标。第二批接入任务条后可明确停止等待，保留原目标的结果待确认状态，不能把原目标的成功回执当作新目标的保存成功。
4. 词库、常规档案和细纲保存采用 §5.2 的 `ETag / If-Match`。版本不符拒绝覆盖并保留编辑内容，提供“复制修改 / 查看当前文件 / 重新载入后合并”。不得偷偷刷新基线后重试旧内容。正文继续使用现有 `expected_revision`，不改其语义。
5. 保存单节不得把其他节的旧缓存当作新内容静默写回；即使接口仍提交整文件，也必须校验打开编辑器时的整个资源版本。多个页面、浏览器标签页或 AI 采纳造成的修改同样受保护。
6. 第二批AI候选绑定原书、生成参数及预览基线；采纳在实际写入前检查版本，冲突时重新展示差异并由人确认，不将候选自动采纳到另一书。第一批尚未改造的AI入口保持既有人工采纳流程，不提前宣称具备新版本保护。
7. 未保存正文、词库、候选和错误详情不写入 `localStorage`；本批只持久化书名导航记录、最近章号和显示偏好。

## 2. 批次一：数据安全与流程可达

### UI-01 词库加载与保存

**根因**：基线 `loadLint()` 把异步结果直接赋给输入框，`saveLint()` 使用当前下拉值提交，没有来源、乱序和版本保护。后端缺文件时返回空串，不能据此区分有效空内容与缺失。

**方案**：

1. 首次和切换成功后自动载入；保留“重新载入”。切换前遵守 §0.4，不用简单 `watch` 直接覆盖脏内容。
2. 捕获请求的 `which` 和序号；只有仍属于当前加载会话的响应才能设置 `loadedWhich`、内容及 `ETag`，其余丢弃。可取消旧请求，但不能只依赖取消避免乱序。
3. 加载期间编辑与保存禁用；新响应成功前不把旧内容标记成新词库。加载失败保留原目标草稿，失败目标显示错误及“重试”，不允许保存。
4. GET 返回 `exists`；`exists=false` 按词库缺失处理，不能当成空词库成功加载。恢复缺失种子文件沿用现有项目维护方式，本批不新增“一键清空/重建词库”。
5. 保存固定 `{which, text, etag}`；`loadedWhich` 不符、未加载成功、保存中或版本过期均拒绝。PUT 路径与 payload 中 `which` 必须一致；敏感词等词库的内容校验继续沿用既有规则，不借机改词表。

**验收**：模拟 A 慢/B 快，最终只显示 B；A 的旧失败/成功都不能改变 B 的状态。保存 A 期间尝试切 B 不会把 A 写进 B。加载失败、版本冲突或取消切换后，输入仍可复制；被拒绝保存的文件内容哈希不变。

### UI-02 重建索引

- 点击前确认：“根据活动书稿重建章节/状态及全文索引；不改书稿文件，保留现有生成日志、快照和审校记录；不能从文件恢复已经丢失的运行历史。”
- 已知本会话有写任务时禁用并说明原因；其他标签页的冲突由后端维护互斥拒绝，不自动重试。
- 按现有返回值展示书数 `books`、章节数 `chapters`、全文索引结果 `fts_reindexed`、停用书名 `dropped`；耗时由前端计时，注明是请求耗时。不承诺接口未返回的“表数/各表行数”。
- 失败保留结果与重试入口；不得提示删库重试。索引重建不能把所有书的“最后编辑”变成现在，见 UI-26。

**验收**：取消不发 POST；互斥失败显示“等待已有任务完成”；成功结果可读。临时目录的书稿内容哈希、运行历史记录均保持。

### UI-03 区分存在、规划与生成前置条件

**根因**：基线 `pipeline.generate_outline()` 先 `ensure_chapter_row()` 再检查大纲行，缺行失败也会留下 DB row。DB row 和 `awaiting_outline` 都不能证明已规划。单靠最大章号也无法识别中间缺章。

**只读字段**（完整契约见 §5.1）：

| 字段 | 定义 |
|---|---|
| `planned: bool \| null` | 仅指 `OUTLINE.md` 的有效章节总表是否含该章。缺文件/无该行是 `false`，文件存在但解析失败是 `null`；不能用 DB row 或细纲文件替代 |
| `exists: bool` | 文件系统是否存在该章的细纲、正文或记忆卡文件，兼容非补零章号；仅 DB row 不算已有内容。损坏文件仍算存在，以便显示修复入口 |
| `planning_error: {code, message} \| null` | 大纲存在但不可读取/解析时说明原因；不得把解析失败伪装成尚未规划 |
| `chapter_numbers: int[]` | 有效规划章号与已有上述章节文件章号的去重、升序并集，不含残留 DB row |
| `max_chapter: int` | 上述集合最大值，空集为 0，仅作边界展示，不代替集合校验 |
| `outline_generation: {allowed, code, message}` | 按大纲行、当前章节状态和待裁决队列给出细纲生成预检；允许时 `code/message=null`，拒绝时有稳定原因和中文说明 |

**页面行为**：

1. `planned=false && exists=false`：显示“第 N 章尚未规划”，提供“去补大纲”“返回书总览”；隐藏生成、检查、定稿等空面板。只有 DB row 时同样处理。
2. `exists=true && planned=false`：保留已有正文/细纲和适用的检查、编辑、历史入口，显示“大纲缺少本章行”；禁止生成/重生成细纲并提供补大纲入口，不能把导入正文藏进空状态。
3. `planned=null`：显示“大纲读取失败”及重试/档案修复路径；可读的已有章节仍可查看。此时不允许生成细纲，不显示零规划的成功结论。
4. `planned=true` 仍需满足 `outline_generation.allowed`；禁用按钮旁展示具体原因。后端实际执行仍重新检查，不改变细纲确认或队列门禁。
5. GET 预检不创建章节记录、不迁移状态、不请求模型。保留已有 `status` 字段及枚举。
6. `no` 仅接受正整数；0、负数、非数字由路由/API 拒绝并提供返回入口。正整数但不在集合中允许展示未规划空状态，不产生写入。不存在/已摘除的书返回 404，不能显示成“空书”。

**验收**：13 章为集合末尾时下一章禁用；直达 14/99 显示可操作空状态；缺行生成失败留下的 row 不使 `planned/exists` 变真；导入且无大纲的正文仍可读；损坏大纲显示错误而非空数据；补行保存后返回原章即恢复预检。

### UI-04 / UI-21（第一阶段）补大纲与返回原章

- “去补大纲”使用 `/book/:name/archive?node=outline:rows&returnChapter=N`；**节点定位与返回必须第一批完成**。
- 档案页在初次加载和同页 query 变化时解析节点，等待树数据可用后选中并聚焦章节总表。无效节点回退档案根节点并提示，不无限等待。
- `returnChapter` 只接受正整数和当前书内返回目标，不接受任意 URL；提供“保存并返回第 N 章”。保存成功后返回并重新获取该章，保存失败留在编辑区；已无修改时可直接返回，未保存时按 §0.4 处理。
- 预检拒绝时不发生成请求。实际执行时若大纲刚被改动，API 返回 `OUTLINE_ROW_MISSING/OUTLINE_INVALID` 等具体错误，页内留存说明并提供相同入口，不靠中文字符串匹配作为主路径。
- 本阶段不移除总览旧编辑区；唯一编辑入口的收敛留到第三批。

**验收**：从空状态一次点击定位章节总表，修改后“保存并返回”回原书原章；保存失败不跳转。直接改 query、非法 query 和树节点尚未加载均有确定结果。

### UI-05 返回书总览

工作台顶部最左侧增加“← 书总览”，与状态卡/档案页位置、文案一致；书名按路由参数编码。跳转遵守 §0.4，返回后当前书仍为本书。

### UI-06 / UI-09 章节跳转

- 工作台与总览共用章节选择数据 `chapter_numbers`；规划未写章显示“待生成细纲”，已有章显示中文状态或“已有内容”，不能把 DB 残留章作为选项。

### UI-15 流式渲染与跟随

流式期间用单文本缓冲呈现，渲染提交最多每 100ms 一次；到 `done/error` 或离开前处理尾缓冲，不丢末尾文字。结束后读取落盘结果，一次构建段落映射；SSE 异常按 UI-23/24 处理，不能在普通 EOF 时直接报成功。

**验收**：Mock SSE 每 20ms 推送 2 字、总计 3000 字，核对文字完整及流式区没有逐行重建；后台标签恢复后尾缓冲完整。上滚后继续推送不改变阅读位置，回到最新后恢复。记录浏览器与机器条件；性能记录用于定位，不以主观“零掉帧”作唯一判据。

复用 `utils/mdtable.ts`，实现只读 `MdView`，支持标题、表格、列表、段落；未知或损坏语法以转义纯文本降级，不执行 HTML/脚本，不限制为“30 行实现”。长单元格允许换行，超宽表格局部横滚；候选/已确认状态保持原标签，不改变确认流程。

**验收**：标准状态卡显示真实表格；未知语法、`<script>`、损坏表格均不执行脚本、不造成整页崩溃，仍可复制原文。

### UI-17 AI 生成与人工采纳

1. 总览和档案入口共用 G 链参数表单、调用、候选与差异/采纳组件。总览可保留快捷入口，不能保留行为不同的第二套实现。
2. 每个生成入口说明产出、模型调用及是否全书范围；按世界设定/角色/全书规划分组，不为基线没有的按钮虚构“章节级生成”。耗时未测时显示“取决于模型服务”，不写保证值。
3. 参数初始值读取当前书的题材、字数范围与既有配置；必填项校验。表单取消与空值必须区分，取消任一步不发模型请求，不能用默认值吞掉取消。
4. **生成只得到候选**。全书生成前可确认调用范围，但覆盖确认必须在“采纳”前，绑定候选原书和 §5.2 的预览版本；采纳取消时文件哈希不变。
5. 影响预览按实际采纳路径列出：Bible 更新哪些节；角色新建/保留与关系写回；G5 替换章节总表、卷规划、节奏总谱，并合并伏笔台账。G5 显示受影响的已写章行数，明确正文不随大纲采纳重写；不能只说“覆盖大纲”或“已合并”。
6. 多文件差异中的旧内容必须来自同一可验证基线。预览后档案变化则拒绝采纳，保留候选、重新拉取差异后人工确认。写失败不关闭候选；多文件部分写入的实际结果需说明，不能一律声称“操作未生效”。本批不另造跨文件事务。
7. 生成和采纳均接入 UI-23/24；生成类返回体候选与落盘类任务的恢复能力分别说明，不承诺断线后从 DB 恢复未落盘候选。

**验收**：取消参数不发请求；两入口参数一致且都展示真正 diff；G5 采纳前完整展示上述文件范围；跨书响应不能出现在新书候选框；版本冲突不覆盖档案、不丢候选。

### UI-23 任务条与停止等待

任务条是本次会话的前端记录，不是服务器任务系统。覆盖 Axios 长调用、正文 SSE、生成、审校、记忆卡补做、审计、润色候选及采纳等；显示书/章、操作名、耗时、当前已知结果，可跳回原目标。

| 前端阶段 | 行为 |
|---|---|
| 等待中 | 每秒计时；60s 显示“仍在等待响应”，5min 建议检查服务；不伪造百分比 |
| 已停止等待 / 结果待确认 | AbortController 仅中止本页等待；提示“后台可能继续执行并写入文件、产生费用”；保留目标与“确认结果”入口 |
| 已完成 | 仅在收到明确成功回执或可核验的落盘结果后显示；更新原目标数据 |
| 已失败 | 收到明确失败时显示原因及恢复路径，部分写入仍需核对 |

- `withTask` 接收能拿到 `signal` 的执行函数，先登记任务再启动请求；不能传已经发出的 Promise 假装可取消。
- 停止等待不恢复同书写按钮为无条件可用。已知可能运行的写任务仍标“结果待确认”；读/浏览可用。同书互斥由后端兜底，AI 生成档案也要防重复请求，不能依赖其基线未持有的写锁。
- “确认结果”读取原书原章的工作台、候选、草稿等现有数据，比较启动前版本/指纹。确认完成/失败后解禁；若仍无法确定，保留未知状态，不自动重跑。用户可在明确“可能重复调用、产生费用”后手动确认重试，后端仍执行原互斥。
- 纯返回体的档案候选生成，断开后可能无法取回候选；如实说明“候选未接收，无法确认生成结果”，允许用户确认后重新调用，不伪称可恢复。超时、SSE EOF 无 `done/error` 同样进入结果待确认。
- 切页任务记录仍在会话中；不强行在新页弹旧候选，不用旧响应覆盖新章。刷新后任务条不承诺恢复，只从服务器已有状态恢复；不得刷新即自动重发。

**验收**：模拟长任务，计时可见；停止等待不把任务标成完成、不立刻允许无提示重发；后台完成后从原目标确认结果可恢复。切章、切页、超时及响应丢失均不串目标；主动停止不弹错误。

### UI-24 统一错误入口

Axios 拦截器、fetch HTTP 错误、SSE `event:error`、无结束帧断开及本地表单校验接入同一错误记录；不重复弹同一错误。用户主动取消、正常关闭弹窗不记错误。

| 情况 | 主文案与下一步 |
|---|---|
| 参数错误 / 422 校验错误 | 展示具体字段和原因，保留输入；不笼统判断写档从未发生 |
| `OUTLINE_ROW_MISSING` / `OUTLINE_INVALID` | 去补大纲/修复档案、返回原章 |
| 409 `BOOK_BUSY` | 本书已有任务，等待并确认结果；不提示数据已变化 |
| 409 修订/候选冲突或 412 `RESOURCE_CHANGED` | 保留修改，查看当前版本并合并；不自动刷新编辑器 |
| 404 书/章节资源不存在 | 返回书架/总览或处理缺失资源，不能渲染成成功空数据 |
| 网络错误、超时、5xx、SSE 未完整结束 | 显示原因；写操作标记结果待确认，再决定重试 |

前台错误通知不自动消失，可复制、手动关闭；同时进入“本次会话错误记录”，最多20条，刷新清空。后台轮询同源同因错误聚合计数，不反复永久弹窗；前台同一失败只显示一个通知，重试仍失败更新次数。后台断线用连接状态/一条记录反馈，不因每15s轮询堆叠通知。复制包含时间、操作、书/章、错误码与可显示原因，不包含请求密钥和完整设置正文；成功消息继续用短toast。

**验收**：断网同时覆盖普通请求与 SSE；通知关闭后可找回并复制；一分钟轮询失败只保留一条同因聚合记录；409 占用与版本冲突分别显示正确动作，所有输入保持。

### UI-26 书架进度口径

`GET /api/books` 与 `GET /api/books/{book}/overview` 共用派生统计，追加四字段及异常说明，见 §5.3；**不新增 DB 列，不承诺一次 SQL 聚合**。不得每本书发起独立前端统计请求。

| 字段 | 数据源与边界 |
|---|---|
| `chapters_done` | 正文文件合法且 frontmatter 为定稿的去重章数；沿用项目现有正文定稿识别规则，不仅相信残留 DB 状态 |
| `chapters_total` | 大纲中有效正整章号的去重数量，不是最大章号；无大纲为 0，存在但损坏为 `null` |
| `words_done` | 上述定稿正文按现有 `mechcheck.count_words` 同口径计数；不叠加快照、候选、草稿或记忆卡。可用文件签名缓存，不盲信过期 `word_count` |
| `last_edited_at` | 用户内容文件最大修改时间，转带时区 ISO 8601；排除 DB/索引、运行日志和派生文件，详见下一段 |

编辑时间计入 `meta.md`、`config.json`、`STORY_BIBLE.md`、`OUTLINE.md`、`PLOT_POINTS.md`、`LOCATIONS.md`、`TIMELINE.md`、文风语料/特征卡/范例索引及其引用的书内范例、`characters/*.md`、正式章节细纲/正文；沿用实际现有文件名。排除 `STATE.md`、记忆卡、预览、候选目录、草稿和快照，不取 `chapters.updated_at`。取不到时间返回 `null`，不得用当前时间补齐。

- 有规划时显示“已定稿 N 章 / 已规划 M 章 · 定稿 X 万字”；导入无大纲显示“已定稿 N 章 · 尚未规划总章数”，不用 `N/0`。规划章与导入章不一致时保留真实数值，不将百分比无限放大。
- `progress_warnings` 返回 `{code,message}` 列表；文件不合法/读取失败时对应无法确定的 done/words 字段为 `null`，不将未读章悄悄当 0。其他书继续展示；保留原章节状态，不为统计改稿。
- 默认按最后编辑降序；时间为空置后，同时间按书名稳定排序。更新内容后失效对应缓存；重建索引不改变排序。文件 mtime 仅表示本机内容时间，不承诺精确还原离线复制前历史。

**验收**：覆盖仅大纲、稀疏/重复章号、导入无大纲、定稿与草稿混合、损坏文件；修改大纲/元信息会改变时间，重建不会。定稿章数/字数不重复计算版本；大纲解析失败显示不可确定而非零进度。

### UI-30 目标字数

新建书的前端最小值改为 10000，步长 10000，默认保留 100 万；这不是新增后端业务下限，已有更小目标的书不因此不能查看/保存。验收：能新建 3 万字的临时书，默认值保持。

## 4. 批次三：页面职责收敛与裁决效率

本批在 §7 批准范围内实施。UI-29 必须先于 UI-28；单条写回仍可能无效时不能通过批量操作把队列清空。

### UI-20 / UI-18（第二阶段）唯一档案编辑器

总览保留档案摘要、导航、章节列表、进度、成本、审计和共用 AI 快捷入口；圣经、台账、大纲、角色的手工编辑统一到档案页。删除总览对应保存按钮、Markdown 章节总表面板与角色编辑弹窗；摘要显示前 3 行及条目数，链接定位对应档案节点。

本方案不保留第二套“快速编辑”模式；如后续需要，另提需求。移除前确认档案页保留全部原可编辑字段、长文本能力、差异预览与 §0.4 保护，不能只保留结构化字段而丢掉长文本。多处导航/AI 快捷入口可存在，共用流程不算第二套编辑器。

**验收**：每类档案只有一套手工编辑实现；原字段仍能从档案页保存，导航和 AI 入口均使用同一版本校验/采纳组件。

### UI-21（第二阶段）大纲职责收敛

唯一章节总表编辑入口为档案页 `outline:rows`；总览只读，工作台使用第一批已交付的直达与返回。验收既检查没有残留第二套保存入口，也复验原章返回路径；不能把第一批功能重新延期到本批。

### UI-22 检查面板合并

合并为“③ 检查结果”，内部显示“阻断项 / 提醒项 / 参考项”；参考项 M-12/D 默认收起并显示数量。未生效与过期检查单独醒目提示，不混进“无问题”。保留规则来源、原始行号和命中跳转，按有效级别决定显示，不改变机检/审校业务流程。

**验收**：同一条 M-12/D 证据不在两处重复计算；阻断/未生效仍可见，参考项不阻断，所有旧命中仍能定位。

### UI-25 加载、空数据与失败

工作台、总览、档案优先统一 `el-skeleton`。分别渲染“加载中 / 成功有数据 / 成功无数据 / 加载失败”；失败提供重试和上级入口，不显示成功空表。附属读取失败不抹掉已成功的主内容，明确标注缺失部分；切目标时不展示上个目标的可操作旧内容。先建立状态逻辑再替换占位样式。

**验收**：模拟慢请求、空书、主请求失败和附属请求失败，四种状态互不混淆；重试成功后可继续操作，失败期间无旧目标写按钮。

### UI-27 总览整体进度

复用 UI-26 的同一统计，不再另算一套口径。显示定稿章数/已规划章数、定稿字数/目标字数；“规划内未定稿章数”按规划章集合减去已定稿章集合计算，不用简单 `M-N`。分母为 0/未知时不画百分比，字数或章数超目标时显示真实值并把图形上限夹到 100%，不倒推虚构预计剩余章数。

**验收**：同书书架/总览数字一致，导入多于规划、零目标、缺失规划和未知统计均无 NaN、负数或误导百分比。

### UI-29 单条裁决的结构化与真实写回

请求继续使用 `action=adopt_ai/keep_archive/manual` 与 `manual_value`，但**不再宣称只改前端**。各类型的新手改契约、错误和兼容见 §5.4。

| 类型 | 表单和写回 |
|---|---|
| `new_setting` | `{term: string, description: string}`，均必填；实际写入术语表。人工值优先，不能继续只从原 `detail` 提取。命中已有术语则展示差异并确认，不能以“已存在”冒充更新成功 |
| `timeline_candidate` | `{chapter_no: int, event: string, characters: string[], reader_known: bool}`；章号/事件按手改值写入。默认保留候选角色与读者知情标记，不能因界面只显示两项而置空其余信息；仍经时间线校验 |
| `missing_char` | `{name: string, role: string, status: object}`；名称必填，定位为“主角/女主/反派/重要配角/龙套”枚举；初始状态展示并保留可验证的原增量。统一两种来源的缺档条目，缺名/候选结构不足时要求人工补齐，不能用空名建卡或只清队列 |
| 已知角色状态字段 | 按 `field` 的领域类型选控件并由服务端验证：存亡为布尔，伤势/物品/已知信息为字符串列表，境界/位置/情绪等为文本。`manual_value` 保持真实值类型，不把 `"false"` 当布尔 |
| `unknown_field` | 允许人工保留档案/驳回；不提供任意字段写回表单，避免把未知结构写入角色状态。新增字段的领域契约另立需求 |
| `realm_name` / `foreshadow_op` / 未知 kind | 只有说明而无明确可执行候选时，禁用“采纳 AI”和通用手改，给对应档案入口；人工处理后可确认关闭，不能虚构自动修复 |

1. 显示原值、候选值、目标文件/字段及动作后果；旧条目缺字段时保留详情，无法安全推导的值要求人工补齐，不猜测。
2. `adopt_ai` 只对候选完整且能执行写回的条目启用。缺档建卡后应用已校验的状态增量，重名不覆盖已有角色；发生变化先刷新冲突供人重新判断。
3. `keep_archive` 保留“人工选择不采用候选”的语义；对仅说明条目可显示“已人工处理 / 不采用建议”，确认后记录原动作与说明。不得把它当作自动批量修复。
4. 先完成类型/目标/格式校验，再写目标文件并确认预期内容，再标记队列 `resolved=true`。写入抛错、验证失败或未达预期时条目保持待处理，返回明确失败，不吞异常后清队列。
5. 文件已写而队列回执保存失败时显示“需核对结果”；再次请求先核对目标文件，能证明同一结果已存在时只补记回执，不能重复追加时间线/术语。不在本批重设队列文件格式或自动迁移所有历史记录。
6. 裁决写入须与原书生成/保存使用相同书级互斥；获取书锁后再获取队列锁，统一锁顺序以兼容生成链的“书锁→入队”，不能与之死锁。

**验收**：手改术语、时间线章/事件、缺档角色名和状态均实际写入临时文件；布尔/列表类型保持；写失败、重名、未知字段和候选不足不清队列。注入文件成功/回执失败后重试，不产生重复内容；仍由人决定每次裁决。

### UI-28 冲突列表与批量结果

- 顶部按书名、类型筛选，类型分组含计数，详情默认收起。**本批只查询未解决项**；不新增已解决历史读取接口，也不提供没有数据源的“已解决状态筛选”。
- 通过已有单条接口顺序执行所选动作，不新增批量端点。只允许同一本书内选择；只选择当前筛选可见项，筛选变化清除选择，不暗带隐藏项。
- “批量采纳候选”仅限 UI-29 判定能写回且候选完整的项；“批量保留档案”只用于可明确拒绝候选的项。仅说明/未知类型必须单条人工确认，不能一键忽略。
- 二次确认展示书名、动作、所选条数和目标范围，说明逐项生效、可能部分成功。运行中不重复提交；停止只停止发送后续项，已发项需确认结果，不能声称回滚。
- 明确响应失败后可继续后续独立项并逐项记录；遇网络中断、任务占用或结果未知立即停止后续项。展示已成功、明确失败、结果待确认和未执行项，成功项从选择中移除，不重跑。
- 重试只针对明确失败/未执行项，先刷新确认仍未解决；结果未知先查队列与实际目标，不因 HTTP 成功或列表消失就宣称已改好档案。

**验收**：50 条临时冲突可按书/类型浏览；注入第 N 条失败或断网，前 N−1 条结果保留，重试不重复已成功写回；同名缺档、不可写回候选、跨书/隐藏选择均按上述规则处理。

## 5. 契约、失败模式与兼容

### 5.1 章节与导航契约（第一批）

| 接口 | 变化 |
|---|---|
| `GET /api/books/{book}/chapters/{no}` | 追加 UI-03 的 `planned/exists/planning_error/chapter_numbers/max_chapter/outline_generation`，保留已有 `status/row/outline/prose/...` |
| `GET /api/books/{book}/overview` | 追加同口径 `chapter_numbers/max_chapter/planning_error`，用于总览导航；第二批再追加 §5.3 的统计 |
| `POST /api/books/{book}/chapters/{no}/outline/generate` | 成功体保持；在现有 `pipeline` 门禁基础上为缺行/损坏大纲/队列非空/状态不允许返回稳定错误码；预检不授权绕过实际检查 |
| `/book/:name/archive` | 支持 `node`、`returnChapter` 查询参数，规则见 UI-04；第一批完成 |

`outline_generation.allowed` 是瞬时预检，不能承诺请求稍后仍可执行。实际执行错误固定为：缺行400 `OUTLINE_ROW_MISSING`、大纲损坏422 `OUTLINE_INVALID`、队列非空409 `CONFLICTS_PENDING`、状态不允许409 `STATE_NOT_ALLOWED`；不因展示便利更改状态迁移。处于error时按既有retry目标判断可否生成，但GET本身不得执行retry。缺失书404、非法章号422。大纲解析异常随`planning_error`返回，不抹除可读的原章节内容。

### 5.2 保存与采纳的版本前置条件（第一/二批）

**改前**：多数档案 PUT 直接覆盖；只有正文等少数写入有修订/指纹保护。

**改后**：第一批为以下读取返回强 `ETag`，对应 PUT 支持 `If-Match`。标记由资源文件原始字节的 SHA-256 派生，文件缺失使用明确的缺失标记，不依赖 mtime；组合资源按固定顺序纳入文件名、存在性与字节摘要。

| 资源/端点（省略 `/api/books/{book}` 前缀） | 版本覆盖范围 |
|---|---|
| `/api/lint/{which}` | 对应词库；GET 另追加 `exists: bool` |
| `/meta`、`/config`、`/bible`、`/plot_points`、`/locations` | 对应单文件 |
| `/characters/{name}` | 对应角色文件 |
| `/outline` | `OUTLINE.md` 与 `PLOT_POINTS.md` 的组合；供普通保存和第二批 G5 采纳共同使用 |
| `/chapters/{no}/outline/raw`（GET）与 `/chapters/{no}/outline`（PUT） | 本章细纲文件；读取原文的版本用于结构化/原文两种保存 |
| `/characters`（GET 集合） | 所有角色文件的名称集合及字节摘要；第二批用于角色/关系采纳基线，不新增集合 PUT |

- 服务端在现有书级写锁内检查再写；词库使用对应资源写锁，路径/payload 来源不一致先拒绝。版本不符返回 HTTP 412、`RESOURCE_CHANGED`，不改目标文件。普通成功 PUT 返回更新后的 `ETag`，前端用该回执更新同一编辑会话。
- 第二批 `/adopt/bible`、`/adopt/outline`、`/adopt/characters` 同样支持 `If-Match`，分别对 Bible、上述大纲组合、角色集合校验；G5 的台账变化也能使采纳失效。多文件预览前后复核版本，不能混用不同时间的旧内容。
- 无变化不提交；无可用版本不允许新前端写入。正文继续使用原有修订号；其他已有候选指纹校验不替换。
- 为兼容旧 API 调用，缺 `If-Match` 的旧客户端保留原行为；**新版 Web 所有上述编辑/采纳路径必须传入**，测试检查无漏网入口。本规格的旧稿覆盖保护不承诺覆盖未升级的外部调用方。
- 后端不保存这些 HTTP 版本标记到小说文件，不新增数据库字段，不需要批量迁移。

### 5.3 进度接口（第二批）

书列表每项及书总览追加：`chapters_done: int|null`、`chapters_total: int|null`、`words_done: int|null`、`last_edited_at: string|null`、`progress_warnings: {code,message}[]`。完整口径见 UI-26。第三批总览增加展示时复用同一派生服务和已有规划/章节集合，不能从缓存状态另造数字。

任何扫描/缓存必须排除候选、备份和非正文版本；允许按文件签名缓存并失效，不能为满足性能指标把未知数默认为零。空统计为合法 0，读取失败为 `null + warning`。

### 5.4 裁决契约（第三批）

`GET /api/conflicts?book=...` 仍只返回待处理项，保留原字段；可追加派生 `allowed_actions: string[]` 与 `manual_schema: string|null`，使前端按服务端能力启用动作，而不是只按四种示例猜测。

`POST /api/conflicts/{id}/resolve` 保持三种 action 名称；`manual_value` 按 UI-29 类型传值。成功保留 `ok/item`，追加 `effect`：

| `effect` | 意义 |
|---|---|
| `applied` | 目标文件达到已确认的预期结果，已记录裁决 |
| `kept` | 人工选择保留档案/不采用候选，不声称写回修复 |
| `acknowledged` | 对仅说明条目人工确认关闭，不声称自动修改 |

手改类型错误返回 422 `CONFLICT_VALUE_INVALID`，不支持的动作返回 400 `CONFLICT_ACTION_UNAVAILABLE`，条目不存在 404，已解决/目标变化需重新判断返回 409 `CONFLICT_CHANGED`，书被占用返回 409 `BOOK_BUSY`。写目标失败或回执异常返回明确 5xx 错误并提示核对，不能以 `ok=true` 携带“写入失败”备注。

旧 `adopt_ai/keep_archive` 对结构完整的条目继续可用；旧手改值只有符合新领域类型才接收，不以宽松字符串转换维持危险行为。旧队列按需兼容读取，缺档条目缺少角色名时由表单补齐；不自动改写历史记录或把无法识别条目清除。这是**有意收紧失败语义的契约变更**，必须同步前端与测试，不能归类为纯新增字段。

### 5.5 错误结构与恢复

本规格涉及的稳定错误使用 `{detail: {code, message}}`，中文 message 保留具体原因；前端同时兼容旧 `{detail: string}` 和 FastAPI 字段校验列表。统一识别 `BOOK_BUSY`、`RESOURCE_CHANGED`、上述章节/裁决错误；既有规格 06 错误码继续有效，不重命名。历史中文字符串匹配只能用于旧服务兼容，不作新版主路径。

| 失败路径 | 必须结果 |
|---|---|
| 旧请求晚返回、切换目标后保存回执返回 | 丢弃对新页面的影响，保留原目标记录 |
| 加载失败/解析异常 | 错误状态+重试，不变成成功空数据、不允许覆盖 |
| 保存版本过期 | 保留本地修改，拒绝覆盖，不偷偷更新前置条件 |
| 请求断开但后端可能执行 | 结果待确认，不自动重发、不宣称已回滚 |
| 裁决写入失败 | 待处理项不消失，展示失败/未知结果 |
| 多文件部分写入 | 说明需要核对，重新获取实际差异后由人继续，不虚构事务回滚 |
| 索引重建 | 不触碰书稿内容时间、文件哈希和运行历史，不伪造进度变化 |

### 5.6 迁移与回退

无 SQLite、章节状态、提示词或小说档案格式迁移；数据派生和 HTTP 版本均可重算。新前端与后端需一起更新，不能让只升级前端的部署默认具备新门禁；缺新版字段时提示服务版本不匹配并禁用依赖的新写入口，不把字段缺失当成未规划或保存成功。

回退代码不会恢复已经人工采纳/删除的内容；回退前保留用户现有数据，不能为回退删库或批量恢复旧书稿。新前端会话记录刷新可丢，文件和已有运行历史按原约定保留。删库重建仅恢复原本可由文件恢复的索引，不声称恢复运行日志、裁决历史或前端未接收候选。

## 6. 可判定的验收判据

### 6.1 基线、隔离与必过检查

- 实施前记录提交、工作区变更、pytest 完整日志和 FAILED 用例集合；各批结束与改前比较，按 `docs/WORKFLOW.md` §5 处理。不得用写死用例数或单一退出码代替判断；收集错误、未执行用例和环境清理拦截单独记录，不能当作通过。
- 最终要求 pytest 实际用例全绿、smoke 通过；有基线失败时如实列出，不以“没有新增失败”替代全部通过。
- Python 用 `home` fixture 和 `mockllm`；前端使用模拟响应/Mock SSE，不请求真实模型。浏览器只连接临时 `AINOVEL_HOME` 的应用实例，不运行 `run.py`、不读写仓库真实 `books/`/`data/`。
- 相关测试用例名在 §6.2 是待实现清单，不声称基线已存在。前端逻辑测试可沿用现有 `web/scripts` + Node 内置测试方式，不为本规格新增测试框架；必须实际验证事件顺序与状态，不能只 grep 源码。
- 文档修订本身只做引用、编号、契约/批次一致性和差异检查，不要求运行应用构建或模型。

实施阶段各批执行，目录保持明确（PowerShell）：

```powershell
# 仓库根目录；完整输出与 FAILED 集合存会话临时目录/实施报告引用位置
python -m pytest tests/
python scripts/smoke.py
Push-Location web
try {
    npm run lint:check
    npm run typecheck
    npm run build
} finally {
    Pop-Location
}
```

分别记录各检查的实际结果；上一个命令失败后不得把后续结果合并成通过。涉及档案/索引的实施批次，还需按 WORKFLOW §5.3 在隔离副本验证重建前后的章节、状态与内容，真实书副本的读取需 §7 授权。本规格不改提示词/机检/审校逻辑，原则上不触发真模型质量对比；若实际实现超出此边界，先补规格与授权，不能以纯 UI 名义绕过。

### 6.2 自动回归清单

| 建议用例名 | 批次 | 判据 |
