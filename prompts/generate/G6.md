基于输入的全书大纲与人物档案，为下一章生成单章细纲（章合同）；卷准备候选尚未采纳，不得称为已确认事实。

【输入】
- 批次计划说明：〖批次计划说明〗。卷准备阶段的预期承接/计划末态不是上一章已写原文；没有真实正文时只能设计预期衔接，不能伪造原句。单章实时路径按真实原文承接。
- 全局大纲中本章对应行：〖全局大纲该章行〗
- 所属卷目标：〖所属卷目标〗
- 所属剧情单元（当前单元的目标/阻力/选择/结果与信息边界；是规划不是已写事实）：〖所属剧情单元〗
- 本章规划边界（可释放上限与必须保留的信息）：〖本章规划边界〗
- 上一章钩子（本章开头必须直接承接）：〖上一章钩子〗
- 上一章结尾原文（本章**第一句**就从这里长出来）：〖上一章结尾原文〗
- 本章出场角色当前状态：〖出场角色状态〗
- 活跃伏笔线程（只能引用其中编号，不得新造）：〖活跃伏笔线程〗
- 章号 〖章号〗 / 总章数 〖总章数〗
- 本章字数区间：〖字数区间〗
- 上一章场景结构（防重复）：〖上一章场景结构〗
- 最近三章已存在的核心事件、场景目标、钩子内容与类型及节奏任务（仅过去章，不把未来章当事实）：〖最近三章节奏〗

【输出】
第一行必须是 `---`，随后输出 YAML frontmatter（字段与格式严格遵守，程序校验失败将整段退回重写），`---` 结束后输出 Markdown 正文（逐场景清单，供人读可编辑）。禁止：代码块围栏、开场白、任何解释文字。

【开篇衔接（最容易被忽略，也最容易被读者发现）】
- 实时路径中上一章结尾原文写明了「人和物此刻在哪」，本章第一个场景**必须从那个位置起步**；卷准备阶段按明确标注的预期末态设计衔接：
  要么同一地点继续，要么用一句话交代怎么到的（谁带的路/爬了几层/走了多久）。
- 严禁凭空换场：上一章在 A 层，本章直接出现在 B 层，中间一个字不交——读者会立刻出戏。
- `opening_bridge` 必须可核对：写出具体的空间关系（"从六层通风井向上""还在那口沉降口边上"）
  或时间关系（"半日后""天没亮"），不许写"承接上章"这种空话。
- 第一个场景的 `chars[].state` 里要带上承接后的位置与伤势，别让读者从对话里反推。

【T6 硬要求】
- 本章场景必须服务「所属剧情单元」的目标与收束：本章结束时向单元目标推进一格；「本章规划边界」中"必须保留"的信息一律不得泄露，"可释放"是上限不是任务量；
- 节奏服从本章目标与人物处境，不规定三幕比例、固定高潮或章末字数配额；
- 比较最近三章是否重复同一种破局、倒计时、封路或威胁收尾，在Markdown中给“节奏说明”解释区别；相似只作人工提醒，不偷改已确认事件；
- 钩子类型不得与上一章相同（上一章钩子类型：〖上一章钩子类型〗）；
- 对照过去章节的场景目标与因果，避免无意义复用；不为求不同强制插日常戏或按数量兑现伏笔；
- 主线之外的支线不得喧宾夺主；无目标、无冲突的场景删掉。

【程序校验约束（违反即重试）】
foreshadow_ops 引用的 FO 编号必须存在于活跃伏笔线程；pay 的必须处于 building 状态。
