基于输入的世界观、人物和核心冲突，生成大纲。规划上下文若标注卷联合候选内存投影，则上游尚未人工采纳；只在候选中组织计划，不称其为已确认/已写事实。严格遵守：

- 规划作用域：〖规划作用域〗
- 规划上下文：〖规划上下文〗
- 世界观摘要：〖世界观摘要〗
- 角色卡摘要：〖角色卡摘要〗
- 一句话故事（logline，主角为了 X 必须做 Y 但障碍是 Z）：〖logline〗
- 目标总章数：〖目标总章数〗；单章字数区间：〖单章字数区间〗

【作用域判定（先读这里）】
- 作用域为 **legacy**：按下方【legacy 输出四部分】输出全书大纲（卷规划 + 章节总表 + 伏笔总表 + 节奏总谱 + 自检）。
- 作用域为 **global / volume / unit / chapters**：只输出【规划 JSON 包络】一节规定的**单个 JSON 对象**，除此之外不输出任何文字。程序做严格结构校验：越出作用域的输出（生成其他卷/章、重复章号、多余字段）会导致**整次输出被驳回重写**。

【legacy 输出四部分】

结构：三幕式，比例约 25% / 50% / 25%；先列卷划分，再列章节。

## 卷规划
每卷一行：| 卷号 | 卷名 | 起止章 | 核心冲突 | 本卷目标 | 卷末高潮 | 卷末钩子(出卷悬念) |

## 章节总表
每章一行：| 章 | 卷 | 本章目标 | 冲突来源 | 爽点/揭露 | 钩子类型 | 重要度★ |
钩子类型 ∈ 悬念|选择|反转，相邻章不得同类型；重要度用 ★1-5 打分（对全书不可或缺程度）。

【关键节点（必须满足）】
- 激励事件落在第 1-3 章；
- 中点反转：主角从被动应对转为主动出击；
- 至暗时刻：主角失去第一幕里最珍视的东西；
- 高潮对决与人物弧光完成在第三幕。
- 标出前 3 章的"核心悬念 / 金手指觉醒 / 第一次小高潮"分别落在哪一章。

## 伏笔总表
| 编号 | 内容 | 埋设章 | 推进章 | 预计回收章 | 备注 |
编号用 F 编号（程序转写为 FO-xxx）；埋设章早于回收章至少 5 章；跨卷伏笔在备注标注。

## 爽点节奏总谱
一段文字标注全书高潮点分布（1-2 章小打脸 / 3-5 章中打脸 / 8-12 章大高潮 / 卷终决战）。

## 自检（入库前程序剥离）
最薄弱的是哪三章？为什么？中段疲软风险在哪？给出补强建议。
禁止套用"开局受挫、中期崛起、后期复仇"的通用骨架；主线目标和障碍必须具体。

【规划 JSON 包络（非 legacy 作用域时唯一允许的输出格式）】

输出**一个** JSON 对象，包络固定为 `{"scope": ..., "target": ..., "data": {...}}`：

- `scope` 必须等于当前规划作用域（global / volume / unit / chapters）。
- `target` 必须原样回传规划上下文中给出的目标结构（`{"volume_no": null, "unit_id": null, "chapters": null}`，按作用域填写对应字段）。
- `data` 只允许当前作用域的字段，多一个键都会被驳回：

1. **global**（全书粗纲，不输出全书章节表）：
   `{"logline": "...", "ending_direction": "...", "global": {"reader_promise": "...", "selling_points": ["..."], "mainline": "...", "stage_boundaries": ["各阶段可推进到哪"], "reserved_reveals": ["暂时保留的终局答案"], "estimated_chapters_override": null}, "rough_volumes": [{"no": 1, "name": "...", "direction": "全书尺度上的本卷方向", "estimated_chapters": 30}, ...]}`
   - 各卷只给**粗方向与估算章数**（rough）；远卷不展开细节、不出章节行。
   - logline/ending_direction 为必填非空文本；ending_direction 是作者拟定的终点，不代表事件已发生。

2. **volume**（只输出目标卷，远卷仅一句方向，不顺带展开）：
   `{"chapter_count": 30, "volume_detail": {"core_conflict": "...", "goal": "...", "climax": "...", "hook_out": "...", "ending_state": "预期人物/关系/资源/地点变化（计划而非当前状态）"}, "unit_skeletons": [{"name": "单元一", "chapters": [1, 5], "goal": "...", "obstacle": "..."}, ...]}`
   - `unit_skeletons` 的章号范围必须**完整覆盖本卷、不重叠、不留洞**；卷的起止章由程序按全卷 chapter_count 分配。
   - 每个单元是一个完整矛盾（触发→交锋→选择→收束），可跨若干章。

3. **unit**（只细化目标单元）：
   `{"unit_detail": {"goal": "...", "obstacle": "阻力及对方的应变", "choices": ["关键选择与转折"], "outcome": "收束结果及后续影响", "can_reveal": ["本单元可以释放的信息"], "must_hold": ["本单元不能提前释放的信息"], "story_lines": ["本单元推进的主线或支线"]}}`
   - 不重写其他单元，不生成正文，不改单元名称/范围。

4. **chapters**（只输出指定单元、指定章号批次）：
   `{"chapter_rows": [{"章": "1", "卷": "1", "本章目标": "...", "冲突来源": "...", "爽点/揭露": "...", "钩子类型": "悬念", "重要度★": "3"}, ...], "rhythm_note": "本批次节奏说明（一两句）"}`
   - 章号必须落在指定批次范围内且**每章恰一行、不重复**；钩子类型相邻不同；不越范围"凑齐整卷"。
   - 每章只写七列，不写单章细纲（细纲由 G6 按章生成）。

【规划通用硬要求】
- 已写正文章节是**事实**，规划不得与之矛盾；未写内容一律是**计划**。
- `must_hold` 的信息不得在对应单元之前释放；`can_reveal` 是本单元可释放的上限。
- 章号/卷号写纯数字，不写"第X章"。
- 拿不准就少写：宁可结构完整内容粗，也不要编造细节。
